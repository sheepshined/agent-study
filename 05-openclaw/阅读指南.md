## 1. 项目定位

**它不是 coding agent CLI，而是"多渠道个人助理网关"。** `package.json:10` 的自述就是 `"Multi-channel AI gateway with extensible messaging integrations"`；`README.md:1` 标题 "OpenClaw 🦞 — Your assistant, on your devices, in your chats"；`VISION.md:3-4`："the AI that actually does things. It runs on your devices, in your channels, with your rules."

与另五家的根本差别（一句话）：**Claude Code / Codex / OpenCode / ZCode / DeepSeek Harness 的宿主是"终端 + 一个仓库 + 一个坐在键盘前审批的人"，OpenClaw 的宿主是"一台常开机器 + 一堆通讯账号 + 一组配对设备"，它的输入源是消息事件而不是人类敲的 prompt。** 因此它多出整套"没有人类在旁边看着"的基础设施：sessionKey 路由语法、双层 lane 串行化、写者围栏、DM 配对码、设备签名配对、渠道级白名单、六条独立限流。

血统：`VISION.md:11-13` 交代 Warelay → Clawdbot → Moltbot → OpenClaw；`VISION.md:121-125` 声明它是 **terminal-first by design**。

⚠️ 运行前必读 `SECURITY.md`（38 KB）。核心一句（`SECURITY.md:5`）：*"OpenClaw is local-first agent infrastructure for trusted operators; it is not designed as a shared multi-tenant boundary between adversarial users on one gateway"*；`SECURITY.md:13`："任何能操作 agent 的人都能让它做任何该 agent 能做的事"。**沙箱默认关闭**（`docs/gateway/sandboxing.md:9`）。

## 3. 三条根级设计优先级（读代码前先装上这套世界观）

来自根 `AGENTS.md` 的 "Design priorities"：

1. **One owner per responsibility**：一个职责只有一个"能决策/能改权威状态"的 owner；调用方只消费它的操作与已记录事实；适配器翻译契约；缓存/投影从 owner 派生并显式失效。
2. **Small core, capable plugins**："内核每加一行面向模型的 prompt、一个工具、一个 config key，都对所有宿主收税；插件/skill/渠道/app 不收"（`VISION.md:78-84`）。觉得规则挡路时，先检查你插在哪一层。
3. **Stable conversation context**：重建历史上下文会毁掉 prompt 前缀复用——限制生成式 prompt/工具/上下文增量的规模、保留 transcript 字节、要求指令整份送达，**只有 compaction 可以改写历史**。

同一文件里的两条硬约束（有 lint 脚本兜底）：

- **状态与缓存一律 SQLite**，不再新增 JSON/JSONL/sidecar 存储；文件只用于具名用户产物、导入导出、附件、日志、备份。类型用 `pnpm db:kysely:gen` 生成。
- **数据库访问必须在 worker 线程**，Gateway 主线程只 await 结果、装填已发布事实；只有 boot admission、迁移、Doctor、CLI 一次性任务、锁原语可例外。

还有 `VISION.md:45-52`：**运行时只读当前 schema，不保留长期别名和静默兼容分支**，升级靠 `openclaw doctor --fix` 重写配置。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| **Gateway** | 常驻进程（`openclaw gateway`），持有所有渠道连接、RPC 面、调度器与状态库；WS + HTTP，默认端口 18789 |
| **Channel（渠道）** | 消息平台适配层：bundled id 共 **27 个**（`src/channels/bundled-channel-ids.generated.ts:11` 起，生成物勿手改）：a2a、buzz、clickclack、discord、feishu(lark)、googlechat、imessage、irc、line、matrix、mattermost、msteams、nextcloud-talk、nostr、qa-channel、raft、reef、signal、slack、sms、synology-chat、telegram、tlon、twitch、whatsapp、zalo、zalouser |
| **Node（节点）** | 配对的设备宿主（macOS/iOS/Android/Linux 或 `openclaw-node` Rust 二进制），提供 `camera.*`、`screen.record`、`location.get`、`canvas.*`、`system.run` 等设备能力，经 WS `role:node` 接入 |
