## 160. 相交链表

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/intersection-of-two-linked-lists/) ｜ 标签：哈希表 · 链表 · 双指针

### ① 题意速览
两条单链表可能从某个节点起共用同一段尾巴，找到**相交的起始节点**（同一引用）；不相交返回 null。全程不得修改链表结构。
- 示例：A = `4→1→(8→4→5)`，B = `5→6→1→(8→4→5)`，交点是值为 8 的节点
- 关键约束：进阶要求 O(1) 空间；两表均无环。

### ② 思路讲解
**从朴素出发**：哈希表存 A 链全部节点引用，扫 B 链第一个命中的就是交点。O(m+n) 时间但 O(m) 空间，没吃到进阶分。

**对齐版**：两条链一旦相交，尾段完全共用，**长度差只出现在相交前的独有段**。先各扫一遍求长度，让长链指针先走 |m−n| 步"找齐"，再同步前进到引用相同处。O(1) 空间，但要写"求长 + 对齐"两段逻辑。

**优雅版（换轨法）**：pA 从 headA、pB 从 headB 出发，**各自走到底就跳到另一条链的头部继续**。若相交：pA 总路程 = a+c+b，pB = b+c+a（a、b 为独有段长，c 为公共段长）——**两条路径等长**，两者必然同时踏进公共段、在同一步到达交点。若不相交：pA 走 m+n、pB 走 n+m，依然等长，最终**同一轮双双变成 null**，而 `pA is pB` 对两个 null 成立，循环干净退出——**不会死循环**，这就是"null 也参与比较"的妙处。

**不变量**：每轮之后 pA 与 pB 走过的总步数相等；等步数 + 换轨让两者永远步调对齐，相遇点只能是交点或同时为 null。

**套路迁移**："靠总步数对齐两条不同路径"是链表双指针的独特玩法：数组双指针靠下标对齐，链表没有下标，就**换轨凑等长**。同家族：142（相遇后回起点同速走）、206（双指针逐个掉头）。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def getIntersectionNode(self, headA: ListNode, headB: ListNode) -> Optional[ListNode]:
        pA, pB = headA, headB
        # 不变量：pA/pB 已走总步数恒相等；任一走完当前链就换轨到另一条
        while pA is not pB:
            pA = pA.next if pA else headA   # A 链走到底 -> 换到 B 链头
            pB = pB.next if pB else headB   # B 链走到底 -> 换到 A 链头
        return pA   # 相遇：要么是交点，要么两者同时为 null（不相交）
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(m+n)**：每个指针至多走两条链各一遍；**空间 O(1)**（哈希版 O(m)）。
- **易错点**：
  1. 用 `pA.val == pB.val` 判相交——交点是"同一个节点"（同一引用），值相等不代表同节点；
  2. 换轨条件写成 `pA = pA.next or headA` 之类时注意：`or` 对 falsy 值都换轨，语义恰好可行但要能讲清，最稳的是显式 `if pA else`；
  3. 不相交时若换轨后比较漏了 null（比如两链等长），会无限循环——本写法靠 null 参与比较天然退出。
- **面试追问**：
  1. 两链表**有环**怎么找交点？→ 先用 141/142 分别找到两条链的入环口：入口相同则退化成"无环版"（环前段找交点）；入口不同则整个环都是公共段，任返回一个入口；
  2. 为什么换轨法不会错过交点？→ 交点后两者同踏公共段，路径差只在独有段，换轨恰好抵消长度差——把 a+c+b 与 b+c+a 写出来对照即可。

## 206. 反转链表

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/reverse-linked-list/) ｜ 标签：递归 · 链表

### ① 题意速览
把单链表整体掉头，返回新头（原尾节点）。
- 示例：`1→2→3→4→5` → `5→4→3→2→1`
- 关键约束：进阶要求给出**迭代 O(n) 时间 O(1) 空间**与**递归**两种写法。

### ② 思路讲解
**为什么需要三根指针**：想把 cur 的 next 掉头指向 prev，麻烦在于一旦改了 `cur.next`，**原来 cur 后面的链就够不着了**——必须先用 nxt 把后继存起来，再掉头，最后 prev、cur 各前进一步。链表操作的第一守则：**断链之前先保住后继**。

**迭代（三指针法）**：prev 从 None 出发，cur 从 head 出发，每轮三步：存后继 → 掉头 → 双双前进。cur 走到 null 时，prev 恰好停在原尾节点（新头）。

**不变量**：任意时刻——prev 及其之前**已反转完毕**（prev 是反转链的头，`prev` 之后接的都反过向了）；cur 到表尾仍是原顺序、**尚未处理**。初态（prev=None、cur=head）与终态（cur=None、prev=新头）都满足它，正确性得证。

**递归版的空间代价**：递归写法"先递归到尾，回头路上把 `head.next.next = head` 再 `head.next = None`"——代码极短，但递归深度 = 链长 n，**调用栈 O(n)**，链表一长就有爆栈风险。迭代版 O(1) 空间，面试首选；主动报出递归的空间代价是加分项。

**套路迁移**：反转是链表题的"子程序之王"：234 反转后半段比对、25 每组调一次反转、92 区间反转都要复用它。务必练到闭眼能写、每次都能说清不变量。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev, cur = None, head
        while cur:
            nxt = cur.next        # 1. 先存后继：掉头前保住，否则链从这里断开
            cur.next = prev       # 2. 掉头：当前节点指向已反转好的前半段
            prev, cur = cur, nxt  # 3. 前进：prev 扩一个，cur 走一步
            # 不变量：prev 及之前已反转完毕（prev 是新链头），cur 及之后未处理
        return prev               # cur 为 null 时 prev 正好是新头
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每节点掉头一次；**空间 O(1)**：只动指针（递归版 O(n) 栈）。
- **易错点**：
  1. 先 `cur.next = prev` 再存 nxt——后继直接丢失，链断成两截；
  2. 初始 prev 忘了置 None（反转链的尾必须指向 None），或最后 `return cur` 而非 `return prev`；
  3. `prev, cur = cur, nxt` 右侧必须用**已保存的 nxt**，顺手写成 `cur.next` 时 cur.next 已被改，全乱。
- **面试追问**：
  1. 只反转**一部分**（LC 92，区间 [m, n]）？→ 找到 m 的前驱，对区间做同样的三指针反转，再把两头接回——挂 dummy 后 m=1 不用特判；
  2. 递归版怎么写？→ `newHead = reverseList(head.next)`，回头路上 `head.next.next = head; head.next = None`，返回 newHead；深度 n，每层栈帧保留一个 head，故 O(n) 空间。

## 234. 回文链表

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/palindrome-linked-list/) ｜ 标签：栈 · 递归 · 链表 · 双指针

### ① 题意速览
判断单链表的值序列是否回文（正读反读相同）。
- 示例：`1→2→2→1` → true；`1→2` → false
- 关键约束：进阶要求 O(n) 时间 + O(1) 空间——排除"抄进数组再双指针比对"和递归栈。

### ② 思路讲解
**从朴素出发**：把值抄进数组，首尾双指针比对；或递归到底后用栈帧里的"回头指针"与正向指针比对。都是 O(n) 时间，但一个 O(n) 数组、一个 O(n) 栈，进阶要求 O(1) 空间。

**O(1) 空间的三步走**：
1. **快慢指针找中点**：慢一步、快两步，循环条件 `fast.next and fast.next.next` 让 slow 停在中点（奇数长度）或左中点（偶数长度），**后半段的起点就是 slow.next**；
2. **反转后半段**（复用 206 的三指针）；
3. **逐一比对**：前半段从 head、反转后的后半段从新头同步走，值全等即回文。

**为什么比"后半段"就够了**：反转后的后半段长度 = 前半段长度或再减一（奇数长度的中点留在前半段、不参与比对），所以循环条件写成"后半段是否走完"，奇偶不用单独讨论。

**面试礼貌版**：本题允许破坏链表，但**比对完把后半段再反转回去接上**是礼貌做法——说明你有"不破坏输入"的意识，面试顺手做掉或口头说明即可。

**套路迁移**："找中点 + 反转 + 拼接/比对"是链表中场的标准起手：148 = 找中点 + 递归 + 21 合并；重排链表（LC 143）= 找中点 + 反转后半 + 两段交错拼接。认出"链表的一半"这个结构，题就解了一半。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        # 1. 快慢指针找中点：slow 停在中点（奇数长）或左中点（偶数长）
        slow = fast = head
        while fast.next and fast.next.next:
            slow, fast = slow.next, fast.next.next
        # 2. 反转后半段（起点 slow.next，复用 206 三指针）
        prev, cur = None, slow.next
        while cur:
            cur.next, prev, cur = prev, cur, cur.next  # 存后继 -> 掉头 -> 前进
        # 3. 前半段 vs 反转后的后半段，逐一比对（以后半段长度为准）
        p, q = head, prev
        while q:
            if p.val != q.val:
                return False
            p, q = p.next, q.next
        return True
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：找中点、反转、比对各一遍；**空间 O(1)**（数组/递归/栈版均 O(n)）。
- **易错点**：
  1. 反转起点必须从 `slow.next` 开始——把中点卷进后半段，奇数长度必错；
  2. 找中点条件漏写第二个 `fast.next.next` 判空，在短链上空引用崩溃；
  3. 比对循环条件写成 `p and q` 会因前半段多出的中点走出错位——用 `while q` 最稳。
- **面试追问**：
  1. 怎么**还原链表**？→ 记下 slow，把 prev 开头的后半段再反转一次，接回 `slow.next`，三步倒着做一遍；
  2. 为什么不用栈？→ 栈版（前半入栈、后半弹出比对）思路直白，但 O(n) 空间，作为"先给个能跑的"起点，再升级三步走。

## 141. 环形链表

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/linked-list-cycle/) ｜ 标签：哈希表 · 链表 · 双指针

### ① 题意速览
判断链表中是否有环：某个节点的 next 指回了链表中位于它之前的节点，沿 next 走将永远转圈。
- 示例：`3→2→0→-4`，尾部 -4 的 next 指回值为 2 的节点 → true
- 关键约束：进阶要求 O(1) 空间；pos 只是内部标注，不作为参数传入。

### ② 思路讲解
**从朴素出发**：哈希表存访问过的节点，第一个重复出现的就是环的证据。O(n) 时间 O(n) 空间；"限定步数硬走"既不知道 n 也不严谨，别用。

**Floyd 判圈（Floyd's cycle detection，弗洛伊德判圈，俗称龟兔赛跑）**：慢针每次 1 步、快针每次 2 步。无环，快针先撞 null；有环，快针先进圈绕圈，**必然在一圈之内追上慢针**。

**为什么一定追得上（别背结论，要会推）**：设慢针刚进圈时，快针在它前方（沿前进方向）领先 k 步，0 ≤ k < 环长。此后每过一轮（慢 1 快 2），两者**相对距离缩小 1**。从 k 递减到 0 只需 k 轮，而 k < 环长——**快针至多绕一圈就能贴上慢针**。也不可能"跳过"：每轮恰好减 1，整数步进，不会从 1 直接跳到"环长−1"。

**不变量**：两针都在圈内时，每轮相对距离严格减 1（模环长意义下）；非负整数每轮减 1 必达 0，相遇是必然事件。

**套路迁移**：Floyd 判圈三件套：本题判有无环 → 142 定位入环口 → 202 快乐数（把"各位平方和"的转移链当隐式链表判圈）。一切"状态转移可能绕圈"的问题都能套：状态当节点、转移当 next。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:     # 快针要跳两步：当前与下一跳都必须存在
            slow = slow.next          # 慢 1 步
            fast = fast.next.next     # 快 2 步
            if slow is fast:          # 比"同一节点"（引用），不是比值
                return True
        return False                  # fast 撞到 null：无环
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：慢针至多走"尾段 + 一圈"步就被追上；**空间 O(1)**（哈希版 O(n)）。
- **易错点**：
  1. 循环条件只写 `fast` 不写 `fast.next`——`fast.next.next` 在尾部空引用崩溃；
  2. 用 `slow.val == fast.val` 判相遇——环上可能有重复值，必须比引用 `is`；
  3. "先前进后比较"与"先比较后前进"只能选一种贯穿，混用会漏判自环（head 指自己）。
- **面试追问**：
  1. 快针一次走 **3 步**行不行？→ 不一定：相对距离每轮减 2，若环长与初始距离奇偶不合会永远错过——步长差 1 保证必中；
  2. 为什么不用"走 n 步没到头就是有环"？→ 链长未知，且上界设多少都既可能误判又浪费；Floyd 两根指针 O(1) 空间、步数有严格上界。

## 142. 环形链表 II

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/linked-list-cycle-ii/) ｜ 标签：哈希表 · 链表 · 双指针

### ① 题意速览
在有环链表里找到**入环的第一个节点**并返回；无环返回 null。不得修改链表。
- 示例：`3→2→0→-4`，-4 指回值为 2 的节点 → 返回值为 2 的节点
- 关键约束：进阶要求不使用哈希表、O(1) 空间。

### ② 思路讲解
**哈希版（热身）**：边走边存节点引用，第一个重复的就是入口。O(n) 空间，先给保底，再上正菜。

**Floyd 两阶段之阶段二（数学推导的通俗版）**：设头到入环口 a 步、入环口到相遇点 b 步、环长 b+c。慢针走到相遇点共 a+b 步；快针快一倍走了 2(a+b) 步，它比慢针多走的全部花在环里绕圈：
- `a + b = n × (b + c)`（n 为快针多绕的整圈数，n ≥ 1）
- 整理得 `a = n(b+c) − b = (n−1)(b+c) + c`，即 **a = c + (n−1)·(b+c)**

读成人话：**从相遇点继续走 c 步正好回到入环口，再绕整圈也回到入环口；而这个距离恰好等于从 head 走到入环口的 a 步**。于是把一根指针放回 head、另一根留在相遇点，**同速每次一步**：head 那根走 a 步到入口；相遇点那根走过 c 步加若干整圈也到入口——第二次相遇就是答案。

**不变量**：两根同速指针从"相距 a（模环长）"的两个位置同时出发，a 步后必然同时站在入环口——上面等式的几何意义就是这句话。

**套路迁移**：Floyd 定式两段论——阶段一判圈得相遇点（141），阶段二同速走定入口（本题）。同款推导出现在寻找重复数（LC 287，把"下标 → 值"当 next 建隐式链表）。记住"快针多走的全是整圈"这一句，考场上能现场重推。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        # 阶段一：快慢指针找相遇点（同 141）
        slow = fast = head
        while fast and fast.next:
            slow, fast = slow.next, fast.next.next
            if slow is fast:            # 相遇：有环，进入阶段二
                p = head                # 一根指针回到起点
                while p is not slow:    # 两根同速、每次一步
                    p, slow = p.next, slow.next
                return p                # 再次相遇处 = 入环口（a=0 时循环不进，返回 head）
        return None                     # fast 撞 null：无环
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：阶段一 O(n)，阶段二至多再走 a < n 步；**空间 O(1)**（哈希版 O(n)）。
- **易错点**：
  1. 阶段二两根指针**必须同速**——沿用快慢速度永远等不到第二次相遇；
  2. 阶段二从 `head` 出发而不是从 dummy/相遇点出发，位置意义才与推导一致；
  3. 推导时别假设 n=1：快针入环时慢针可能还没进环，n 是"快针多绕的圈数"，公式里保留 (n−1) 项才对。
- **面试追问**：
  1. 为什么阶段二恰好停在入环口而不是别处？→ a = c + (n−1)(b+c)：p 走 a 步到入口时，slow 恰走完 c 步加整数圈也到入口，同刻同位；
  2. 202 快乐数和本题什么关系？→ 把"各位平方和"当作 next，非快乐数必然绕圈，141 的判圈即可判定快乐数，无需哈希。

## 21. 合并两个有序链表

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/merge-two-sorted-lists/) ｜ 标签：递归 · 链表

### ① 题意速览
把两条**升序**链表合并成一条升序链表，节点要**复用原节点**（改 next 拼接，不是新建）。
- 示例：`1→2→4` 与 `1→3→4` → `1→1→2→3→4→4`
- 关键约束：任一链表可为空（此时返回另一条）。

### ② 思路讲解
**为什么要 dummy**：结果链的真头可能是 l1 的头也可能是 l2 的头，不设虚拟节点就得先比一次并特判返回值。挂一个 dummy 在前面，tail 只管**往尾部摘节点**，最后 `dummy.next` 就是真头——返回路径零特判。

**主流程**：tail 永远指向已拼段的尾。两链都非空时，比较两链当前头，把**较小者摘下来接到 tail 后**并推进该链；某条链空了，把另一条**整段接上**——剩余部分本身有序且尾节点 next 为 null，逐个摘纯属浪费。

**不变量**：`dummy.next` 开头的已拼段始终升序，tail 恰为已拼段的尾；l1/l2 各自剩余部分仍升序。于是"摘当前两链中较小的头"每一步都维持整体有序——这就是归并排序里 merge 一步的正确性。

**递归版为何空间 O(n)**：`merge(l1, l2)` = 较小头当新头，其 next 指向"剩下两条的递归合并结果"——优雅，但递归深度 = 最终链长（两链节点总数），**调用栈 O(n1+n2)**；迭代 dummy 版 O(1)，面试先给迭代并主动指出递归的代价。

**套路迁移**：这是"归并"的最小单元：148 排序链表直接调用它做合并，23 合并 K 个升序链表是它的 k 路推广。链表必背题，练到闭眼能写。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def mergeTwoLists(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()        # 虚拟头：免"真头是谁"的特判
        tail = dummy              # 不变量：tail 始终指向已拼段的尾
        while l1 and l2:
            if l1.val <= l2.val:  # 摘较小头（<= 保稳定）
                tail.next, l1 = l1, l1.next
            else:
                tail.next, l2 = l2, l2.next
            tail = tail.next      # 尾指针推进
        tail.next = l1 if l1 else l2  # 某条空了：整段接上另一条的剩余部分
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n1+n2)**：每个节点被摘一次；**空间 O(1)**：只改 next（递归版 O(n1+n2) 栈）。
- **易错点**：
  1. 循环结束忘接尾巴 `tail.next = l1 or l2`——结果被截短，后半段丢失；
  2. 漏写 `tail = tail.next`，所有节点都挂在同一位置上互相顶掉；
  3. 元组赋值 `tail.next, l1 = l1, l1.next` 的右侧先整体求值，顺序安全——但拆成两行时必须先接后进，否则断链。
- **面试追问**：
  1. 递归版怎么写？→ `if not l1: return l2`；`l1.val <= l2.val` 时 `l1.next = merge(l1.next, l2)` 返回 l1，对称处理 l2；空间 O(n) 因为每层栈帧保留一个头节点；
  2. 合并时用 `<` 会怎样？→ 本题只判值无影响，但"稳定归并"要求相等时先取前者，养成 `<=` 的习惯，148 里保持稳定性靠它。

## 2. 两数相加

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/add-two-numbers/) ｜ 标签：递归 · 链表 · 数学

### ① 题意速览
两个非负整数按**逆序**存成链表（个位在头），求它们的和，同样以逆序链表返回。
- 示例：`2→4→3`（342）+ `5→6→4`（465）→ `7→0→8`（807）
- 关键约束：每链可达 100 个节点（大数，按位加而非转整数硬算）；两链均可能为空。

### ② 思路讲解
**为什么逆序是恩赐**：加法从**个位**开始、进位向高位传——逆序存储恰好让两表的头就是个位，**同步前进逐位相加**即可，无需反转或栈对齐。

**模拟竖式加法**：维护进位 carry。每轮取两链当前位（空位补 0）与 carry 求和：`val = sum % 10` 新建节点挂到结果尾，`carry = sum // 10` 带入下一轮。**两链都走完后 carry 若为 1 还要再补一个节点**（如 5+5=10、99+1=100）——最容易漏的一步，直接把它写进循环条件 `while l1 or l2 or carry` 最稳。

**dummy 的用法**：结果头取决于哪条链更长，挂 dummy、tail 逐个接**新建**节点（本题不是摘原节点），最后返回 `dummy.next`。

**不变量**：每轮结束后，tail 之前的结果链恰为"两数已处理低位之和"的逆序表示，carry 是尚未传向高位的进位。终态（两链皆空）只剩 carry 待处理。

**套路迁移**：逐位模拟 + 进位是"手工大数运算"模板：字符串相加（LC 415）同模子只是载体换成字符串；两数相加 II（LC 445，正序存储）先反转两链再套本题（或用栈对齐低位）。凡"手工模拟四则运算"，核心都是**对齐位 + 进位/借位**。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def addTwoNumbers(self, l1: Optional[ListNode], l2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()
        tail, carry = dummy, 0
        while l1 or l2 or carry:                 # carry 也进循环：最后一位可能再进一
            s = (l1.val if l1 else 0) + (l2.val if l2 else 0) + carry  # 空位补 0
            tail.next = ListNode(s % 10)         # 新建节点存本位（不是摘原节点）
            tail, carry = tail.next, s // 10     # 进位带入下一轮
            l1 = l1.next if l1 else None
            l2 = l2.next if l2 else None
        # 不变量：tail 前的结果链 = 已处理低位之和的逆序；carry = 待传进位
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(max(m, n))**：逐位各一遍；**空间 O(1)**（不计输出的新链，输出长 O(max(m,n))）。
- **易错点**：
  1. 循环条件漏 `or carry`——5+5、99+1 的最后进位被吞，答案少一位；
  2. 两链不等长时空位没补 0（`l1.val if l1 else 0`），直接空引用崩溃；
  3. 转大整数硬算（`int(''.join(...))`）——Python 能过但违背题意，Java/C++ 直接溢出，面试会被点名。
- **面试追问**：
  1. 数字**正序**存（LC 445）？→ 先反转两链（206 题）再做本题；或用两个栈把低位对齐弹出；
  2. 递归版怎么做？→ `add(l1, l2, carry)` 返回新建节点、next 由递归填，与迭代等价，深度 O(max(m,n))。

## 19. 删除链表的倒数第 N 个结点

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/) ｜ 标签：链表 · 双指针

### ① 题意速览
删除链表中倒数第 n 个节点（n 从 1 计），返回头节点。要求**一趟扫描**完成。
- 示例：`1→2→3→4→5`，n=2 → `1→2→3→5`
- 关键约束：1 ≤ n ≤ 链长；两遍遍历（先求长再删）不合进阶要求。

### ② 思路讲解
**从朴素出发**：先扫一遍求长度 L，倒数第 n 个即正数第 L−n+1 个，再扫到它的前驱删除。两遍 O(L)，直白但被题目点名。

**一趟的诀窍：先拉开 n+1 步再同步走**。fast 从 dummy 出发先走 n+1 步，之后 fast、slow 同速各走一步直到 fast 为 null。设链长 L：null 相当于"第 L+1 个位置"，同步阶段走 L+1−(n+1) = L−n 步，slow 从 dummy（第 0 位）落到**第 L−n 个节点**——倒数第 n 个是正数第 L−n+1 个，它的**前驱正是第 L−n 个**。口诀："间距 n+1，慢针落前驱"。

**为什么是前驱而不是目标**：删除单链表节点改的是**前驱的 next**，`slow.next = slow.next.next` 一步摘除。快慢间距若是 n，slow 会停在目标自己身上，无从下手。

**dummy 的两重价值**：① 计数从 dummy 起步，头节点也有"位置"；② n = L 时删的是**头节点**，它没有真前驱——挂 dummy 后头节点的前驱就是 dummy，与一般情况统一处理，返回 `dummy.next`。

**不变量**：同步阶段 slow 与 fast 恒距 n+1 步；fast 抵达 null 时该距离不变量给出 slow 的精确落点 = 待删节点前驱。

**套路迁移**："快针先走 k 步再同步"是定位**倒数第 k 个位置**的通用手法：本题找"倒数第 n+1 个"（前驱），面试题"链表倒数第 k 个节点"就把间距改成 k。与 141/142 的"异速"快慢同族，这里是"同速不同起点"。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def removeNthFromEnd(self, head: Optional[ListNode], n: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)     # 虚拟头：删真头时也有前驱可改
        fast = slow = dummy
        for _ in range(n + 1):        # fast 先走 n+1 步
            fast = fast.next
        while fast:                   # 同速前进，直到 fast 掉出链尾变 null
            fast, slow = fast.next, slow.next
        # 不变量：fast 与 slow 恒距 n+1 步 -> fast 为 null 时 slow 在待删节点前驱
        slow.next = slow.next.next    # 摘掉目标节点
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(L)**：一遍扫描；**空间 O(1)**。
- **易错点**：
  1. fast 先走 **n** 步而非 n+1——slow 停在待删节点上，删成了"删自己的后继"；
  2. 没有 dummy 时 n = L（删头）越界——dummy 是本题保命符，返回值也要 `dummy.next`；
  3. 循环条件写成 `while fast.next`——fast 少走一步，slow 落点偏一，删错节点。
- **面试追问**：
  1. n 可能**非法**（大于链长）怎么办？→ 先走阶段判 `fast` 提前为 null 即返回原链或报错，把防御写出来是加分项；
  2. 只给**待删节点本身**（LC 237）怎么删？→ 拿不到前驱，改为"把下一节点的值抄给自己，再删下一节点"——替身法，注意它删不了尾节点。

## 24. 两两交换链表中的节点

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/swap-nodes-in-pairs/) ｜ 标签：递归 · 链表

### ① 题意速览
相邻两个节点两两交换——必须**改 next 指针**真正交换节点，不能只交换值——返回新头。
- 示例：`1→2→3→4` → `2→1→4→3`
- 关键约束：节点数为 0 或 1 时原样返回；奇数个节点时最后一个落单不动。

### ② 思路讲解
**为什么必须画图**：交换一对节点要动**四根指针**——前驱 prev、两个交换节点 a、b、b 的后继 rest。顺序动错就断链或丢指针，且脑内模拟极易漏。纸面画出 `dummy→a→b→rest` 与目标 `dummy→b→a→rest`，代码只是翻译图。

**每组的四个动作**（以 `prev→a→b→rest` 翻成 `prev→b→a→rest` 为例）：
1. `prev.next = b`——前驱越过 a 接住 b（组间接续）；
2. `a.next = b.next`——a 接住 rest，**必须先于第 3 步**：b.next 一旦改掉，rest 只剩这一条路能找回来；
3. `b.next = a`——b 掉头指 a（组内交换）；
4. `prev = a`——**a 是新的"已处理部分的尾"**，充当下一组的前驱。

**dummy 的作用**：第一组没有真前驱，prev 无处安放——挂 dummy 后 prev 从 dummy 出发，首组与后续组写法完全一致。

**不变量**：每处理完一组，prev 指向已处理部分的**尾节点**，未处理部分以 `prev.next` 开头；凑不满两个节点就收工。

**套路迁移**：这是"分组处理链表"的最小规模版本：25 题 K 个一组翻转是它的加强版（组内从交换升级为反转、组大小可能不足），92 题区间反转是"一组但任意长"。三题共享同一骨架：**prev 记前驱 → 处理组内 → prev 移到组尾**。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def swapPairs(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy                     # 不变量：prev 指向已处理部分的尾
        while prev.next and prev.next.next:   # 凑齐一组（两个节点）才处理
            a, b = prev.next, prev.next.next
            prev.next = b                # 1. 前驱接住 b
            a.next = b.next              # 2. a 接住 rest（先于 b 掉头，防丢指针）
            b.next = a                   # 3. b 掉头指 a
            prev = a                     # 4. a 成为组尾，做下一组的前驱
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(L)**：每节点移动常数次；**空间 O(1)**（递归版 O(L/2) 栈）。
- **易错点**：
  1. 顺序错：先 `b.next = a` 再 `a.next = b.next`——此时 b.next 已指 a，rest 整段丢失；
  2. 循环条件漏第二个 `prev.next.next`——尾节点落单时凑不齐组，继续走会空引用崩溃；
  3. prev 推进到 **a**（新组尾）而不是 b——推到 b 会把下一组接在错误位置，输出乱序。
- **面试追问**：
  1. 递归版怎么写？→ 先递归处理 `swapPairs(b.next)` 得到后面已换好的头，再 `a.next = 递归结果; b.next = a` 返回 b；深度 O(L/2)；
  2. 只交换**值**行不行？→ 本题明确不许；面试可补充：值交换 O(n) 简单，但节点携带大对象负载时改值代价高，指针交换是通用解。

## 25. K 个一组翻转链表

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/reverse-nodes-in-k-group/) ｜ 标签：递归 · 链表

### ① 题意速览
每 k 个节点一组翻转链表，**末尾不足 k 个的组保持原样**；返回新头。
- 示例：`1→2→3→4→5`，k=3 → `3→2→1→4→5`（前三翻转，后两个原样）
- 关键约束：进阶要求 O(1) 空间；只能改指针、必须真翻转（不许只改值）。

### ② 思路讲解
**从 24 题升级**：组内动作从"交换两个"变成"翻转 k 个"，但骨架原封不动：**prevGroupEnd 记住已处理部分的尾，每组处理完把 prevGroupEnd 移到新组尾**。

**主流程三步**：
1. **先探组**：从 prevGroupEnd 出发向后数 k 个节点，数到第 k 个记为 end；中途撞 null 说明剩余不足 k——直接收工返回（题目要求保持原样，先探后翻让这个分支零成本，翻了再还原就麻烦了）；
2. **翻转这一组**：组起点 start = prevGroupEnd.next，下一段开头 nxtGroup = end.next 先存好。对 [start, end] 用 206 的三指针反转子程序，且 **prev 初值给 nxtGroup**——组尾翻转后自然接回下一段，不用补针；
3. **接回**：prevGroupEnd.next = 翻转后的新头（原 end）；新组尾是 start；prevGroupEnd 前进到 start。

**不变量**：每轮开始时，prevGroupEnd 及其之前已处理完毕且整链连通；`prevGroupEnd.next` 指向未处理部分。初态 prevGroupEnd = dummy 成立；终态（剩余不足 k 或走完）依然成立，返回 `dummy.next` 即正确。

**套路迁移**：本题是"焊接题"的典型：**206 的反转子程序 + 24 的 prev 组尾骨架 + 先探组的哨兵逻辑**，三个简单模块焊在一起、一个接缝都不能错。困难题常常不是新知识，而是接缝管理——同款焊接还出现在 148（找中点 + 递归 + 合并）与重排链表（LC 143）。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prevGroupEnd = dummy            # 不变量：始终指向已处理部分的尾
        while True:
            # 1. 探组：从组头数 k 个，数到 null 说明不足 k，收工
            end = prevGroupEnd
            for _ in range(k):
                end = end.next
                if end is None:
                    return dummy.next   # 剩余不足 k：保持原样
            start = prevGroupEnd.next
            nxtGroup = end.next         # 先存下一段开头，翻转后组尾要接回它
            # 2. 翻转 [start, end]（206 三指针），prev 初值给 nxtGroup
            prev, cur = nxtGroup, start
            while cur is not nxtGroup:
                cur.next, prev, cur = prev, cur, cur.next
            # 翻转完：end 是新头，start 是新尾（start.next 已自然指向 nxtGroup）
            # 3. 接回：前驱接新头，prevGroupEnd 前进到新组尾 start
            prevGroupEnd.next = end
            prevGroupEnd = start
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(L)**：每节点被数一次、翻一次；**空间 O(1)**（递归版 O(L/k) 栈）。
- **易错点**：
  1. 翻转的 prev 初值必须是 `nxtGroup` 而非 None——组尾要接回下一段，翻成指 None 就断链；
  2. 探组从 prevGroupEnd 起数（不是 prevGroupEnd.next）——起点差一位，组边界全错；
  3. prevGroupEnd 更新为 **start**（新组尾）而不是 end（新组头）——更新错人，下一组接错位置；
  4. 循环条件 `cur is not nxtGroup` 别写成 `cur is not None`——那样会把后面所有组全翻掉。
- **面试追问**：
  1. 不足 k 个**也要翻转**怎么改？→ 探组失败时不 return，把剩余段照常翻转接回即可，一行条件的事；
  2. 迭代版和递归版怎么选？→ 递归版"翻一组后 next 接 `reverseKGroup(组尾.next, k)`"代码短但栈 O(L/k)；迭代 O(1) 空间符合进阶要求，面试先写迭代。

## 138. 随机链表的复制

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/copy-list-with-random-pointer/) ｜ 标签：哈希表 · 链表

### ① 题意速览
深拷贝一条特殊链表：每个节点除 next 外还有一个 random 指针，可指向链中**任意节点或 null**。新链的 random 必须指向**新链**中对应节点，两链完全独立。
- 示例：旧节点 1 的 random 指向旧节点 2 → 新节点 1 的 random 指向新节点 2
- 关键约束：进阶要求 O(1) 额外空间（哈希版是 O(n)）。

### ② 思路讲解
**难点在哪**：next 顺着链复制没问题，可 random 可能指向**还没建出来**的节点——一遍建链连不顺，必须先解决"凭旧节点找到对应新节点"的检索问题。

**哈希两遍法**：第一遍只造节点不连线，往哈希表存 `旧节点 → 新节点` 的映射；第二遍按映射补线：`新.next = map[旧.next]`、`新.random = map[旧.random]`（旧侧为 null 用 `get` 兜底）。"查字典"消解了"目标尚未建好"的时序问题——这是引用型结构深拷贝的通用解法。

**原地插值法（O(1) 空间，面试展开）**：不用字典，把新节点当"影子"织进旧链：
1. **插值**：每个旧节点后面紧跟它的克隆，串成 `A→A'→B→B'→C→C'`；
2. **补 random**：旧 A 的 random 指向 X，则克隆 A' 的 random 就是 `X.next`——**影子永远紧随本体**，这就是插值的意义；
3. **拆链**：奇偶位分开，旧链复原、克隆链独立成串，即答案。

面试节奏：先讲哈希版（稳、好懂），被追问"O(1) 空间"再亮插值法——展示"先给正确解，再给优化解"的工程素养。

**套路迁移**："建映射解决时序依赖"家族：克隆图（LC 133）一模一样（旧→新字典 + 遍历补边）、前序中序建树同理。核心一句话：**引用关系无法一次建全时，先全部造出来，再回头补线**。

### ③ 注释代码
```python
# LeetCode 已提供 Node 节点定义（val / next / random）
class Solution:
    def copyRandomList(self, head: 'Optional[Node]') -> 'Optional[Node]':
        if not head:
            return None
        # 第一遍：只造节点，建立 旧->新 映射（先不连线：random 目标可能还没入表）
        old2new = {}
        cur = head
        while cur:
            old2new[cur] = Node(cur.val)
            cur = cur.next
        # 第二遍：按映射补 next 与 random，None 用 .get 兜底
        cur = head
        while cur:
            old2new[cur].next = old2new.get(cur.next)
            old2new[cur].random = old2new.get(cur.random)
            cur = cur.next
        return old2new[head]
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：两遍遍历；**空间 O(n)**：哈希表（插值法 O(1) 额外空间，不计输出）。
- **易错点**：
  1. `old2new[cur.next]` 在 next/random 为 None 时 KeyError——用 `.get` 或先判空；
  2. 第一遍顺手把 next 连上"看似省一遍"——random 指向的目标可能还没建，映射必须全表就位后再补线；
  3. 插值法拆链时把旧链拆坏不还原——题面要求"原链保持"，拆完务必接回原样。
- **面试追问**：
  1. 写一下插值法三步？→ 见②；点睛一句：**克隆的 random = 本体 random 的 next**，因为影子紧跟本体；
  2. 克隆图（LC 133）怎么做？→ 同一张"旧→新"字典 + DFS/BFS：造新节点入表、补邻边，本质相同——一切引用型结构的深拷贝都靠映射。

## 148. 排序链表

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/sort-list/) ｜ 标签：链表 · 双指针 · 分治 · 排序 · 归并排序

### ① 题意速览
把链表按升序排序，返回排序后的头。
- 示例：`4→2→1→3` → `1→2→3→4`；`-1→5→3→4→0` → `-1→0→3→4→5`
- 关键约束：进阶要求 O(n log n) 时间 + 常数级空间（递归归并 O(log n) 栈已是标准答案）。

### ② 思路讲解
**为什么排除快排**：快排靠"两端向中间扫 + 原地交换"，依赖随机访问；链表**只能顺 next 单向走**，双端操作与随机访问全没有。归并排序是链表的亲儿子：它只需要"按顺序访问 + 拼接"，恰好全是链表强项。

**三步骨架（全是老朋友）**：
1. **找中点并断开**：快慢指针（234 题同款，fast 初值给 head.next）找中点，再把链**从中间断开**——不断开递归就没有终点：左半还连着右半，"分"没分干净；
2. **递归排序两半**：长度 ≤ 1 直接返回（递归基）；
3. **合并**：按 21 题的 dummy + 尾指针合并两条有序链。

**复杂度账**：每层把 n 对半分、合并 O(n)，共 log n 层 → O(n log n)；递归栈 O(log n)。要真正 O(1) 空间用**自底向上归并**：步长 1→2→4→8 每轮翻倍，每轮把相邻等长段用 21 题合并、手动维护"段前驱接回"，无递归栈——思路面试讲清即可，手写工程量不小。

**不变量**：merge 返回的子链内部有序；递归函数"输入一条链、返回排好序的头"自证正确，拼接时只需维持断链后各段边界。

**套路迁移**：分治三件套在链表上的标准落地：找中点（快慢指针）+ 递归 + 合并（21 题）。同家族：23 合并 K 个升序链表（归并的多路版）、重排链表 LC 143（同样先找中点分两半再交错拼）。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
class Solution:
    def sortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        # 递归基：空或单节点天然有序
        if not head or not head.next:
            return head
        # 1. 快慢指针找中点：fast 初值 head.next，偶数长度时 slow 停在左半段尾
        slow, fast = head, head.next
        while fast and fast.next:
            slow, fast = slow.next, fast.next.next
        mid = slow.next
        slow.next = None                  # 断链！否则左半仍连着右半，递归没有终点
        # 2. 递归排两半
        left, right = self.sortList(head), self.sortList(mid)
        # 3. 合并两条有序链（21 题模板）
        dummy = tail = ListNode()
        while left and right:
            if left.val <= right.val:     # <= 保持稳定
                tail.next, left = left, left.next
            else:
                tail.next, right = right, right.next
            tail = tail.next
        tail.next = left or right         # 整段接上剩余部分
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n log n)**：log n 层 × 每层 O(n) 合并；**空间 O(log n)**：递归栈（自底向上版 O(1)）。
- **易错点**：
  1. 找中点后**忘断链** `slow.next = None`——左半还是整条链，递归永不缩小，爆栈；
  2. fast 初值用 head 而非 head.next——两节点链上 slow 停在第二个节点，mid 为空、左半仍是全链，死循环；head.next 初值让两节点恰好切成 1+1；
  3. 合并完忘 `tail.next = left or right` 接剩余段，结果截短。
- **面试追问**：
  1. 严格 **O(1) 空间**怎么做到？→ 自底向上归并：步长从 1 每轮翻倍，每轮扫描相邻两段用 21 题合并并维护前驱接回；无递归栈，讲清"每轮段长翻倍、共 log n 轮"即可；
  2. 链表上能做快排吗？→ 能但不划算：按值分三条链（小于/等于/大于）拼接，无随机访问时的变通；期望仍是 O(n log n) 但常数与实现复杂度都高，归并是链表最优实践。

## 23. 合并 K 个升序链表

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/merge-k-sorted-lists/) ｜ 标签：链表 · 分治 · 堆（优先队列） · 归并排序

### ① 题意速览
给定 k 条升序链表，合并成一条升序链表（复用原节点）。
- 示例：`[1→4→5, 1→3→4, 2→6]` → `1→1→2→3→4→4→5→6`
- 关键约束：k 可为 0；k 与总节点数 N 可达 10⁴ 量级——顺序两两合并 O(Nk) 会超时。

### ② 思路讲解
**从朴素出发**：拿 21 题挨个合并：第 1 条合第 2 条，结果再合第 3 条……最坏情形（k 条等长）下，**先合并出的长链被反复扫了 k 次**，O(Nk)。瓶颈：每一步都要在"k 个当前头"里找最小，而线性找最小是 O(k)。

**堆优化**：找最小 O(k) → 堆 O(log k)。小顶堆里放 **k 条链各自的当前头节点**（按 val 比较）：每轮弹出堆顶（全局最小）接到结果尾，**把它的 next 推回堆**。堆里永远至多 k 个节点，每个节点进出堆各一次 → **O(N log k)**。

**Python 细节**：heapq 不会用自定义比较器，元素用 `(val, 序号, node)` 三元组——序号保证 val 相同时比较下一个字段而不是 node（ListNode 没有 `<`，直接 TypeError）。

**不变量**：堆中始终恰好是"每条未耗尽链表的当前头"；堆顶一定是所有链当前头里最小的，也就是全局下一个应输出的节点。结果链因此天然有序。

**套路迁移**："多路归并 + 堆"是家族模板：本题是本体；丑数 II（LC 264）、数据流第 k 大（LC 703）是堆亲戚。第二个标准答案是**分治两两合并**：k 条对半分组递归合并，共 log k 层 × 每层总量 O(N) = O(N log k)，不依赖堆、实现朴素——面试给两个答案并对比，稳赢。

### ③ 注释代码
```python
# LeetCode 已提供 ListNode 节点定义
import heapq

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        dummy = tail = ListNode()
        heap = []
        for i, node in enumerate(lists):
            if node:                                # 空链不入堆
                heap.append((node.val, i, node))    # 序号兜底：val 相同时不比 node
        heapq.heapify(heap)
        while heap:
            val, i, node = heapq.heappop(heap)      # 全局最小的当前头
            tail.next, tail = node, node            # 摘到结果尾
            if node.next:                           # 该链推进：下一个头入堆
                heapq.heappush(heap, (node.next.val, i, node.next))
        return dummy.next
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(N log k)**：N 个节点各进出堆一次，堆规模 ≤ k；**空间 O(k)**：堆（不计输出）。
- **易错点**：
  1. 元组只放 `(val, node)`——val 相同时 Python 继续比 node，ListNode 不可比较，TypeError；
  2. lists 里的 None 没跳过就 heapify——比较炸在 None 上；
  3. 弹出后忘推 `node.next`——该链剩余部分全部丢失，结果截短。
- **面试追问**：
  1. **不用堆**怎么做？→ 分治两两合并：每轮 k 条两两配对用 21 题合并、条数减半，log k 轮共 O(N log k)，递归栈 O(log k)——与堆版同阶、实现更朴素；
  2. 顺序合并为什么是 O(Nk) 而分治是 O(N log k)？→ 顺序合并让最长的中间结果被重复扫 k 次；分治保证每条链只参与 log k 层合并，每层总量 O(N)。

## 146. LRU 缓存

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/lru-cache/) ｜ 标签：设计 · 哈希表 · 链表 · 双向链表

### ① 题意速览
设计 LRU（Least Recently Used，最近最少使用）缓存：`get(key)` 取值（不存在返回 −1），`put(key, value)` 写入；**容量满时淘汰最久未使用**的键。两个操作都要求 O(1)。
- 示例：容量 2：put(1,1)、put(2,2)、get(1)、put(3,3) → 3 挤掉 2（1 刚被用过），get(2) 返回 −1
- 关键约束：O(1) 时间是本题唯一的难点来源；key/value 均为非负整数。

### ② 思路讲解
**两个需求，两个结构**：
- "key 一查便知" → **哈希表**（单链表做不到）；
- "维护使用顺序、O(1) 淘汰最旧、O(1) 提升最新" → **双向链表**（数组挪元素 O(n)；单向链表删给定节点找前驱 O(n)）。

**组合拳**：哈希表存 `key → 节点`；双向链表按使用时间排列（头部最新、尾部最旧）。所有操作由此全 O(1)：
- `get`：查表 → 命中则**把节点摘下搬到头部**，返回值；未命中返回 −1；
- `put`：key 已存在则改值 + 搬头（**不占新容量**）；不存在则头插新节点并入表；若超容量 → **摘掉链表尾部节点**（最久未用）并从表中删除。

**为什么必须是双向链表**：摘除"给定节点"要同时改它的前驱和后继，单向链表拿不到前驱——多维护一个 prev 指针，就是为本题 O(1) 摘除付的账。

**哨兵省心**：头尾各放一个 dummy 哨兵节点（head/tail 永远存在），"链空、删头、删尾"的边界特判全部消失——单向链表题的 dummy 免"返回头"特判，这里免"边界摘接"特判，同一思想的两副面孔。

**不变量**：哈希表的每个 key 恰对应链表一个节点，反之亦然；链表从头到尾严格按"最近使用 → 最久未用"排列。任何操作动手前先保住这对"表—链"同步。

**套路迁移**："哈希表 + 双向链表 = O(1) 淘汰"是设计题黄金搭档：LFU（LC 460）在其上加"频次桶"（每档频率一条双向链表 + 全局最小频次指针）；Redis 的近似 LRU 也值得聊——真 LRU 每次访问都要动链表，Redis 用采样淘汰池省开销。

### ③ 注释代码
```python
# LeetCode 提交格式：本题入口是 class LRUCache（非 class Solution），节点类自己实现
class Node:
    def __init__(self, key: int = 0, val: int = 0):
        self.key, self.val = key, val   # key 存进节点：淘汰时凭它反删哈希表
        self.prev = None                # 双向链表：O(1) 摘除的前提
        self.next = None

class LRUCache:
    def __init__(self, capacity: int):
        self.cap = capacity
        self.map = {}                   # key -> Node
        self.head, self.tail = Node(), Node()   # 哨兵：head.next 最新，tail.prev 最旧
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node: Node) -> None:
        # 摘除节点：双向指针成对改，一个都不能漏
        node.prev.next, node.next.prev = node.next, node.prev

    def _add_front(self, node: Node) -> None:
        # 头插（标记为最近使用）
        node.next, node.prev = self.head.next, self.head
        self.head.next.prev, self.head.next = node, node

    def get(self, key: int) -> int:
        if key not in self.map:
            return -1
        node = self.map[key]
        self._remove(node); self._add_front(node)   # 命中即搬到最前
        return node.val

    def put(self, key: int, value: int) -> None:
        if key in self.map:                 # 已存在：改值 + 搬头，不占新容量
            node = self.map[key]
            node.val = value
            self._remove(node); self._add_front(node)
            return
        if len(self.map) >= self.cap:       # 满：淘汰链表尾部（最久未用）
            lru = self.tail.prev
            self._remove(lru)
            del self.map[lru.key]           # 表链同步：哈希表项必须一起删
        node = Node(key, value)
        self.map[key] = node
        self._add_front(node)
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(1)**：get/put 均为常数次哈希 + 常数次指针改动；**空间 O(capacity)**：表与链同容量。
- **易错点**：
  1. 淘汰时忘 `del self.map[lru.key]`——表链失同步，get 会"命中"已淘汰的键；
  2. put 已存在 key 的顺序：先判存在再判容量——已有键不该触发淘汰；
  3. 节点里不存 key——淘汰时拿不到该删哪个哈希表项；
  4. `_remove` 的双向指针必须成对改（`node.prev.next` 与 `node.next.prev` 同一句赋值），漏一个就断链。
- **面试追问**：
  1. **LFU**（LC 460）怎么改？→ 淘汰"频率最低"而非"最久未用"：按频次分桶、每桶一条双向链表（桶内再按 LRU 排），另维护全局最小频次，均摊仍 O(1)；
  2. Python 用 `OrderedDict` 一行能过，面试怎么说？→ 先手写哈希 + 双向链表证明懂机制，再补一句 `move_to_end` / `popitem` 是它的现成封装——两条都提是满分答法。

| 虚拟头节点 | Dummy node | 挂在真头前的占位节点，使头部增删与中部同构、免对头节点特判，返回时取 `dummy.next` |
