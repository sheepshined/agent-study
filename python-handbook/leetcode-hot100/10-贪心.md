**这个专题练什么**：贪心（Greedy，贪心算法）= 每一步都取"当前看起来最优"的选择（局部最优），并论证这些局部最优累积起来不会拖累全局。它比动态规划轻——不存子问题答案表，全程只维护"一个量"；也比动态规划险——**直觉给出的策略必须配上论证才敢提交**。贪心题的正确性论证（交换论证 Exchange Argument：证明任一最优解都能逐步替换成贪心的选择而不变差；或归纳法 Induction：证明性质从一步传到下一步）比写代码重要。本文 4 题全是"维护一个量、扫一遍"的形态：股票维护历史最低价、跳跃维护可达边界、划分维护段的义务边界——代码只是论证的注脚。

## 121. 买卖股票的最佳时机

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/) ｜ 标签：数组 · 动态规划

### ① 题意速览
给一串每天的股价 `prices[i]`，只能完成**一笔**交易（先买后卖各一次），求最大利润；一直下跌就返回 0（不交易）。
- 示例：`[7,1,5,3,6,4]` → `5`（第 2 天买 1、第 5 天卖 6）
- 示例：`[7,6,4,3,1]` → `0`（一路下跌，不交易）
- 关键约束：只有一笔交易；卖出日必须在买入日之后。

### ② 思路讲解
**从暴力出发**：枚举所有（买日 i，卖日 j>i）组合取利润最大，O(n²)。瓶颈：对每个卖出日 j，都在重新回答"j 之前哪天最便宜"这个问题，而这个答案随 j 只增不减，被重复计算了。

**为什么等价于枚举卖出日**：一笔交易由买、卖两日唯一确定。固定卖出日 j，利润 = `prices[j] − min(prices[0..j−1])`——最优买入日就是 j 之前的历史最低价，与后面的选择无关。于是枚举对象从"所有买卖对"缩成"每个卖出日"，而"历史最低价"只需一个变量随扫描滚动：每天先结算"在历史最低点买入、今天卖出"的利润，再把今天纳入历史。

**不变量（Invariant，循环每一步都保持为真的性质）**：处理完第 i 天后，`min_price = min(prices[0..i])`，且 `ans` 等于"只在前 i 天里买卖"的最大利润。"先结算、后更新"的顺序保证卖日在买日之后。一遍扫描 O(n)、O(1) 空间，把 O(n²) 里反复"找前缀最小值"压成一个滚动变量。

**套路迁移**："维护前缀最值 + 一遍扫"家族：接雨水（42 题）维护左右两侧最高柱、滑动窗口最大值（239 题）维护窗口最值。追问变体：无限次交易（LC 122）贪心收所有上涨段；带冷冻期（LC 309）/手续费（LC 714）要靠状态机 DP——"一个量"不够描述状态时，就该转 DP 了。

### ③ 注释代码
```python
class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        min_price = float("inf")  # 历史最低买入价
        ans = 0                   # 不交易的利润是 0，ans 初始为 0
        for p in prices:
            # 不变量：此刻 min_price 是"今天之前"的最低价 -> 先结算再更新，卖必在买后
            ans = max(ans, p - min_price)  # 历史最低点买入、今天卖出的利润
            min_price = min(min_price, p)  # 今天也可作为之后日子的买入日
        return ans
```
> `min_price` 初始化为 `float("inf")`：第一天的结算值 `p - inf` 为负，被 `max(ans, ...)` 吸收，首日无需特判。

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**：两个变量。
- **易错点**：
  1. `ans` 初始为 0 而非负数——全程下跌时答案就是"不交易"的 0（如 `[7,6,4,3,1]`），返回负数就错了；
  2. 别用 `max(prices) - min(prices)` 抄近路——最大值可能出现在最小值**之前**（如 `[2,10,1,3]`：该式给 9，真答案 8）；
  3. 这套"一个变量"的贪心只对**一笔交易**成立，多笔交易不能直接套；
  4. "卖在买后"靠的是"先结算后更新"的顺序保证，不是靠 `ans` 初值兜底，两行的先后不能对调。
- **面试追问**：
  1. 可以**无限次**交易（LC 122）？→ 贪心收集所有相邻上涨差值之和（等价于只吃每段上涨），或转"持有/不持有"两状态 DP；
  2. 卖出后有**冷冻期**（LC 309）？→ "持有 / 不持有且不冷冻 / 冷冻"三状态状态机 DP，一天一转移，贪心的一个量装不下。

## 55. 跳跃游戏

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/jump-game/) ｜ 标签：贪心 · 数组 · 动态规划

### ① 题意速览
`nums[i]` 表示在下标 i 处最多能向右跳 `nums[i]` 步，问能否从下标 0 到达最后一个下标。
- 示例：`[2,3,1,1,4]` → `true`（0→1→4）；`[3,2,1,0,4]` → `false`（最远停在 3，动弹不得）
- 关键约束：`nums[i]` 均为非负整数；起点固定为下标 0。

### ② 思路讲解
**从暴力出发**：DP——`dp[i]` 表示 i 可达，`dp[i] = 存在 j<i 使 dp[j] 且 j+nums[j] ≥ i`。每个 i 都要回看前面所有点，O(n²)。

**慢在哪**：判断"i 可不可达"不需要逐个检查前面的点，只需一个问题——"**目前能到的最远下标 far** 够不够到 i"。

**贪心正确性（本题灵魂，务必讲清）**：跳跃力是"最多能跳"，所以从一个可达点 j 出发，可以落在 `[j+1, j+nums[j]]` 里的**任何一格**——一个可达点点亮的是一整段连续区间。归纳论证：0 可达（初值）；若 `[0, far]` 全可达（归纳假设），扫描中每个 `i ≤ far` 都可达，并把 far 扩到 `max(far, i+nums[i])`；而 far 之外仍不可达——因为所有可达点的射程都不超过 far。于是**"能到 i 就能到 far 之间一切点"，`i > far` 是断路的充分判据**。

**不变量**：处理到 i 时，`far = max{ j + nums[j] : 0 ≤ j < i }`，且 `[0, far]` 内每个下标都可到达、far+1 及以后（就当前信息）不可达。n 步扫完即可判定，O(n²) 降为 **O(n) 时间 O(1) 空间**。

**套路迁移**："维护一个可达边界"家族：45 题是它的**分层**版（数步数）；LC 1024 视频拼接、LC 452 射气球同用"边界"直觉。口诀：可达性只问"最远能到哪"，不问"怎么到的"。

### ③ 注释代码
```python
class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)
        far = 0  # 当前能到的最远下标
        for i in range(n):
            # 不变量：[0, far] 内每个下标都可达；far = max(j + nums[j]) over j < i
            if i > far:
                return False  # 断路：已见所有点的跳力都够不到 i
            far = max(far, i + nums[i])  # i 可达 -> 它的射程并入边界
            if far >= n - 1:
                return True  # 终点已被覆盖（提前收工，非正确性依赖）
        return True  # n == 1 时起点即终点
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**。
- **易错点**：
  1. 断路判断 `i > far` 要放在**更新 far 之前**——先确认 i 可达，再让 i 扩展边界，顺序反了会把不可达点的射程混进来；
  2. `n == 1`（起点即终点）要返回 true，别把"动不了"当成 false；
  3. `far >= n - 1` 的提前返回是优化不是正确性依赖，扫完整个循环同样能判。
- **面试追问**：
  1. 求**最少**跳跃次数？→ 就是 45 题：把 far 拆成 curEnd/nextFar 两个边界，撞边界步数 +1；
  2. 若允许**往左跳**？→ 可达集合不再连续，"一个边界"失效，退回 BFS/DP。

## 45. 跳跃游戏 II

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/jump-game-ii/) ｜ 标签：贪心 · 数组 · 动态规划

### ① 题意速览
与 55 题同一设定（`nums[i]` 是下标 i 的最大跳跃力），但**保证**一定能到终点，求最少跳跃次数。
- 示例：`[2,3,1,1,4]` → `2`（0→1→4）；`[2,3,0,1,4]` → `2`
- 关键约束：测试数据保证可达；求的是最少步数而非可行性。

### ② 思路讲解
**从暴力出发**：DP——`steps[i]` = 到 i 的最少步数，对每个 i 回看所有"射程覆盖 i"的 j 取最小，O(n²)。

**关键视角（层序 BFS）**：把"恰好 k 步能到的下标集合"看成 BFS 的第 k 层：起点是第 0 层，第 k+1 层 = 第 k 层各点跳一步新覆盖的范围。因为第 k 层是一段连续下标、每个点的射程又以自己为左端，**每层恰好是一段连续区间**：记 `curEnd` = 用 k 步最远能到的下标（当前层右边界），扫这一层时用各点射程攒出 `nextFar`（用 k+1 步最远能到哪，即下一层右边界）。i 走到 `curEnd` 时这一层扫完——还没到终点就必须再起跳一次，步数 +1、`curEnd = nextFar`。BFS 的层数就是最少步数，而"层"被两个边界变量完全表示，连队列都省了。

**为什么保证最少步数**：层序 BFS 按"步数"分层，第一次覆盖终点的层数就是最少步数（步数少的层先被扫到）；本题贪心与 BFS 逐层等价——`curEnd` 就是第 k 层右边界，`nextFar` 就是第 k+1 层右边界，且相邻层无缝衔接（第 k+1 层从 curEnd+1 起），i 不会漏扫任何一层。

**不变量**：扫描到 i 时，`cur_end` = 用 steps 步能到达的最远下标，`next_far` = 用 steps+1 步能到达的最远下标（由 [0..i] 的点算出）；题目保证可达，故 `i ≤ cur_end` 恒成立。复杂度 O(n²) → **O(n) 时间 O(1) 空间**。

**套路迁移**："撞边界就结算"家族：55 题判可达、本题数步数、763 题切段——都是"维护当前区间的右边界，i 撞到边界就结算，并把边界推到 next"。LC 1024 视频拼接是同一母题的变式。

### ③ 注释代码
```python
class Solution:
    def jump(self, nums: List[int]) -> int:
        steps = 0
        cur_end = 0    # 当前步数能到的最远下标（当前层右边界）
        next_far = 0   # 扫当前层时攒出的下一层右边界
        for i in range(len(nums) - 1):  # 终点不用扫：到了终点不需要再起跳
            # 不变量：i <= cur_end（数据保证可达）；next_far = max(j+nums[j]) over j <= i
            next_far = max(next_far, i + nums[i])
            if i == cur_end:     # 撞到当前层边界：这一层到此为止
                steps += 1       # 还没到终点，必须再跳一次
                cur_end = next_far
        return steps
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**：三个变量。
- **易错点**：
  1. 循环只到 `n−2`（`range(n-1)`）：把终点当"撞边界"点会多计一步；
  2. `next_far` 要在撞边界判断**之前**每步更新——漏了层内点的射程，边界会推短、步数虚高；
  3. 照抄 55 题的 `i > far` 断路判断没坏处，但本题数据保证可达，`i <= cur_end` 恒成立，属于冗余。
- **面试追问**：
  1. 若**不保证**可达怎么办？→ 加回断路判断：撞边界时若 `next_far` 没能越过 `cur_end`，说明无路，返回 −1；
  2. 为什么不需要显式 BFS 队列？→ 每层是连续区间，两个右边界变量即可表示整层，省掉 O(n) 队列空间。

## 763. 划分字母区间

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/partition-labels/) ｜ 标签：贪心 · 哈希表 · 双指针 · 字符串

### ① 题意速览
把字符串 s 切成尽可能多的片段，使**每个字母最多出现在一个片段里**，返回每个片段的长度。
- 示例：`"ababcbacadefegdehijhklij"` → `[9,7,8]`（`"ababcbaca"`、`"defegde"`、`"hijhklij"`）
- 关键约束：片段数尽量多；字母一旦出现就被"锁死"在其所在片段。

### ② 思路讲解
**从暴力出发**：逐字符贪心切段，每切一刀都回头确认"前面段里的字母后面不再出现"，O(n²) 且实现琐碎。

**关键观察**：一个字母出现在某段，这段就必须延伸到它的**最后出现位置**。于是先预处理 `last[c]` = 字母 c 最后一次出现的下标（一遍扫描记全），再扫一遍：维护当前段的"最远义务" `end = max(last[c] : c ∈ 本段已见字母)`。i 一路走、end 一路被更远的 last 撑大；当 `i == end` 时，本段所有字母的最后出现都已落进段内——后面不会再出现本段的任何字母，**此处安全切刀**。

**不变量**：i 在本段内扫描时，`end = max{ last[c] : c ∈ s[start..i] }`，即"本段至少要延伸到 end"这一义务的当前值；`i == end` 时义务全部结清。两遍扫描，**O(n) 时间 O(1) 空间**（last 表至多 26 项）。

**与 45 题同构**：45 的 `curEnd` 是"当前步数的边界"，本题的 `end` 是"当前段的义务边界"——都是**扫到边界就结算（步数 +1 / 记段长），并用刚扫过的信息把边界推向更远**。认出这层同构，两题可以一起记。

**套路迁移**："先查每个元素的最远要求，再扫一遍合并"家族：合并区间（56 题，按左端点排序后维护右端）、无重叠区间（LC 435）。共性：把单个元素的约束预计算成端点，扫描时只做区间并。

### ③ 注释代码
```python
class Solution:
    def partitionLabels(self, s: str) -> List[int]:
        last = {c: i for i, c in enumerate(s)}  # 每个字母最后出现的下标（扫描前建全）
        res = []
        start = end = 0
        for i, c in enumerate(s):
            # 不变量：end = max(last[c'] : c' in s[start..i])，本段至少延伸到 end
            end = max(end, last[c])
            if i == end:  # 撞到边界：本段所有字母后面都不再出现，安全切刀
                res.append(end - start + 1)
                start = i + 1  # end 不必重置：新段任何字母的 last 都 > 旧 end
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：建 last 一遍 + 扫描一遍；**空间 O(1)**（last 至多 26 项，不计输出）。
- **易错点**：
  1. `last` 必须**扫描前建全**——边扫边更新信息不全，会把段切短；
  2. 切刀条件是 `i == end`（整段义务结清），别写成 `last[c] == i`（只看当前字母，段内其他字母的义务还没还清）；
  3. 返回的是**每段长度**列表，不是分割点下标。
- **面试追问**：
  1. 和 45 题的同构体现在哪？→ 同是"维护当前区间右边界 + 撞边界结算 + 边界外推"：45 结算步数、本题结算段长；
  2. 若要求每段长度尽量均衡？→ 本贪心只优化"段数最多"，均衡是另一个目标函数，需换策略（例如先按本贪心切段、再把相邻短段合并做近似）。

| 贪心 | Greedy | 每步取局部最优并论证全局不劣的策略范式，常表现为"维护一个量、扫一遍" |
