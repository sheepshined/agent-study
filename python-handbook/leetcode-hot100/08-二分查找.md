# 08 · 二分查找

> 覆盖官方专题「二分查找」，共 6 题。所有代码为 Python 3、LeetCode 提交格式（`List` 等类型由平台自动导入），中文注释。
>
> 每题统一四件套：**① 题意速览 → ② 思路讲解 → ③ 注释代码 → ④ 复杂度 · 易错点 · 面试追问**。

**这个专题练什么**：二分查找（Binary Search）的本质不是"有序"，而是**单调性/二段性**——只要能用一次判断把候选分成"必不在这边 / 只可能在那边"两段，就能每轮排除一半、O(log n) 收敛。有序数组只是二段性最常见的来源；旋转数组的"有序半"、两数组的"第 k 小消元"、与端点比较找断点，都是同一思想的变装。本文件全篇统一一套模板，先立骨架：

```python
def lower_bound(nums, target):
    """第一个 >= target 的下标；全数组都 < target 时返回 len(nums)"""
    l, r = 0, len(nums)     # 搜索区间 [l, r)：左闭右开，r 允许取到 n
    while l < r:            # 区间里还有候选就继续，收缩到一点为止
        mid = (l + r) // 2
        if nums[mid] < target:
            l = mid + 1     # mid 及其左侧整体出局
        else:
            r = mid         # mid 可能就是答案，保留
    return l                # 收缩到一点：l 即分界线
```

三条铁律：**(1) `while l < r`**——左闭右开区间为空才停，结束时 `l == r` 即答案；**(2) `l = mid + 1` 与 `r = mid`**——mid 已判过，出局要带走它、可能命中要留下它，区间每轮严格缩小、永不死循环；**(3) 返回 l**——它天然是"第一个满足谓词的位置"。**精确命中**型（33 题）可换闭区间 `while l <= r` 版，灵魂相同：每轮一次判断，排除一半。

## 35. 搜索插入位置

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/search-insert-position/) ｜ 标签：数组 · 二分查找

### ① 题意速览
升序无重复数组里找 `target`：存在返回其下标；不存在返回"插入后仍保持有序"的位置。
- 示例：`nums = [1,3,5,6]`：`target = 5` → `2`；`target = 2` → `1`；`target = 7` → `4`；`target = 0` → `0`
- 关键约束：必须 O(log n)（升序 + 互异，官方点名二分）。

### ② 思路讲解
**从暴力出发**：从左向右扫，返回第一个 `≥ target` 的元素下标，扫到头返回 n。O(n) 正确，但"有序"带来的折半能力一分没用。

**把题意翻译成一个谓词（二分的第一步）**：无论 target 存不存在，插入位置都是**第一个 ≥ target 的元素下标**——下界（lower_bound，第一个 ≥ target 的下标）：
- target 存在：第一个 ≥ target 的位置就是它自己（无重复）；
- target 不存在：第一个 ≥ target 的元素正是插入后要"顶开"的位置，插进去天然有序。

"元素 < target"在数组上呈**前真后假**的单调分布——这就是二分赖以成立的二段性，有序只是它的来源之一。

**返回 l 为什么就是插入点（三种情形一个不漏）**：模板排除到 `l == r` 时，`[0, l)` 全 `< target`、`[l, n)` 全 `≥ target`，l 是两段的分界线——
- 开头：所有元素 > target，l 停在 0；
- 中间：l 停在第一个 ≥ target 的元素处；
- 末尾：所有元素 < target，l 停在 n（这正是模板 `r` 初值取 n 的原因：区间必须能表达"插到末尾"）。

**套路迁移**：lower_bound 是二分家族的地基——34 题调它两次求区间、74 题把矩阵摊平后调它、Python 标准库 `bisect_left` 就是它。本专题的核心能力是"**把题意翻译成一个单调谓词，再套模板**"。

### ③ 注释代码
```python
class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        l, r = 0, len(nums)   # [l, r)：r 取 n，"插到末尾"才是合法答案
        while l < r:
            mid = (l + r) // 2
            # 不变量：[0, l) 全 < target；[r, n) 全 >= target
            if nums[mid] < target:
                l = mid + 1   # mid 及左侧出局
            else:
                r = mid       # mid 可能是分界点，保留
        # 收缩到一点：l == r 即分界线，也就是插入位置
        return l
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log n)**：区间每轮折半；**空间 O(1)**。
- **易错点**：
  1. `r` 初值写成 `n - 1`：target 比所有元素大时答案 n 取不到——左闭右开区间的 `r` 必须是 n；
  2. 找不到时返回的是分界线 l，不是 -1（本题要插入点，不是"不存在"标记）；
  3. 两套模板混写必错：闭区间版（`while l <= r`）必须配 `l = mid + 1`、`r = mid - 1`，左闭右开版必须配 `r = mid`——全文件统一后者。
- **面试追问**：
  1. 数组有**重复**、要返回第一个等于 target 的位置？→ 本模板原样即可（第一个 ≥ target 的位置就是第一个等于的位置）；
  2. 直接调 `bisect.bisect_left`？→ 工程上完全正确，但面试考的就是边界掌控，必须能手写。

## 74. 搜索二维矩阵

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/search-a-2d-matrix/) ｜ 标签：数组 · 二分查找 · 矩阵

### ① 题意速览
m×n 矩阵满足两条性质：(1) 每行从左到右升序；(2) 每行第一个数**大于**上一行最后一个数。判断 target 是否在矩阵中。
- 示例：`[[1,3,5,7],[10,11,16,20],[23,30,34,60]]`：`target = 3` → `true`；`target = 13` → `false`
- 关键约束：要求 O(log(m·n))；两条性质合起来等价于"按行展开是严格递增的一维序列"。

### ② 思路讲解
**从暴力出发**：全扫 O(m·n)；或逐行二分 O(m log n)。瓶颈：性质 (2)——"行与行之间也严格递增"——被白白浪费。

**关键观察**：把第 0 行接在第 1 行后面、再接第 2 行……展开成一维，得到长度 m·n 的**严格递增序列**（性质 1 保证行内、性质 2 保证行间）。于是"矩阵找数"等价于"一维有序数组找数"——35 题的模板原样搬来，一次二分 O(log(m·n))。

**虚拟下标（Virtual Index）**：真展开要 O(m·n) 复制，得不偿失。直接对虚拟一维下标 mid ∈ [0, m·n) 二分，用时 O(1) 映射回二维：**row = mid // n，col = mid % n**（n 是列数）。比较、收缩与一维模板完全一致，只是"取 nums[mid]"换成"取 matrix[mid // n][mid % n]"。

**不变量（Invariant，循环每一步都保持为真的性质）**：虚拟序列 `a[mid] = matrix[mid // n][mid % n]` 严格递增，因此 `[0, l)` 的虚拟下标值全 < target、`[r, m·n)` 全 ≥ target——与一维版同构，收缩到一点后核对落点值即可。

**对照 240 题（搜索二维矩阵 II）**：那边只有"每行递增 + 每列递增"，行与行之间没有大小关系——展开后**不再单调**，二分失效，只能从右上角出发做"每步淘汰一行或一列"的扫描 O(m + n)。两题放一起记：**能不能二分，判据就是"展开后是否单调"**。

**套路迁移**："规则结构 + 虚拟下标摊平"：凡是能由一维下标 O(1) 算出元素的规则结构（等宽矩阵等）都可摊平后二分；摊不平就退回逐行二分或淘汰扫描——选解法前先验证单调性。

### ③ 注释代码
```python
class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        m, n = len(matrix), len(matrix[0])
        l, r = 0, m * n                     # 虚拟一维区间 [0, m*n)
        while l < r:
            mid = (l + r) // 2
            # 虚拟下标 -> 真实行列：整除定行，取模定列
            x = matrix[mid // n][mid % n]
            # 不变量：虚拟序列 [0, l) 全 < target；[r, m*n) 全 >= target
            if x < target:
                l = mid + 1
            else:
                r = mid
        # 收缩到一点：l 是第一个 >= target 的虚拟下标；越界或值不等都不存在
        return l < m * n and matrix[l // n][l % n] == target
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log(m·n))**：区间每轮折半；**空间 O(1)**：没有真的展开矩阵。
- **易错点**：
  1. 行列映射写反：`row = mid // n`、`col = mid % n`（n 是**列数**）——拿 m 去除会越界；
  2. 别真展开矩阵再二分：O(m·n) 的复制把 log 级优势全赔进去；
  3. 240 题的条件（每行每列各自递增）套本题解法必错——展开不单调。
- **面试追问**：
  1. 240 题怎么做？→ 右上角出发：比 target 大左移、小下移，每步淘汰一行或一列，O(m + n)；
  2. 矩阵大到内存装不下、只能按行读？→ 先对"每行首元素"二分定行（log m），再行内二分（log n）——仍是 O(log(m·n))，还省内存。

## 34. 在排序数组中查找元素的第一个和最后一个位置

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/find-first-and-last-position-of-element-in-sorted-array/) ｜ 标签：数组 · 二分查找

### ① 题意速览
非递减数组（可有重复元素）中找 target 的**第一个和最后一个下标**，组成 `[first, last]` 返回；不存在返回 `[-1, -1]`。
- 示例：`[5,7,7,8,8,10]`：`target = 8` → `[3,4]`；`target = 6` → `[-1,-1]`
- 关键约束：必须 O(log n)——重复元素的存在让"普通二分"不够用。

### ② 思路讲解
**为什么"找到就返回"的二分会翻车**：target 有重复时，标准二分命中哪个全看运气（可能正中中间某个），既不保证最左也不保证最右；命中后向两边线性扩，极端用例（整个数组都相同）退化 O(n)，违背 O(log n)。**边界查找的正解是"排除法"**：不问"mid 等不等于 target"，只问"mid 这边能不能整体出局"。

35 题的 lower_bound 正是这样一台纯排除机器——返回第一个 ≥ target 的位置。于是两次调用同一函数、模板一字不改：
- **左边界** `first = lower_bound(target)`；
- **右边界** `last = lower_bound(target + 1) - 1`：第一个 ≥ target+1 的位置的左边一位，恰是最后一个等于 target 的位置（上界（upper_bound，第一个 > target 的下标）减一的等价写法）。

**合法性检查**：first 可能越界（数组里全 < target 时返回 n），或落点值不等于 target（target 缺席）——两种情况都返回 `[-1, -1]`。先判再求右边界，不存在时还能省一次二分。

**不变量**：同一套模板，谓词从"与 target 比"换成"与 target+1 比"，收缩出的 l 就换了一条分界线；两条分界线之间（含）恰好是所有等于 target 的元素。**一个 lower_bound，参数化的谓词，覆盖有序数组的全部边界需求**。

**套路迁移**：有序数组的区间统计全靠两条分界线相减：值域 `[x, y]` 内元素个数 = `lower_bound(y+1) - lower_bound(x)`；"target 出现次数" = `last - first + 1`。记住"**求区间 = 两条 lower_bound 相减**"。

### ③ 注释代码
```python
class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def lower_bound(t: int) -> int:
            """第一个 >= t 的下标；不存在则返回 len(nums)（模板同 35 题）"""
            l, r = 0, len(nums)
            while l < r:
                mid = (l + r) // 2
                # 不变量：[0, l) 全 < t；[r, n) 全 >= t
                if nums[mid] < t:
                    l = mid + 1
                else:
                    r = mid
            return l

        first = lower_bound(target)
        # 不存在两种形态：落点越界（全 < target），或落点值不是 target
        if first == len(nums) or nums[first] != target:
            return [-1, -1]
        # 右边界 = 第一个 >= target+1 的位置再左移一位
        last = lower_bound(target + 1) - 1
        return [first, last]
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log n)**：两次二分；**空间 O(1)**。
- **易错点**：
  1. 右边界忘减一：`lower_bound(target+1)` 给的是"最后一个 target 的下一位"；
  2. 存在性要两条都查：`first == n`（全数组 < target，空数组天然落在这条）或 `nums[first] != target`（target 缺席）；
  3. `target + 1` 写法依赖整数（Python 无溢出，其他语言注意 INT_MAX）；实数域要另写 upper_bound；
  4. 命中后向两边扩的写法最坏 O(n)（全相同数组），判题会卡。
- **面试追问**：
  1. 求 target **出现次数**？→ `last - first + 1`（两条 lower_bound 相减同理）；
  2. 不想用 `target + 1`？→ 另写 upper_bound：`nums[mid] <= t` 时 `l = mid + 1`，返回第一个 > t 的下标，`last = upper_bound(target) - 1`。

## 33. 搜索旋转排序数组

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/search-in-rotated-sorted-array/) ｜ 标签：数组 · 二分查找

### ① 题意速览
升序无重复数组在某个未知下标处被"旋转"（如 `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`），在旋转后的数组里找 target，返回下标或 -1。
- 示例：`[4,5,6,7,0,1,2]`：`target = 0` → `4`；`target = 3` → `-1`
- 关键约束：元素互异；必须 O(log n)——整体无序，普通二分的"折半"看似失效。

### ② 思路讲解
**困难在哪**：普通二分靠"nums[mid] 与 target 比一次就排除一半"，前提是 mid 两侧都有序。旋转数组整体无序，这个前提塌了一半——但只塌了一半。

**关键观察**：断点（旋转点）只有一个，从 mid 切开，**两半之中必有一半完全有序**（断点只能落在其中一边）。判断哪半有序只需一次端点比较：
- `nums[l] <= nums[mid]`：左半 `[l, mid]` 有序（取等号覆盖"左半只剩一个元素"的情形）；
- 否则右半 `[mid, r]` 有序。

**有序的那半能精确回答"target 在不在里面"**——用值域判断：左半有序时，`nums[l] <= target < nums[mid]` 则 target 在左半（`r = mid - 1`），否则必在右半（`l = mid + 1`）；右半有序时对称：`nums[mid] < target <= nums[r]` 则在右半，否则去左半。断点所在的那半**不用判**——有序半的值域装不下 target，它若存在只可能在另一半。每轮排除一半，O(log n)。

**模板变体说明**：本题是"精确命中"型（mid 等于 target 要立刻返回），用闭区间 `[l, r]` + `while l <= r` 写最顺手；"边界/收缩到一点"型（35/74/34/153 题）继续用左闭右开模板。两者灵魂一致：**每轮一次判断，排除一半**。

**不变量**：target（若存在）始终留在 `[l, r]` 内——每步移动都有"有序半值域判断"或"排除一半"的论证兜底，绝不会把答案划出去。

**套路迁移**：旋转家族二件套：本题找"指定值"，153 题找"最小值（断点）"；两段式解法（先用 153 找断点、再对两段各做一次普通二分）同样 O(log n) 但代码更长。允许重复的版本（LC 81 / 154）端点相等时无法判断，只能保守收缩，最坏退 O(n)。

### ③ 注释代码
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        l, r = 0, len(nums) - 1          # 闭区间 [l, r]：命中即返回
        while l <= r:
            mid = (l + r) // 2
            if nums[mid] == target:
                return mid
            # 不变量：target（若存在）必在 [l, r] 内
            if nums[l] <= nums[mid]:     # 左半 [l, mid] 有序（<= 覆盖 l == mid）
                if nums[l] <= target < nums[mid]:
                    r = mid - 1          # target 落在有序左半的值域内
                else:
                    l = mid + 1          # 左半有序但值域不含 target -> 只能在右半
            else:                        # 右半 [mid, r] 有序
                if nums[mid] < target <= nums[r]:
                    l = mid + 1
                else:
                    r = mid - 1
        return -1
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log n)**：每轮排除一半；**空间 O(1)**。
- **易错点**：
  1. 判左半有序写成 `nums[l] < nums[mid]`：`l == mid`（区间只剩 1~2 个元素）时会误判——必须 `<=`；
  2. 值域判断的等号：左半有序时 target 可等于 `nums[l]`（边界元素属于左半）但不可等于 `nums[mid]`（已判过）；右半对称，`nums[r]` 处取等；
  3. 未旋转（断点在头）时 `nums[l] <= nums[mid]` 恒真，自动退化成普通二分——不要画蛇添足特判；
  4. 闭区间版移动指针必须 `mid ± 1`，否则死循环。
- **面试追问**：
  1. 允许**重复**（LC 81）？→ `nums[l] == nums[mid]` 时分不清哪半有序，`l += 1` 保守收缩，最坏 O(n)（如 `[1,1,1,0,1,1]` 找 0）；
  2. 两段式解法？→ 先用 153 题找最小值得断点，再对两段各做一次 35 题式二分，同样 O(log n)。

## 153. 寻找旋转排序数组中的最小值

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/) ｜ 标签：数组 · 二分查找

### ① 题意速览
升序数组旋转 1 ~ n 次后（元素互异），找其中的**最小值**并返回。
- 示例：`[3,4,5,1,2]` → `1`；`[4,5,6,7,0,1,2]` → `0`；`[11,13,15,17]` → `11`（旋转 0 次）
- 关键约束：元素互异（含重复版本是 LC 154）；要求 O(log n)——排除 O(n) 扫描。

### ② 思路讲解
**从暴力出发**：扫一遍取 min，O(n)——没用上"旋转数组 = 两段有序拼接"的结构。

**最小值的特征**：若旋转过，最小值是**第二段的第一个元素**；未旋转则就是 `nums[0]`。它把数组切成两段：左段全部 > 右段全部（未旋转时右段为空）。要找的就是"从高段跳到低段"的那个断点。

**和谁比？——mid 与右端点 `nums[r]` 比，这是本题的灵魂**：
- `nums[mid] > nums[r]`：mid 比右段某元素还大，说明 mid 站在较高的左段里 → 最小值在 `(mid, r]`，`l = mid + 1`（mid 自己绝不可能是最小值，放心丢）；
- `nums[mid] < nums[r]`：mid 站在低段里 → 最小值在 `[l, mid]`——可能在 mid 左边，也可能**就是 mid**，只能 `r = mid` 保留。

**为什么不能与左端点 `nums[l]` 比**：`nums[mid] > nums[l]` 时无法排除任何一半——未旋转数组 `[1,2,3,4,5]`（最小值在 mid 左侧）与 `[3,4,5,1,2]`（最小值在 mid 右侧）给出同样的比较结果，判据失效。右端点无此歧义：未旋转时 `nums[mid] < nums[r]` 恒成立，范围一路压向左端，l 收敛到 0，"旋转 0 次"天然覆盖。

**不变量**：最小值始终在 `[l, r]` 内。这是"收缩到一点"模板（`while l < r`、`r = mid`）的又一次登场——只是谓词从"与 target 比"换成了"与 nums[r] 比"，再次印证：二分二分的是**二段性**，不是"数组有序"。

**套路迁移**："与右端点比较找断点"是旋转家族的基石：33 题的两段式解法第一步就是本题；LC 154（含重复）在 `nums[mid] == nums[r]` 时无法判断方向，`r -= 1` 保守收缩（nums[r] 在 mid 处有替身，丢掉不丢值），最坏 O(n)。

### ③ 注释代码
```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        l, r = 0, len(nums) - 1
        while l < r:
            mid = (l + r) // 2
            # 不变量：最小值始终在 [l, r] 内
            if nums[mid] > nums[r]:
                l = mid + 1  # mid 在高段：最小值在 mid 右侧，mid 不可能最小
            else:
                r = mid      # mid 在低段：最小值在 mid 左侧或就是 mid，保留
        # 收缩到一点：l == r 即最小值下标
        return nums[l]
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log n)**：每轮排除一半；**空间 O(1)**。
- **易错点**：
  1. 跟 `nums[l]` 比（歧义见思路）——十有八九的错误答案；
  2. `nums[mid] < nums[r]` 分支写成 `r = mid - 1`：mid 可能正是最小值，丢了就错；
  3. `while l <= r` 配 `r = mid` 会死循环——收缩到一点版必须 `l < r`；
  4. 数组未旋转时同样成立（r 一路左压到 0），无需特判。
- **面试追问**：
  1. 含**重复**（LC 154）？→ `nums[mid] == nums[r]` 时 `r -= 1`：即便 nums[r] 是最小值，mid 处有相等的替身，最坏 O(n)；
  2. 要返回"旋转了多少位"？→ 最小值下标 l 就是旋转量（右移位数），33 题两段式解法的第一步也靠它。

## 4. 寻找两个正序数组的中位数

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/median-of-two-sorted-arrays/) ｜ 标签：数组 · 二分查找 · 分治

### ① 题意速览
两个升序数组（长度可不同、允许一个为空），返回**合并后**的中位数：总长为奇数取正中，偶数取中间两数的平均。
- 示例：`[1,3]` 与 `[2]` → `2.0`；`[1,2]` 与 `[3,4]` → `2.5`
- 关键约束：不许真合并（O(m+n) 达不到要求）；要求 O(log(m+n))；总长 ≥ 1。

### ② 思路讲解
**中位数的本质是"第 k 小"**。总长 L = m + n：奇数时中位数是第 `(L+1)//2` 小（从 1 计数）；偶数时是第 `L//2` 小与第 `L//2 + 1` 小的平均。统一写成：取第 `k1 = (L+1)//2` 小与第 `k2 = (L+2)//2` 小，平均返回——奇数时 k1 == k2，**一组下标奇偶通吃**。于是问题变成：两个有序数组的并集里找第 k 小。

**第 k 小 + 二分消元（好懂好写的正解）**：每次取两数组各自的第 `⌊k/2⌋` 个候选（下标偏移 `k//2 − 1`）比一比：
- 设 `a[pi] <= b[pj]`。a 中排在 a[pi] 前面的有 `k//2 − 1` 个；b 中可能比 a[pi] 小的只可能是 b[pj] 之前的元素（b[pj] 起全部 ≥ a[pi]），至多 `k//2 − 1` 个。合计严格小于 a[pi] 的至多 `k − 2` 个，**a[pi] 自己的名次至多第 k−1**——它和它前面的 `k//2 − 1` 个统统当不了第 k 小，这 `k//2` 个元素整段安全出局。
- 出局后 k 减去**实际出局个数**，被出局数组的起点前移；某数组耗尽就直接在另一数组数第 k 个；k 减到 1 时直接比两数组当前首元素。

每轮排除 `⌊k/2⌋` 个，k 指数级缩小 → **O(log(m+n))**。对比"归并数到第 k 个"的 O(k)：消元不逐个走、整段跳，这正是"一次判断排除一批候选"的二段性威力。

**偶数下标细节**：用 `(L+1)//2` 与 `(L+2)//2` 两次调用取平均，避免"奇数一套下标、偶数另一套"的两套代码；平均必须浮点除 `/`，整数除会把 0.5 丢掉。

**划分类 O(log min(m,n)) 妙解（面试加分项，讲清思路即可）**：在**较短**数组上二分一条分割线 i（另一数组自动配 `j = (L+1)//2 − i`），使"左半 = a 的前 i 个 + b 的前 j 个"满足：左半最大 ≤ 右半最小，即 `a[i−1] <= b[j]` 且 `b[j−1] <= a[i]`（越界用 ±∞ 兜底）。i 太大说明左边装多了、太小说明装少了——天然二段性，二分找线。找到后：奇数取左半最大 `max(a[i−1], b[j−1])`；偶数再与右半最小 `min(a[i], b[j])` 平均。它把"找第 k 小"升级为"找完美分割"，比较次数压到 log(短数组)，但空数组、全落一边等边界繁杂——**考场写消元版更稳，面试口述划分类拿加分**。

**套路迁移**："第 k 小 + 消元"是双有序结构找次序的通用武器：两数组第 k 小是本体，中位数只是 k1、k2 的包装；k 个有序数组用堆归并（LC 23）；有序矩阵第 k 小（LC 378）另有"按值域二分"一条路。

### ③ 注释代码
```python
class Solution:
    def findMedianSortedArrays(self, nums1: List[int], nums2: List[int]) -> float:
        def kth(a: List[int], i: int, b: List[int], j: int, k: int) -> int:
            """在 a[i:] 与 b[j:] 的并集中找第 k 小（k 从 1 计）"""
            while True:
                if i == len(a):            # a 已耗尽：直接在 b 里数第 k 个
                    return b[j + k - 1]
                if j == len(b):            # b 已耗尽：同理
                    return a[i + k - 1]
                if k == 1:                 # 不特判则 k//2=0，谁也不出局，死循环
                    return min(a[i], b[j])
                # 各取第 k//2 个候选（下标 i + k//2 - 1）；剩余不足 k//2 个则取末尾
                pi = min(i + k // 2, len(a)) - 1
                pj = min(j + k // 2, len(b)) - 1
                if a[pi] <= b[pj]:
                    # 不变量：a[i..pi] 这段不可能包含第 k 小，整段出局
                    k -= pi - i + 1        # k 减去"实际出局个数"
                    i = pi + 1
                else:
                    k -= pj - j + 1
                    j = pj + 1

        total = len(nums1) + len(nums2)
        # 偶数取第 total//2 与 total//2+1 小的平均；奇数时两下标重合，公式通吃
        k1 = (total + 1) // 2
        k2 = (total + 2) // 2
        return (kth(nums1, 0, nums2, 0, k1) + kth(nums1, 0, nums2, 0, k2)) / 2
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(log(m+n))**：k 每轮至少减半；**空间 O(1)**：只用常数个游标。
- **易错点**：
  1. `k == 1` 不特判：`k//2 == 0`，两数组谁也出不了局，死循环；
  2. 某数组剩余不足 `k//2` 个时，候选下标要夹到末尾（`min(i + k//2, len(a)) - 1`），硬取会越界；
  3. 出局后 k 减的是**实际出局个数**（`pi - i + 1`），不是想当然的 `k//2`——候选被截短时两者不同；
  4. 平均必须 `/ 2` 浮点除；`(L+1)//2` 与 `(L+2)//2` 奇偶通吃，别写两套下标。
- **面试追问**：
  1. O(log min(m,n)) **划分法**思路？→ 短数组上二分分割线 i，`j = (L+1)//2 - i`，验证 `a[i-1] <= b[j]` 且 `b[j-1] <= a[i]`（越界 ±∞ 兜底），中位数由分割线两侧的四个边界值给出；
  2. 两数组**长度极悬殊**时选哪种？→ 划分法在短数组上二分代价极小、更优；消元版 O(log(m+n)) 通用稳健，作为保底答案。
