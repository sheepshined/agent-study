## 1. 两数之和

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/two-sum/) ｜ 标签：数组 · 哈希表

### ① 题意速览
在数组里找**两个**数，使它们的和等于目标值 `target`，返回这两个数的下标。
- 示例：`nums = [2,7,11,15]`，`target = 9` → `[0,1]`（2 + 7 = 9）
- 关键约束：恰好只有一组解；同一个元素不能被用两次；返回下标、顺序任意。

### ② 思路讲解
**从暴力出发**：两两枚举所有数对，判断和是否为 target。外层固定 i 后，内层其实在反复问同一个问题——"`target - nums[i]` 这个数在不在数组里？"两层循环 O(n²)。

**慢在哪**：瓶颈不是比较本身，而是"找数"这个动作每次都要线性扫一遍数组。

**优化**：把"扫一遍找"换成"哈希表一查便知"。一遍遍历，对当前数 x：先查表里有没有 `target - x`，查不到就把 x 连同下标存进表里。表里存的永远是"已经看过的数 → 它的下标"。

**不变量（Invariant，循环每一步都保持为真的性质）**：处理到下标 i 时，哈希表里恰好是 `nums[0..i-1]` 的"值 → 下标"映射。有了它，两条正确性白送：
- "先查后存"保证查到的下标一定 ≠ i，**天然不会把同一个元素用两次**（如 `[3,3]`、target=6）；
- 解恰好存在，所以第一次查到补数时就是唯一解。

复杂度从 O(n²) 降到 O(n)，代价是 O(n) 额外空间——典型的空间换时间。

**套路迁移**：这是"哈希快速查找"的原型题。同家族：三数之和（15 题，排序后固定一个数，剩下两个数退化成本题）、四数之和（LC 18）、和为 K 的子数组（560 题，把"值的补数"换成"前缀和的补数"，同一个模子）。

### ③ 注释代码
```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}  # 值 -> 下标：存"已经看过的数"
        for i, x in enumerate(nums):
            # 不变量：此刻 seen 里恰好是 nums[0..i-1] 的"值->下标"映射
            if target - x in seen:
                # 补数只会出现在 i 之前 -> 下标必然不等于 i，不会用同一元素两次
                return [seen[target - x], i]
            seen[x] = i  # 先查后存：顺序不能反
        return []  # 题目保证有解，此处只是形式兜底
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个元素至多一查一存；**空间 O(n)**：哈希表最多存 n−1 项。
- **易错点**：
  1. 先存后查：`x + x = target` 时会拿同一元素拼出 `[i, i]`——必须先查后存；
  2. 返回的是**下标**不是值；
  3. 哈希解法依赖"恰好一组解"，若要输出所有解需要另外设计去重（见 15 题）。
- **面试追问**：
  1. 数组**已排序**怎么办？→ 左右双指针 O(n) 时间 O(1) 空间（LC 167），比哈希省空间，但通用性差（要先排序 O(n log n)）；
  2. 找**三个**数呢？→ 固定一个数后剩下两个数就是本题（见 15 题），这是"降维"思想的原型。

## 49. 字母异位词分组

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/group-anagrams/) ｜ 标签：数组 · 哈希表 · 字符串

### ① 题意速览
把"字母构成完全相同、只是顺序不同"的单词归到同一组，返回所有组。
- 示例：`["eat","tea","tan","ate","nat","bat"]` → `[["eat","tea","ate"],["tan","nat"],["bat"]]`
- 关键约束：单词全为小写字母；顺序不同的输出无所谓。

### ② 思路讲解
**从暴力出发**：两两比较"是否互为异位词"（排序后相等就是），相同的塞进一组。n 个词要比较 O(n²) 次，每次还要 O(k log k) 排序（k 为词长），太慢。

**慢在哪**：每来一个新单词，都在和"已有的组"重复比较。分组问题的正确姿势是**一次分类**：同一个组里的所有元素，必须能映射到**同一个 key**。

**优化**：给每个单词找一个"标准形（canonical form）"当 key——把单词排序，`"eat"/"tea"/"ate"` 都变成 `"aet"`。排序后相等的才是异位词，这一个 key 就够。遍历一遍，每个单词按 key 进桶（`dict` 的 value 是列表），最后把所有桶输出即可。

**不变量**：任何时刻，互为异位词的单词当且仅当落在同一个桶里——因为 key 相等 ⇔ 排序后相等 ⇔ 字母多重集（多重集合，元素可重复）相等。

**再进一步（面试加分）**：排序 key 的代价是 O(k log k)。其实不必排序：26 个字母各出现几次本身就是身份证明，用 `tuple(counts)` 当 key，单次归类降到 O(k)。这展示了哈希题的核心自由度——**key 不必是数据本身，可以是数据的任意"指纹"，指纹越贴近本质，分类越快**。

**套路迁移**："设计哈希 key"家族：本题用"排序后的串"，128 题用"连续段的起点"，438 题用"26 位计数向量"做窗口指纹。凡是"按特征分组/匹配"的题，先问一句：特征能不能压缩成一个可哈希的 key？

### ③ 注释代码
```python
from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs: List[str]) -> List[List[str]]:
        groups = defaultdict(list)  # key = 单词的"标准形" -> 同组单词列表
        for s in strs:
            # 方案一（O(k log k)）：排序后的串当 key
            key = ''.join(sorted(s))
            # 方案二（O(k)，面试可提）：26 位计数向量当 key
            # cnt = [0] * 26
            # for ch in s:
            #     cnt[ord(ch) - 97] += 1
            # key = tuple(cnt)  # tuple 可哈希，list 不行
            groups[key].append(s)
        # 不变量：互为异位词 <=> key 相同 <=> 同一个桶
        return list(groups.values())
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n·k log k)**（n 个词、词长 k；计数 key 版为 O(n·k)）；**空间 O(n·k)**：桶与 key 的开销。
- **易错点**：
  1. 计数 key 忘了转 `tuple`——`list` 不可哈希，直接 `TypeError`；
  2. 用 `dict.setdefault` 或 `defaultdict` 二选一，普通 dict 直接 `groups[key].append` 会 KeyError；
  3. 别用"字母和"之类的弱指纹当 key：`ad` 与 `bc` 和相同但不是异位词。
- **面试追问**：
  1. 单词里含**Unicode/大写**怎么办？→ 计数数组开不下，退回排序 key（排序对任意可比字符都成立）；
  2. 数据量大到内存装不下？→ 按 key 分片（shuffle）后分布式分组——MapReduce 的 `word count` 同款思路，key 分区天然并行。

## 128. 最长连续序列

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/longest-consecutive-sequence/) ｜ 标签：并查集 · 数组 · 哈希表

### ① 题意速览
无序数组里，找值上连续的一段整数（如 1,2,3,4），返回最长能连多长。**不要求这些数在数组里相邻**。
- 示例：`[100,4,200,1,3,2]` → `4`（1,2,3,4）
- 关键约束：必须 O(n) 时间（官方明确要求，排除"先排序"）；可能有重复和负数。

### ② 思路讲解
**从暴力出发**：排序后线性扫一遍，相邻差 1 就连上。简单，但 O(n log n)，题目点名要 O(n)。

**空间换时间的地基**：把所有数扔进集合（set），"x 存不存在"变成 O(1) 查询。于是可以"从每个数 x 向上数"：x+1 在吗？x+2 在吗？……数到断为止，得到从 x 出发的段长。但这样最坏还是 O(n²)：`[1,2,3,...,n]` 里每个数都会把同一条链数到底。

**关键观察**：一条长为 L 的连续段会被数 L 次，因为段里**每个成员**都当了一次"出发点"。但一段只有一个**起点**——"x−1 不在集合里"的 x。**只让起点发起向上数**，段内其他成员直接跳过：每条链就只被完整数一次。

**不变量**：只有起点才进入内层 while；从起点 s 出发，while 会恰好走完 s 领头的整段（段内成员都在集合里，段外第一个不在）。因此内层 while 的总步数 ≤ 总元素个数，整体 O(n) 得证——这就是"每个元素至多被访问常数次"的均摊（amortized，把偶发的贵操作摊到多次便宜操作上）分析。

**套路迁移**："集合 + 只从特殊位置发起"家族：本题是"只从段起点数"，连通块计数（200 岛屿数量）是"只从块内第一个访问的格子 DFS"。共性：**给等价类找一个唯一的代言人，让每个元素只被代言人处理一次**。

### ③ 注释代码
```python
class Solution:
    def longestConsecutive(self, nums: List[int]) -> int:
        num_set = set(nums)  # 去重 + O(1) 存在性查询
        best = 0
        for x in num_set:
            # 只从"序列起点"出发：x-1 不在集合里，说明 x 是某段的最小值
            if x - 1 in num_set:
                continue  # 不是起点：它会被自己所在段的起点数到，跳过
            # 不变量：x 是起点，while 会恰好走完 x 领头的整段
            cur = x
            length = 1
            while cur + 1 in num_set:
                cur += 1
                length += 1
            best = max(best, length)
        return best
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：外层每数一次 + 内层只从起点发起，总步数 ≤ 2n；**空间 O(n)**：集合。
- **易错点**：
  1. 忘了判 `x - 1 not in num_set`，退化成 O(n²)——这是本题唯一但致命的坑；
  2. 遍历 `nums` 原数组而非集合：重复元素会重复发起（有起点判断兜底不致错，但多浪费）；
  3. 空数组要返回 0，不是抛错。
- **面试追问**：
  1. 要**输出这个序列本身**？→ 记录 best 段的起点和长度，最后返回 `list(range(start, start + best))`；
  2. 并查集（Union-Find，一种"合并集合 + 查代表"的结构）也能做：x 与 x+1 合并，答案取最大集合——能讲出两种解法与各自的空间取舍是加分项。

## 283. 移动零

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/move-zeroes/) ｜ 标签：数组 · 双指针

### ① 题意速览
把数组里所有 `0` 挪到末尾，非零元素保持原来的相对顺序，要求**原地**（不开新数组）。
- 示例：`[0,1,0,3,12]` → `[1,3,12,0,0]`
- 关键约束：原地操作；尽量减少操作次数（进阶要求）。

### ② 思路讲解
**从朴素出发**：开一个新数组，先抄所有非零元素，再补零。O(n) 时间但 O(n) 空间，违反"原地"。

**快慢指针（读写双指针）**：让 slow 指向"**下一个非零元素应该落的坑**"，fast 负责扫描。fast 遇到非零数，就把它放进 slow 的坑里，slow 前进一位；fast 走完后，`[slow, n)` 这个区间里剩下的全是坑，统一填 0。

**不变量**：任意时刻——
- `[0, slow)`：全是非零元素，且**保持原相对顺序**（每个都来自 fast 已扫过的前缀）；
- `[slow, fast)`：全是 0（被非零元素"腾出来"的坑）；
- `[fast, n)`：还没看。

fast 只增不减、slow 只被非零元素推进，两指针各走一遍数组，O(n) 一次搞定。

**再进一步（交换版，写次数更少的论证）**：也可以不"填零"，直接把 fast 的非零元素与 slow 位置**交换**：坑被立刻填上，0 自动被甩到后面。不变量同样成立，且省掉第二遍填零循环；当数组几乎全非零时，`slow == fast` 是自我交换（无害）。面试说出两种写法并讲清取舍（赋值版整体写 2n 次、交换版写 ~2×非零数次）即可。

**套路迁移**：这是"读写分离"双指针的原型：快指针读、慢指针写。同家族：移除元素（LC 27，把"≠0"换成"≠val"）、删除有序数组重复项（LC 26）、颜色分类（75 题，把两种颜色扩成三种）。

### ③ 注释代码
```python
class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        """原地修改，函数无返回值"""
        slow = 0  # 下一个非零元素应落的坑
        for fast in range(len(nums)):
            # 不变量：nums[0..slow-1] 全非零且保序；nums[slow..fast-1] 全为 0
            if nums[fast] != 0:
                if slow != fast:  # 避免自我交换（无害，但跳过更省）
                    nums[slow], nums[fast] = nums[fast], nums[slow]
                slow += 1  # 坑被非零元素填上，坑指针右移，被换走的 0 留在 fast 侧
```
> 若想写次数更少，可用**赋值版**：`nums[slow] = nums[fast]; slow += 1`，扫完后把 `nums[slow:]` 整段置 0——两次遍历、总写次数 = 非零个数 + 零个数。

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**：原地。
- **易错点**：
  1. 交换版里 `slow += 1` 必须放在交换之后（先填坑再挪坑指针）；
  2. 用"赋值 + 末尾补零"版时，补零区间是 `[slow, n)` 别写错；
  3. 本题要求**稳定**（非零元素相对顺序不变），交换版恰好满足——若把"非零"换成"偶数"等条件同样成立。
- **面试追问**：
  1. 若要求**写次数最少**（题面的进阶）？→ 赋值版：非零直接赋给 slow，最后一次性把尾部置 0，总写次数 = 非零个数 + 零个数；
  2. 链表版怎么移零？→ 同样快慢指针摘节点重接，注意别断链（对照 206 反转链表的指针手法）。

## 11. 盛最多水的容器

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/container-with-most-water/) ｜ 标签：贪心 · 数组 · 双指针

### ① 题意速览
n 条垂直线段，第 i 条在 x=i、高 `h[i]`。任选两条与 x 轴围成容器，容量 = `min(两边较矮者) × 宽度`，求最大容量。
- 示例：`[1,8,6,2,5,4,8,3,7]` → `49`（选下标 1 和 8：min(8,7) × 7 = 49）
- 关键约束：n ≥ 2；不能倾斜容器。

### ② 思路讲解
**从暴力出发**：枚举所有数对 `(i, j)` 算容量取最大，O(n²)。瓶颈：大量组合明显不可能赢，却在被认真计算。

**对撞指针**：`l = 0`、`r = n−1` 从最宽的组合开始，每轮记录容量，然后**移动较矮的一侧**，直到两指针相遇。

**为什么移动较矮一侧是安全的（本题的灵魂）**：设当前 `h[l] ≤ h[r]`。若保留 l、把 r 往里移，宽变小，而高度受 `min` 限制——不管新边多高，水位都不会超过 `h[l]`，所以面积**不可能超过当前值**。也就是说：**当前组合是 l 能参与的所有组合里最优的**（其他组合更窄），记录完它就可以放心淘汰 l。每一步淘汰一侧，n−1 步走完。

**不变量**：被淘汰的每条边，它"能参与的最优组合"已被记录；剩余的 `(l, r)` 区间里仍可能藏着全局最优。于是指针扫描一遍 O(n) 就覆盖了所有"可能赢"的组合——双指针的通用证明套路：**证明被跳过的组合一定不优**。

**套路迁移**：对撞指针家族：两数之和 II（LC 167）、三数之和（15 题）、验证回文串（LC 125）。记忆口诀："找对儿优化先对撞，谁矮（差）谁让路"。42 接雨水是它的 HARD 进阶，同一个"较矮一侧说了算"的直觉。

### ③ 注释代码
```python
class Solution:
    def maxArea(self, height: List[int]) -> int:
        l, r = 0, len(height) - 1
        best = 0
        while l < r:
            # 不变量：被淘汰的边，其最优组合都已记录在 best 里
            area = min(height[l], height[r]) * (r - l)
            best = max(best, area)
            if height[l] <= height[r]:
                l += 1   # 较矮一侧可以安全淘汰：它参与的所有剩余组合都不更优
            else:
                r -= 1
        return best
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每轮淘汰一条边；**空间 O(1)**。
- **易错点**：
  1. 移动**较矮**一侧——移动较高一侧会漏掉最优解（高边还可能配到更高的矮边）；
  2. 两侧等高时任移一侧即可，但**不能两边都不动**（死循环）；
  3. 先算面积再移动，顺序反了会漏掉当前组合。
- **面试追问**：
  1. 为什么等高时随便移一边不会错？→ 设 `h[l] == h[r]`，任何同时保留两者的组合不会更优；而淘汰 l 保留 r 的组合与淘汰 r 保留 l 的组合是对称的，另一侧的最优已被"min 不超过 h"论证覆盖；
  2. 本题和 42 接雨水为什么解法气质不同？→ 本题选**两条边**（组合优化），接雨水算**每一列**上方的水（总量统计），后者要的是"两侧最大值"信息而非"一条边"。

## 15. 三数之和

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/3sum/) ｜ 标签：数组 · 双指针 · 排序

### ① 题意速览
数组里找出**所有**"三个不同下标的数之和为 0"的三元组，答案不能有重复三元组。
- 示例：`[-1,0,1,2,-1,-4]` → `[[-1,-1,2],[-1,0,1]]`
- 关键约束：答案去重（值相同的算同一个）；三元组内下标互异。

### ② 思路讲解
**从暴力出发**：三重循环枚举 O(n³)，再用集合给结果去重——又慢又容易在去重上翻车。

**第一步降维**：`a + b + c = 0` 固定 a 之后就是"b + c = −a"——**两数之和**！但数组无序、还要求不重复枚举，先**排序**：排序带来两个礼物——(1) 相同值相邻，去重变得容易；(2) 有序数组上找两数之和可以用对撞指针 O(n)。

**主流程**：i 从头枚举 a（剩下两个数在 i 右侧找），区间 `[i+1, n-1]` 上对撞指针找和为 `−nums[i]` 的对：和小了移左指针，和大了移右指针，相等则收集一组解并继续找。

**两处去重（缺一不可）**：
1. **枚举 a 的去重**：`i > 0 且 nums[i] == nums[i-1]` 时跳过——同一个 a 值上一轮已经找全了，再找必出重复；
2. **指针去重**：收集到一组解后，left/right 各自跳过与刚用掉的值相同的元素——否则同一对 b、c 会再被收集一次。

**不变量**：对每个 a，`(l, r)` 在右侧区间内已穷尽所有和为 `−a` 的组合；加上两处去重，答案中每个三元组恰好收集一次。

复杂度：排序 O(n log n) + 外层 n 次 × 内层 O(n) = **O(n²)**。与暴力比，省掉的不是常数，是整整一维。

**套路迁移**：这是"排序 + 枚举一个 + 对撞指针"的模板题：四数之和（LC 18）再外套一层枚举成 O(n³)；"最接近的三数之和"（LC 16）把"找等于"换成"维护差值最小"。通用心法：**k 数之和 = 枚举一层 + (k−1) 数之和**，递归到两数之和为止。

### ③ 注释代码
```python
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()  # 去重与对撞指针都依赖有序
        res = []
        n = len(nums)
        for i in range(n - 2):
            if nums[i] > 0:          # 剪枝：a>0 时后两个更大的数不可能凑出 0
                break
            if i > 0 and nums[i] == nums[i - 1]:
                continue             # 去重①：a 值本轮已找全
            l, r = i + 1, n - 1
            target = -nums[i]
            # 不变量：[l, r] 内尚未穷尽所有和为 target 的组合
            while l < r:
                s = nums[l] + nums[r]
                if s < target:
                    l += 1
                elif s > target:
                    r -= 1
                else:
                    res.append([nums[i], nums[l], nums[r]])
                    l += 1
                    r -= 1
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1       # 去重②：跳过重复的 b
                    while l < r and nums[r] == nums[r + 1]:
                        r -= 1       # 去重②：跳过重复的 c
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n²)**（排序 O(n log n) 被主项淹没）；**空间 O(log n)**（排序栈，不计输出）。
- **易错点**：
  1. 两处去重少一处都出重复答案——这是本题判题的重点；
  2. 找到解后**继续**收缩指针找下一组，不是找到就 break；
  3. `nums[i] > 0` 的 break 是剪枝不是正确性依赖，删掉也对但慢。
- **面试追问**：
  1. 推广到 **k 数之和**？→ 递归降维：k 数 = 枚举一层 + (k−1) 数，到 2 数用对撞指针，总 O(n^(k−1))；
  2. 为什么不用哈希表做两数部分？→ 本题要"所有不重复组合"，排序 + 双指针天然有序、去重方便；哈希也能做但去重逻辑更绕（面试能对比即可）。

## 42. 接雨水

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/trapping-rain-water/) ｜ 标签：栈 · 数组 · 双指针 · 动态规划

### ① 题意速览
一排柱子高度 `height[i]`，下雨后凹槽能接多少水，求总水量（按列累加）。
- 示例：`[0,1,0,2,1,0,1,3,2,1,2,1]` → `6`
- 关键约束：n ≥ 2（两边柱子外侧不存水）；宽度为 1。

### ② 思路讲解
**按列拆解（想通这步题就解了一半）**：第 i 列上方的水量 = `min(左边最高柱, 右边最高柱) − height[i]`（为负记 0）。水位由**两侧较矮的那堵墙**决定——水翻不过矮墙。

**暴力 → 预处理**：每列都向左右各扫一遍找最高，O(n²)。瓶颈同样是"重复扫描"。解法与 128 题同款：预处理 `leftMax[i]`（含 i 的左侧最大）与 `rightMax[i]`（含 i 的右侧最大），各扫一遍数组，之后每列 O(1) 结算——**O(n) 时间 + O(n) 空间**。

**双指针压掉空间（O(n) + O(1)）**：`leftMax`/`rightMax` 数组其实每步只各用一项，可以换成两个变量。`l, r` 对撞，维护 `leftMax = max(height[0..l])`、`rightMax = max(height[r..n-1])`。**核心不变量**：若 `leftMax < rightMax`，那么 `l` 列的真实水位就是 `leftMax`——虽然右侧远处我们没看全，但 `rightMax`（只统计了一部分右区间）已经 > leftMax，真实的右侧最高只会更大，**矮墙在左边是板上钉钉**，于是可以放心结算 l 列并右移；对称地，`rightMax < leftMax` 时结算 r 列。**谁的最大值小就结算谁**，每次 O(1)，两指针相遇即结束。

还有一条**单调栈**路线：维护高度递减的栈，来了一根更高的柱子就"横向"结算一层水（栈顶是坑底，左右是墙）——那是栈专题（09 文件 84 题）的主场，思路先埋个伏笔。

**套路迁移**：本题是"预处理前缀/后缀信息 + 双指针压缩空间"的巅峰示例：动态规划版（leftMax/rightMax 数组）好想好写，双指针版省空间但要证不变量。**面试先写 DP 版拿稳，再升级双指针版**是标准策略。同家族：柱状图中最大的矩形（84 题）、盛最多水的容器（11 题）。

### ③ 注释代码
```python
class Solution:
    def trap(self, height: List[int]) -> int:
        l, r = 0, len(height) - 1
        leftMax = rightMax = 0  # 分别是已扫过左右区间的最大值
        water = 0
        while l < r:
            if height[l] < height[r]:
                # 左边这根比右边最矮的已知墙还矮 -> leftMax 能否盖过它已定
                leftMax = max(leftMax, height[l])
                water += leftMax - height[l]  # 不变量：右侧真实最高 >= rightMax > leftMax
                l += 1                        #   所以 l 列水位由 leftMax 决定，可安全结算
            else:
                rightMax = max(rightMax, height[r])
                water += rightMax - height[r]  # 对称：结算 r 列
                r -= 1
        return water
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每列结算一次；**空间 O(1)**（DP 版为 O(n)）。
- **易错点**：
  1. 水量可能为负的列要记 0（本写法因 `leftMax ≥ height[l]` 天然非负，换成"先减后 max"的写法就踩坑）；
  2. 结算对象是**较矮一侧的列**，不是随机选一边；
  3. `leftMax` 是否"含当前列"要与更新顺序配套：先 `max` 再结算，或先结算再 `max`，两种写法只能选一种贯穿始终。
- **面试追问**：
  1. **二维版**接雨水（LC 407）？→ 外圈是墙，用小顶堆从边界向内"注水收缩"，堆保证每次结算的是当前水位最低的边界格；
  2. 用**单调栈**写一版？→ 维护递减栈，遇高柱弹栈结算横向水层，宽 = 右墙 − 左墙 − 1、高 = min(两墙) − 坑底；与 84 题同族，见 09 文件。
