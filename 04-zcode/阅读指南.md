## 1. 项目定位

ZCode 是**一个"多形态产品"里长出来的 coding agent**：agent 内核在 `apps/zcode-cli`（一个内嵌的独立 workspace），而 Desktop（Electron）、Web（Hono server + React）、SDK、手机远控共享 `packages/` 下那 14 个包，并通过 **ZCode Protocol V4** 与内核通信。它的主循环是**三层结构**（turn → provider-turn 循环 → 单个 model step），这一点比另五家都更明确地把"回合/步骤/请求"分层。

六家横向一句话对比：

| | 内核形态 |
|---|---|
| ZCode | 三层显式循环 + 事件溯源 SQLite + 多宿主（stdio 协议）|
| Claude Code | 单循环 `query()` 递归 |
| Codex | `run_turn` + step，Rust app-server 守护进程 |
| DeepSeek Harness | Cordis 插件树上的 agent-loop 驱动器 |
| OpenCode | Effect HttpApi server，TUI 只是它的 HTTP 客户端 |
| OpenClaw | 常驻 Gateway，输入是消息事件 |

⚠️ **运行前必读 `NOTICE.md`**（这是全仓库最被低估的一页，中文写的风险声明）：

- `NOTICE.md:9`：**"当前共享 Agent 执行适配器不提供默认的操作系统沙箱"**，且明确"工作目录、工作区身份、Git worktree、浏览器页面隔离和 Node REPL 的运行上下文，均不应被当作所有工具的系统级隔离保证"。
- `NOTICE.md:11`：**共享配置默认 `build` 模式；独立 CLI 用 `--prompt` 跑非交互任务时，未带 `--mode` 会采用 `yolo`**（`CLI:cli/src/run.ts:42` 已核实）。
- `NOTICE.md:24`：Computer Use（`PKG:zcode-cua`）是**占位**。
- `NOTICE.md:39`：命中官方两个 Anthropic 兼容端点时会**自动改写到 ZCode 网关且无逐次确认**。
- `NOTICE.md:58-64`：会话库默认 `~/.zcode/cli/db/db.sqlite`；凭据是"本地加密文件、密钥可从本机派生，也接受明文"，**不是系统钥匙串**。

## 3. 顶层目录导览

```
packages/*                      ← 14 个共享包（UI/服务/宿主/协议）
apps/zcode-cli                  ← ★ 内嵌的第二个 workspace（agent 内核）
apps/zcode-cli/packages/*       ← 16 个子包
apps/zcode-cli/tools/*          ← prompt-trajectory、typescript
harness/remote                  ← ⚠️ 只是一个 SSH 联调容器
config/{default.json,provider/} ← 反馈 URL + 内置 provider 目录
third-party/                    ← 纯合规材料，无 vendor 源码
scripts/                        ← 40+ 个 mjs（bootstrap/build/native-search/architecture/许可证）
```

**pnpm workspace 四组**（`pnpm-workspace.yaml:1-5`）。`apps/zcode-cli` 自带 `pnpm-workspace.yaml`、`pnpm-lock.yaml`、`turbo.json`、`.release-it.json`、`skills-lock.json`，作为普通目录随主仓一起克隆（`README.md:32`【文档】，目录存在【实证】）。工具链：`packageManager: pnpm@10.33.2`（`package.json:98`）、`engines.node: ">=24"`（`:93`）、`.nvmrc=24`、`mise.toml:2-3` 锁 node 24.14.0 + pnpm 10.33.2；turbo ^2.4.0；`tsconfig.base.json` 开 composite + `verbatimModuleSyntax`，typecheck 是 `tsc -b` 项目引用链（`package.json:36`）；`.npmrc:1` `node-linker=hoisted`。

**`harness/` 是什么（一个容易误读的点）**：里面**只有一个 `remote/`**——`Dockerfile`（ubuntu:22.04 + sshd + root/dev 账号）、`build.sh`、`README.md`（两行：`docker run -p 2222:22` + `ssh-copy-id`）。它是"**远程 SSH 工作区联调容器**"，跟 slogan 里的 "coding agent harness" 没关系。真正的"被 harness 的东西"是 `apps/zcode-cli`。

也支持 mise 任务：`mise run install|bootstrap|dev|dev-web|typecheck|lint`（`mise.toml:11-40`，统一经 `scripts/mise-run.mjs`）。需要远程（SSH/WSL）资源时 `pnpm bootstrap:with-remote`。打包产物调试：`node dist/zcode/debug/zcode/bin/zcode.mjs --web --port 3030 --no-open`（`README.md:160-204`）。登录 `zcode login [zai|bigmodel]`（`en-US.ts:19`）。

**两个坑**：

1. **`harness/remote` 不是 agent harness**（第 3 节），别按 DeepSeek Harness 的 `native/` 去理解它。
2. **没有可跑的测试网**：`git ls-files` 里只有 4 个 `*.test.ts(x)`，且**没有任何 `package.json` 含 `"test"` 脚本**（已实测 `grep -l '"test":' … | wc -l` = 0）。这与 `CLI:zcode-cli/AGENTS.md:9` "测试 case 很关键，能证明结果是否符合预期"直接矛盾。行为回归只能靠 `pnpm typecheck` + `pnpm lint` + `pnpm architecture:check` + 手工跑 CLI + 读 `~/.zcode/cli/rollout` 的模型 I/O 轨迹。

## 7. 术语表

| 术语 | 含义 |
|---|---|
| **CollaborationMode** | 权限模式，5 值：`plan \| build \| edit \| yolo \| auto`（`CLI:contracts/src/interfaces/session.port.ts:32`，已核实）。**没有** `acceptEdits`/`bypassPermissions`。`auto` 是**占位**，`permission/service.ts:140-146` 直接 deny：`"Auto mode is reserved but not implemented yet"` |
| **三层循环** | turn（`turn.ts:93`）→ provider-turn 外层循环（`turn-loop.ts:43`）→ 单个 model step（`turn-model-step.ts:133`）。一次 turn 可含多个 provider-turn，每个 provider-turn 一个模型请求 + 它的工具执行 |
| **`alwaysAsk`** | 不可被模式抹掉的独立审批通道：yolo 与 plan 的放行都要先让给它，但 `disallowedTools` / 项目 deny / auto 又压得过它（`permission/service.ts:131→:333-392`）。决策对象带结构化 `alwaysAsk` 标记（`:70-75`）供 PreToolUse hook 判断"这个确认不可被抹掉" |
| **sideEffectScope** | 工具副作用声明：`none \| workspace \| git \| network \| system`；权限系统/sandbox/审批**只读这些声明**，不靠调用点临时猜（`CLI:zcode-cli/AGENTS.md:61-66`） |
| **`CommandInbox`** | 已接受的 busy/running 输入的**串行 admission** 队列（`CLI:bootstrap/src/zcode-protocol-v4/command-inbox.ts`；根 AGENTS.md:65） |
| **microcompact** | 只把旧 tool result 换成 `[Old tool result content cleared]`，不动历史：`keepRecentToolResults=5`、`thresholdRatio 0.9`、`buffer 2000`、`minTokenSavings 256`、可压工具白名单（`compact/microcompact.ts:11-28`） |
| **auto compact** | 阈值：`contextWindow 200k`、输出预留 `min(maxOutput, 21_000)`、`AUTOCOMPACT_BUFFER_TOKENS 13_000`、`thresholdPercent 100`、连续失败 3 次熔断（`compact/policy.ts:8-14`；决策 `:90-160` 带 `reason`） |
| **reactive compact** | 超窗错误/finish reason 之后的补救压缩，配 **rapid-refill 断路器**（`turn-loop.ts:77-102` 的 `evaluateRapidRefill`，命中 `"rapid_refill_blocked"` 直接抛错；执行 `turn-model-step.ts:742-803`） |
| **streaming tool coordinator** | 边流式边执行：模型还在吐 tool call 时就已经进协调器排队（`turn-model-step.ts:209` + `streaming-tool-coordinator.ts`） |
| **system-reminder attachment** | 四类运行时注入提醒：`plan_mode_exit` / `runtime_mode` / `todo_reminder` / `output_style`（`turn-loop.ts:120-167`） |
| **cacheHint / cache-control** | 显式 prompt cache 管理：builder 每段可带 `cacheHint:"stable"`，loop 在 provider 可见投影**之后**统一设 cache-control（`turn-loop.ts:168-186` + `helpers/provider-request-messages.ts:302-313`）；另有 `--force-mcs` 中期 system 投影开关 |
| **ZCode Protocol V4** | 宿主（Desktop/Web/SDK/手机）与内核之间的 stdio 帧协议；命令面在 `CLI:bootstrap/src/zcode-protocol-v4/`；协议类型与运行时校验只落 `PKG:shared/src/zcode-protocol/index.ts` |
| **app-server / agent-server** | `zcode app-server --stdio` / `agent-server`（`run.ts:525-533`）：stdout 是严格帧通道，console 改道 stderr（`main.ts:30-35`） |
| **window-scoped Local Host** | 桌面端每个窗口一个 Local Host，本地 workspace 共享它；远程 workspace 由窗口内连接注册表管理（根 AGENTS.md:61-63） |
| **attachment（手机远控）** | 手机复用桌面已有 Host attachment，**不另起 Agent/Local Host/远程会话**；`desktop-continuous`（实时链路）与 `web-remote-replayable`（恢复链路）语义必须区分 |
| **workspaceIdentity vs workspacePath** | 前者用于身份隔离（去重/绑定/缓存/队列/持久化/请求关联，key 统一 `workspaceIdentity?.trim() \|\| workspacePath`），后者用于文件操作、命令 cwd、Git、路径展示 |
