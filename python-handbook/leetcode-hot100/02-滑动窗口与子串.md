## 3. 无重复字符的最长子串

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/longest-substring-without-repeating-characters/) ｜ 标签：哈希表 · 字符串 · 滑动窗口

### ① 题意速览
在字符串 s 中找**不含重复字符**的最长连续子串，返回其长度。
- 示例：`"abcabcbb"` → `3`（`"abc"`）；`"bbbbb"` → `1`；`"pwwkew"` → `3`（`"wke"`，子串必须连续，`"pwke"` 是子序列不算）
- 关键约束：s 由英文字母、数字、符号和空格组成；只求长度。

### ② 思路讲解
**从暴力出发**：枚举每个起点 l，向右扫到第一个重复字符为止，得到以 l 开头的最长无重复子串——O(n²)；再笨一点对所有子串逐一判重就是 O(n³)。

**慢在哪**：每换一个起点就从零重扫。其实相邻起点的扫描区间高度重叠：`[l, r]` 无重复 ⇒ `[l+1, r]` 必无重复（去掉一个字符不会引入重复）——**右边界对递增的 l 是不降的**，上一轮的 r 信息被白白扔掉。

**滑动窗口**：右指针 r 一路扩张，一旦新字符 ch 在窗口内已出现过，左指针 l 就收缩、逐个删掉窗口左端字符，直到把那个旧的 ch 删出窗口。任意时刻 `[l, r]` 就是"以 r 结尾的最长无重复子串"，答案取所有 r 的最大值。每个字符至多进出窗口各一次，O(n²) → **O(n)**。

**再进一步（左指针跳跃）**：逐格收缩还能换成"直接跳"。哈希表改记 `last[ch]` = ch 最后一次出现的下标：r 扫到 ch 时，若 `last[ch] >= l`（上次出现落在窗口内）说明撞车，l 直接跳到 `last[ch] + 1`，省掉一格格删的过程。

**不变量（Invariant，循环每一步都保持为真的性质）**：处理完 r 时，窗口 `[l, r]` 内无重复字符，且它是"以 r 结尾"的最长无重复子串（l 再靠左必有重复，再靠右则丢字符）。有了它，`r - l + 1` 就是当前候选答案。

**套路迁移**：这是可变长窗口"求最长"的模板——**扩张到即将违约，违约时收缩修复，窗口合法时记录答案**。同家族：LC 209 长度最小的子数组（把"无重复"换成"和 ≥ target"）、LC 904 水果成篮（至多两种字符）、以及本文件的 438（定长版）与 76（覆盖版）。

### ③ 注释代码
```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}   # 字符 -> 最后一次出现的下标
        l = 0       # 窗口左端
        best = 0
        for r, ch in enumerate(s):
            # 不变量：进入本轮前，窗口 [l, r-1] 内无重复字符
            if ch in last and last[ch] >= l:
                l = last[ch] + 1  # ch 上次出现在窗口内 -> l 跳到它右边（等价于收缩到位）
            last[ch] = r          # 更新 ch 的最后出现位置；窗口外的过期记录留着不碍事
            best = max(best, r - l + 1)  # [l, r] 即以 r 结尾的最长无重复子串
        return best
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：r 扫一遍、l 只跳不退；**空间 O(min(n, |Σ|))**：哈希表至多存字符集大小 |Σ| 个记录。
- **易错点**：
  1. 跳跃条件必须是 `last[ch] >= l`：上次出现位置可能已在**窗口外**（过期），此时 l 若后退会把重复字符放回窗口（如 `"abba"` 扫到末尾的 a）；
  2. 逐格收缩版里，while 删除的是窗口左端滑出的字符，别把 r 刚指的 ch 也删了；
  3. 空串要返回 0。
- **面试追问**：
  1. 要**输出子串本身**？→ 在 best 更新时记下当时的 l，最后返回 `s[start:start+best]`；
  2. 字符集是 **Unicode**？→ dict/set 按字符处理即可，机制不变；只是"按字符集开 26 计数数组"的设计用不了（对照 438 题）。

## 438. 找到字符串中所有字母异位词

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/find-all-anagrams-in-a-string/) ｜ 标签：哈希表 · 字符串 · 滑动窗口

### ① 题意速览
给定 s 和 p，找出 s 中所有"p 的异位词（Anagram，字母重排）"子串的**起始下标**。
- 示例：`s = "cbaebabacd"`，`p = "abc"` → `[0, 6]`（`"cba"` 与 `"bac"`）；`s = "abab"`，`p = "ab"` → `[0, 1, 2]`
- 关键约束：s、p 只含小写字母；`len(p) <= len(s)`；输出顺序任意。

### ② 思路讲解
**从暴力出发**：对 s 的每个长度为 m = len(p) 的窗口，统计 26 字符计数与 p 的计数比对（O(n·26)），或排序后比对（O(n·m log m)）。窗口在滑，计数却每次**全量重算**——相邻窗口只差"进一个字符、出一个字符"。

**定长滑动窗口**：窗口长度恒为 m，右端进字符 +1、左端出字符 −1，计数**增量维护**，每步 O(1)。剩下的问题是：怎么判断"窗口计数 == p 计数"？

**valid 优化**：逐项比对两个 26 数组每步要 O(26)。引入 valid = "**已满足需求的字符种数**"（win[c] == need[c] 的 c 的个数，只统计 p 里出现过的字符）：进/出窗每次只动一个字符，valid 随之增量更新——该字符**恰好凑齐**时 +1，**由齐变溢出或由齐变缺**时 −1。窗口合法 ⇔ `valid == p 的字符种数`，判断降到 O(1)。

**不变量**：窗口长度恒为 m（先出窗再判断）；win 恰为窗口 `[l, r]` 的 26 计数；valid 恰为满足需求的字符种数。p 里没有的"杂质字符"进窗**不动 valid**——它挤占 m 个名额，必然压得某个需求字符不够，valid 到不了目标值，天然不会误报。

**套路迁移**：定长窗口模板——**进出各一、增量维护、长度够了才判断**。同家族：LC 567 字符串的排列（本题的存在性版，找到一个即返回 true）、239 滑动窗口最大值（定长窗口 + 最值统计）、LC 30 串联所有单词（把"字符"换成"定长单词"）。与 49 字母异位词分组同属异位词家族，但分工不同：49 把整串压成"指纹"当哈希 key 做分组，本题让窗口实时长成 p 的指纹去逐位比对。

### ③ 注释代码
```python
class Solution:
    def findAnagrams(self, s: str, p: str) -> List[int]:
        n, m = len(s), len(p)
        if m > n:
            return []
        need = [0] * 26            # p 的字符需求
        win = [0] * 26             # 当前窗口的字符计数
        for ch in p:
            need[ord(ch) - 97] += 1
        kinds = sum(1 for x in need if x)  # p 的字符种数（valid 的目标值）
        valid = 0                  # 已满足需求（win[c] == need[c]）的字符种数
        ans = []
        l = 0
        for r, ch in enumerate(s):
            i = ord(ch) - 97
            win[i] += 1                          # 右端进窗
            if need[i] > 0:
                if win[i] == need[i]:
                    valid += 1                   # 缺 -> 恰好齐
                elif win[i] == need[i] + 1:
                    valid -= 1                   # 恰好齐 -> 溢出
            if r - l + 1 > m:                    # 超长：先出窗，保持定长 m
                j = ord(s[l]) - 97
                l += 1
                if need[j] > 0:
                    if win[j] == need[j]:
                        valid -= 1               # 恰好齐 -> 缺
                    elif win[j] == need[j] + 1:
                        valid += 1               # 溢出 -> 恰好齐
                win[j] -= 1
            # 不变量：win 恰为窗口 [l, r] 的计数；valid 恰为满足需求的字符种数
            if r - l + 1 == m and valid == kinds:
                ans.append(l)                    # 窗口 26 项计数与 p 完全一致
        return ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n + m)**：每个字符进出窗各一次，计数与 valid 均为 O(1) 增量；**空间 O(1)**：两个 26 数组。
- **易错点**：
  1. valid 的增减分支按**变化后的计数**判断（新值 == need 是"由缺转齐"、== need+1 是"由齐转溢"）；若改成"先判断后增减"，所有分支方向要整体反过来——两种顺序只能选一种，混用必错；
  2. 判断答案前必须先把窗口**缩回长度 m**（先出窗后判断），顺序反了会把 m+1 长的窗口误判；
  3. 杂质字符进窗只参与"超长出窗"，别去动 valid。
- **面试追问**：
  1. 只需判断**是否存在**一个异位词（LC 567 字符串的排列）？→ 同一套代码，首次 `valid == kinds` 即返回 True；
  2. p 含大写或 **Unicode** 字符？→ 26 数组换 dict/Counter，valid 的目标值取 len(need)，机制不变。

## 560. 和为 K 的子数组

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/subarray-sum-equals-k/) ｜ 标签：数组 · 哈希表 · 前缀和

### ① 题意速览
求整数数组中"元素和恰好等于 k"的**连续子数组**的**个数**。
- 示例：`nums = [1,1,1]`，`k = 2` → `2`（两个 [1,1]）；`nums = [1,2,3]`，`k = 3` → `2`（[1,2] 与 [3]）
- 关键约束：元素可为**负数和 0**；求个数，不是最长/最短。

### ② 思路讲解
**先问滑动窗口行不行**：窗口题的前提是单调性——扩窗和变大、缩窗和变小，指针才知道往哪动。数组一旦有负数甚至 0，窗口和随长度不再单调，指针进退失据。**这就是本题归入「子串」专题却不用窗口的原因**（对比全正数的 LC 209，那才是窗口的主场）。

**前缀和（Prefix Sum）转化**：记 `prefix[i] = nums[0..i-1] 之和`（约定 prefix[0] = 0），则子数组 `[j, i-1]` 的和 = `prefix[i] - prefix[j]`。"和为 k" ⇔ **`prefix[j] = prefix[i] - k`**。用前缀和数组枚举全部 (j, i) 数对是 O(n²)，瓶颈在"对每个 i，数有几个 j 满足条件"还要扫一遍。

**又是两数之和**：把上句读出来——"对当前值 prefix[i]，数一数**之前**有几个数等于 `prefix[i] - k`"。与第 1 题两数之和同构，只是把"值的补数"换成了"**前缀和的补数**"。于是哈希表登场：一边扫一边维护"**每个前缀和出现的次数**"，对每个 i 先查 `prefix[i] - k` 出现几次、累加进答案，再把 prefix[i] 存入表。

**两条顺序纪律**：
1. **先查后存**：查的是 j < i 的旧前缀和，必须先查再存当前 prefix[i]——否则 k = 0 时当前前缀和会和自己配对，把"空子数组"算进答案；
2. **预存 `{0: 1}`**：prefix[0] = 0 是"空前缀"，对应所有"从下标 0 开始"的子数组——不预存，`prefix[i] == k` 的前缀段全会漏掉。

**不变量**：处理完下标 i 时，哈希表恰是 `prefix[0..i]` 各前缀和的出现次数，且对 prefix[i] 的查询发生在它入表之前（保证 j < i）。O(n²) → **O(n)**。

**套路迁移**："前缀和 + 哈希"是区间计数题的万能起手式：LC 523 连续的子数组和（改存前缀和**首次出现下标** + 同余判定）、LC 974 和可被 K 整除的子数组（prefix mod K 当 key）、LC 1248 统计优美子数组（把"奇数个数"当前缀和）。口诀：**把区间条件列成等式，等式另一头的那个量就进哈希表**。

### ③ 注释代码
```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        cnt = {0: 1}  # 前缀和 -> 出现次数；预存 prefix[0]=0，覆盖"从下标 0 开始"的子数组
        prefix = 0    # 当前前缀和
        ans = 0
        for x in nums:
            prefix += x
            # 不变量：此刻 cnt 恰为 prefix[0..i-1] 的出现次数（当前 prefix 尚未入表）
            ans += cnt.get(prefix - k, 0)  # 有几个更早的 prefix[j] = prefix[i] - k，
                                           # 就有几个以 i 结尾、和为 k 的子数组
            cnt[prefix] = cnt.get(prefix, 0) + 1  # 先查后存，顺序不能反
        return ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描、每步一查一存；**空间 O(n)**：哈希表至多 n+1 个前缀和。
- **易错点**：
  1. 先存后查：k = 0 时 `prefix - 0` 会查到刚存入的自己，每个位置多算一个"空子数组"；
  2. 忘了预存 `{0: 1}`：所有"从下标 0 开始且和为 k"的子数组全漏；
  3. cnt 存的是**次数**不是下标——本题要"个数"，相同前缀和要累加；换成求最长（见追问 2）才存下标；
  4. 有负数时别硬套滑动窗口——单调性不成立，前缀和 + 哈希才是正解。
- **面试追问**：
  1. 数组**全为正数**？→ 可以用滑动窗口 O(1) 空间（正数保证和的单调性），但哈希前缀和解法不受限，面试能对比取舍即可；
  2. 改求"和为 k 的**最长**子数组"（LC 325）？→ 哈希改存"每个前缀和**首次出现**的下标"且不再更新，答案取 `i - first[prefix - k]` 的最大值——"计数"与"最值"是同一模子的两种馅。

## 239. 滑动窗口最大值

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/sliding-window-maximum/) ｜ 标签：队列 · 数组 · 滑动窗口 · 单调队列 · 堆（优先队列）

### ① 题意速览
数组 nums 和窗口大小 k，窗口从最左端滑到最右端、每次右移一位，返回**每个位置**窗口内的最大值。
- 示例：`nums = [1,3,-1,-3,5,3,6,7]`，`k = 3` → `[3,3,5,5,6,7]`
- 关键约束：1 ≤ k ≤ n；注意官方 Hot 100 把它归入「子串」专题——窗口滑动的对象是子数组，正是数组版的"子串"。

### ② 思路讲解
**从暴力出发**：每个窗口扫 k 个数取最大，O(n·k)，n、k 同阶时就是 O(n²)。

**慢在哪**：相邻窗口共享 k−1 个元素，最大值信息被反复重算。用堆可以缓解：（值，下标）大顶堆，取堆顶前把下标已出界的元素**懒删除**，O(n log n)——仍带 log 因子，因为"被压死"的元素还躺在堆里占地方。

**关键观察（本题的灵魂）**：窗口右移、新元素 x 进来时，窗口里所有**比 x 小的旧元素永远不可能再当最大值**——它们比 x 先出窗，值又比 x 小，"资历更老、能力更弱"。这些被 x **压死**的元素可以直接淘汰。于是维护一个从队头到队尾**值单调递减**的双端队列（Deque，两端均可进出），存**下标**：
- **队尾弹出**：x 进队前，弹出所有对应值 ≤ x 的队尾元素（被 x 压死，永无出头之日）；
- **队头出窗**：队头下标滑出窗口左界（`≤ r-k`）时弹出——它不是被压死，是到龄退休；
- 每个窗口的最大值 = 队头下标对应的值。

队列里存**下标**而不是值，是因为判断"队头是否过期"必须知道它的年龄（下标），值本身没有时间信息。

**不变量**：任何时刻，队内下标都落在当前窗口内、对应值从队头到队尾严格递减——**队头恒为窗口最大值**。每个下标至多进队一次、出队一次，总操作 ≤ 2n，均摊（Amortized，把偶发的贵操作摊到整个序列上）O(n)。

**套路迁移**：单调队列（Monotonic Queue）模板——**队尾按"压制关系"弹、队头按"出界"弹、答案看队头**。滑动窗口最小值：把递减改递增、队尾弹出方向反过来即可。同家族：LC 1438 绝对差不超过限制的最长子数组（最大、最小两个单调队列 + 可变窗口）、LC 862 和至少为 K 的最短子数组（前缀和 + 单调队列，带着 560 题的影子）。42/84 的单调栈是它的静止亲戚——同一个"被压死就淘汰"的直觉，只是不滑窗。

### ③ 注释代码
```python
from collections import deque

class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        q = deque()   # 存下标；对应值从队头到队尾严格递减，队头 = 当前窗口最大值候选
        ans = []
        for r, x in enumerate(nums):
            # 1) 队尾弹出：值 <= x 的旧元素被 x 压死，永远当不上后续窗口的最大值
            while q and nums[q[-1]] <= x:
                q.pop()
            q.append(r)
            # 2) 队头到龄退休：下标滑出窗口左界 [r-k+1, r]
            if q[0] <= r - k:
                q.popleft()
            # 不变量：队内下标均在窗口内且对应值递减 -> 队头即窗口最大值
            if r >= k - 1:            # 窗口成形（[0, k-1] 起）后每步记录一次
                ans.append(nums[q[0]])
        return ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个下标至多进出队各一次（均摊）；**空间 O(k)**：队列至多存一窗的下标。
- **易错点**：
  1. 队列存**下标**不是值——出界判断需要下标，值没有时间信息；
  2. 队尾弹出用 `<=`（相等也弹）：等值元素留新的那个活得更久，队列保持严格递减更干净；写 `<` 也正确，只是队列可能积压等值元素；
  3. 窗口成形前（r < k−1）不记录答案；
  4. 出界条件是 `q[0] <= r - k`（窗口是 [r−k+1, r]），别错写成 `<`。
- **面试追问**：
  1. **滑动窗口最小值**？→ 单调**递增**队列：队尾弹出值 ≥ x 的元素，队头即最小值，其余一行不改；
  2. 用**堆**怎么做？→（值，下标）大顶堆 + 懒删除：取堆顶时循环弹出下标出界的元素，O(n log n)——能说出它和单调队列的差距来源（被压死的元素仍留在堆里）是加分项。

## 76. 最小覆盖子串

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/minimum-window-substring/) ｜ 标签：哈希表 · 字符串 · 滑动窗口

### ① 题意速览
在 s 中找出包含 t **全部字符**（重复字符要按次数凑齐）的**最短**连续子串；不存在则返回空串。
- 示例：`s = "ADOBECODEBANC"`，`t = "ABC"` → `"BANC"`；`s = "a"`，`t = "aa"` → `""`（一个 a 凑不齐两个）
- 关键约束：大小写敏感；测试保证最短答案唯一。

### ② 思路讲解
**从暴力出发**：枚举 O(n²) 个子串，逐个比对计数判断"是否覆盖 t"，规模爆炸。瓶颈：每个子串都全量重算覆盖信息。

**两阶段滑动窗口**："覆盖" = 窗口内每个需求字符的计数 ≥ need[c]。让窗口交替做两件事：
- **右指针扩张**：一路收字符进窗，直到窗口**覆盖** t；
- **左指针收缩**：覆盖后，只要仍覆盖就继续缩——缩到**刚刚不满足**为止，左移前的窗口就是"以 r 结尾的最短覆盖子串"，记录进答案；
- 失去覆盖后右指针继续扩张，如此往复。

**为什么收缩是安全的**：右端点固定为 r 时，左端越靠右窗口越短，我们要找的就是"能覆盖的最靠右的 l"——while 循环把它精准逼到临界点上；r 继续增大只会让覆盖更容易，l 不必后退。于是**每个右端点的最优解都被枚举到**，全局最短自然在其中；两指针都只前进，步数有保障。

**valid 变量（判断覆盖的 O(1) 引擎）**：need 存 t 的需求计数，window 存窗口计数；valid = "**已满足需求的字符种数**"（window[c] ≥ need[c] 的 c 的个数，只统计 t 里出现过的字符）。**valid == len(need) ⇔ 覆盖**。进窗字符恰好凑齐时 valid +1，出窗字符由齐变缺时 valid −1，判断覆盖从"比对两张计数表 O(|Σ|)"降到 O(1)——和 438 题的 valid 是同一枚零件。

**不变量**：每当 valid == len(need)，窗口 [l, r] 覆盖 t；左收缩循环终止时，刚记录的是以 r 结尾的最短覆盖（再缩一个就不覆盖）。只把 need 里出现的字符计入统计，"杂质字符"对覆盖毫无贡献。

**套路迁移**：可变窗口"求最短"模板——**扩张到覆盖，收缩到刚不满足，在收缩循环里、移出字符之前记录答案**。对照 3 题的"求最长"（扩张后、违约前记录）：**记录时机永远贴着窗口合法的那一侧**。同家族：LC 209 长度最小的子数组（把字符覆盖换成和 ≥ target）、438 题（定长版异位词）、LC 30 串联所有单词（按词块计数的覆盖）。

### ③ 注释代码
```python
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = Counter(t)      # 需求：t 中每个字符要几个（只含 t 出现过的字符）
        window = Counter()     # 窗口内需求字符的计数（杂质字符不记，对覆盖无贡献）
        valid = 0              # 已满足需求（window[c] >= need[c]）的字符种数
        l = 0
        start, length = 0, float('inf')   # 最优覆盖子串的起点与长度
        for r, ch in enumerate(s):
            # 1) 右指针扩张
            if ch in need:
                window[ch] += 1
                if window[ch] == need[ch]:    # 恰好补齐的那一刻（再多算溢出，不加 valid）
                    valid += 1
            # 2) 覆盖了就左缩：缩到刚不满足为止
            while valid == len(need):
                # 不变量：[l, r] 覆盖 t；先记录再移出，记录的是以 r 结尾的最短覆盖
                if r - l + 1 < length:
                    start, length = l, r - l + 1
                out = s[l]
                l += 1
                if out in need:
                    if window[out] == need[out]:  # 缩掉了恰好满足的字符 -> 失去覆盖
                        valid -= 1
                    window[out] -= 1
            # 3) 未覆盖：右指针继续扩张
        return "" if length == float('inf') else s[start:start + length]
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(|s| + |t|)**：左右指针各至多走 |s| 步、每步 O(1)（valid 增量更新）；**空间 O(|Σ|)**：两张计数表至多存字符集大小。
- **易错点**：
  1. valid 的增减以**恰好** need[c] 为界（进窗 `==` 才 +1、出窗减前 `==` 才 −1），写成 `>=` 会重复累加；
  2. 记录答案要在**收缩循环内**、移出字符**之前**：放循环外只记一次，最短解会被缩过头漏掉；
  3. 收缩用 while 不是 if——覆盖窗口可能一口气缩掉好几段杂质字符；
  4. t 比 s 长（或 t 的字符 s 凑不齐）要返回 ""，用 length 仍为 inf 判断，别硬取 `s[start:start+length]`。
- **面试追问**：
  1. 为什么两指针都**不会回退**、总步数 O(|s|)？→ l 只在覆盖时右移、一旦失去覆盖不再左移（r 增大只会让覆盖更容易），r 单调右移；每个字符至多进出窗各一次——这正是滑动窗口 O(n) 的通用论证；
  2. t 含 **Unicode** 字符？→ Counter/dict 天然支持任意可哈希字符，len(need) 判覆盖，机制不变。

## 本文件术语表

| 术语 | 英文 | 释义 |
|---|---|---|
| 滑动窗口 | Sliding window | 同向双指针夹出的连续区间，右扩左缩、都不回退，把子串/子数组枚举从 O(n²) 压到 O(n) |
| 定长窗口 | Fixed-size window | 长度恒定的窗口（438、239）：进出各一个元素、统计量增量维护，长度够了才判断 |
| 前缀和 | Prefix sum | prefix[i] = 前 i 个元素之和；区间和 = 两个前缀和之差，把区间问题化成配对问题 |
| 单调队列 | Monotonic deque | 双端队列保持值单调（存下标才能判过期），队头即窗口最值；"被压死"的元素直接淘汰 |
| 覆盖 | Cover | 窗口内各字符计数 ≥ 需求（76 题），用 valid（已满足需求的字符种数）== len(need) 判定 |
| 先查后存 | Query before insert | 哈希只与"更早的元素"配对的顺序纪律（1 题、560 题同款） |
