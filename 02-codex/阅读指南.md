# OpenAI Codex 源码学习 · 阅读指南

> 生成日期：2026-09-11 ｜ 仓库：`codex/`（github.com/openai/codex）@ `818f1cc`（shallow clone）
>
> 代码版本说明：本快照是 **2026 年的 Codex CLI**——一个相当庞大的 Rust workspace（`codex-rs/` 下 100+ 个 crate），已从早期"单 crate + 旧 TS 前端"演进为 **app-server 守护进程 + 多前端 + 多智能体 + 插件/技能体系**的完整工程。不要把它当成简单的 CLI 来读，先看全局图（见 `架构拆解.md`）。

> **动手先修课**：[analysis_codex/](analysis_codex/README.md) —— 自建《Learn OpenAI Codex》10 课教材（每课中文讲解 + 注释版零依赖可运行代码 + SVG 图解 + 真实源码精读锚点，`run.bat` 一键全跑）：回合循环 → rollout 录制 → 工具总闸 → 审批×沙箱双轴 → 升级重试 → MCP 双向 → apply_patch → 多智能体 → app-server → 多前端收官。Codex 本体是 Rust 而本机无 cargo，mini 实现全用 Python 纯标准库（注释标注 Rust 概念对应物）。建议先跑通 mini 版建立体感再回真源码。

## 1. 项目定位

- OpenAI 官方开源的**本地 coding agent**（CLI / IDE / 桌面 App / SDK 多形态；云端版 Codex Web 不开源）。
- 许可：Apache-2.0（见 `LICENSE`，另有 `NOTICE`）；大量 10 万级 star（GitHub 上最受关注的 agent 项目之一）。
- 安装：官方安装脚本 / `npm install -g @openai/codex` / `brew install --cask codex`（README.md 有各平台细节）；登录支持 ChatGPT 账号或 API key。

## 4. 推荐阅读路线

**第 1 阶段：主循环（1~2 天）**

1. `codex-rs/protocol/src/protocol.rs` 第 992 行起：`AskForApproval`、`SandboxPolicy`、`NetworkAccess` 枚举——先建立"权限/沙箱"两轴的世界观。
2. `codex-rs/core/src/session/turn.rs`：`run_turn`（第 163 行）→ 第 423 行 `loop {}`（回合内的采样-工具循环）→ `run_sampling_request`（第 1537 行）。
3. `codex-rs/core/src/tools/registry.rs`：`ToolRegistry`、`CoreToolRuntime`（工具运行时契约）。
4. `codex-rs/core/src/tools/orchestrator.rs`：文件头注释直接写明职责——"approval → select sandbox → attempt → retry with escalated sandbox on denial"（权限 → 选沙箱 → 执行 → 拒绝后升级重试）。

**第 2 阶段：工具与安全**

5. `core/src/tools/handlers/` 浏览全部内置工具：`apply_patch.rs`、`unified_exec.rs`、`plan.rs`、`request_user_input.rs`、`new_context_window.rs`、`tool_search.rs`、`view_image.rs`、`multi_agents.rs`、`mcp.rs`、`request_permissions.rs`、`sleep.rs` 等。
6. `apply-patch/src/parser.rs` + `file_update.rs`：补丁格式与"模糊定位"（`seek_sequence.rs`）原理。
7. `sandboxing/src/{lib.rs,manager.rs,seatbelt.rs,landlock.rs}` + `linux-sandbox/`、`windows-sandbox-rs/`：平台沙箱落地。
8. `execpolicy/`：命令策略规则。

**第 3 阶段：上下文与记忆**

9. `core/src/compact.rs` 及 `compact_remote_v2*.rs`：压缩策略（本地/远程、pre-sampling/auto）。
10. `core/src/context_manager/`、`core/src/session/context_window.rs`、`token_budget.rs`：上下文窗口治理。
11. `core/src/agents_md.rs`：AGENTS.md 记忆注入；`codex-rs/memories/`。

**第 4 阶段：架构全貌与扩展**

12. `app-server/` + `app-server-protocol/`：守护进程与 v2 RPC（TUI 只是客户端）。
13. `core/src/session/mcp_runtime.rs`、`mcp_refresh.rs`：MCP 运行期管理。
14. `core/src/hook_runtime.rs`：Pre/PostToolUse、Pre/PostCompact、turn stop/interrupt 各生命周期钩子。
15. `core/src/agent/`（registry/roles/control）+ `tools/handlers/multi_agents_v2.rs`：多智能体。
16. `core/src/plugins`、`codex-rs/skills/`、`plugin/`：插件与技能。

## 5. 本地构建与运行

- 常规安装：见 `README.md`（安装脚本 / npm / brew / GitHub Releases 平台包）。
- 源码构建（需要 Rust 工具链）：仓库根有 `justfile`（可 `just --list` 查看任务）；workspace 在 `codex-rs/`，CLI 二进制名为 `codex`（`codex-rs/cli/Cargo.toml` 的 `[[bin]]`）。典型方式：
  ```sh
  cd codex-rs
  cargo build -p codex-cli        # 产物 target/debug/codex
  cargo run  -p codex-cli --bin codex -- --help
  ```
  （本仓库快照未实际执行构建；以 `justfile`/CI 的实际任务为准。注：完整构建对 Rust 版本与平台依赖要求较高。）
- 运行形态：`codex`（TUI）、`codex exec`（非交互，见 `docs/exec.md`）、`codex app`（桌面 App，README 第 7 行）、IDE 插件、以及通过 SDK（`sdk/typescript`、`sdk/python`）作为库调用。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| **turn / step** | 回合与步骤：`run_turn` 处理一次用户输入，内部按 step 推进（见 `core/src/session/turn.rs`、`step_context.rs`） |
| **AskForApproval** | 审批策略枚举：`untrusted`（除非明确策略否则都问）、`on-request`（默认，模型自主决定何时问）、`granular`（细粒度开关：shell/规则/skill/权限请求/MCP elicitation）、`never`（从不问） |
| **SandboxPolicy** | 沙箱策略枚举：`read-only`、`workspace-write`（额外可写根 + 网络开关 + tmp 控制）、`danger-full-access`、`external-sandbox`；配套 `WritableRoot` 保护 `.codex`、`.git/hooks` 等提权敏感路径 |
| **NetworkAccess** | 网络访问开关（Restricted/Enabled），由 `network-proxy` 等强制 |
| **execpolicy** | 命令执行策略：规则式允许/拒绝/询问（crate `execpolicy`） |
| **unified_exec** | 统一命令执行工具（handler `unified_exec.rs`），取代早期裸 shell 工具 |
| **apply_patch** | 专用补丁工具，非交互式改写文件；`seek_sequence` 提供模糊上下文定位 |
| **code mode** | 把工具集以"可执行代码"形式暴露给模型（`code-mode-*` crates） |
| **app-server** | 本地守护进程，通过 RPC（v2 协议）服务 TUI/IDE/桌面/SDK 所有客户端 |
| **rollout** | 会话轨迹录制与回放（`rollout/`、`session/rollout_reconstruction.rs`） |
| **compaction（compact）** | 上下文压缩：pre-sampling / auto / remote 多形态（`core/src/compact*.rs`） |
| **multi-agent** | 多智能体：`agent-roles`、`handlers/multi_agents_v2`、`agent-graph-store`（角色、命名空间工具、通信） |
| **AGENTS.md** | 项目级给 agent 的指令文件（`core/src/agents_md*.rs`、`docs/agents_md.md`） |
| **Guardian** | 会话来源甄别与安全审查相关机制（`core/src/guardian*`，`turn.rs` 中可见） |
| **elicitation** | MCP 的"向用户征求输入"流程（`core/src/elicitation.rs`） |
| **MXC / Seatbelt / Landlock / bwrap** | 各平台沙箱后端 |

## 7. 学习提示

- 这个仓库非常大，**不要在 crate 海洋里迷路**：永远从 `core/src/session/turn.rs`（主循环）和 `protocol/src/protocol.rs`（策略枚举）两处出发向外扩展。
- 很多 markdown 文档只是跳转索引（正文在 developers.openai.com），阅读代码内的模块头注释（如 `orchestrator.rs` 开头）往往信息量更大。
- 与 Claude Code 对照阅读：两者主循环几乎同构，但 Codex 把**权限/沙箱**做成了内核级一等公民（每次工具执行都要过 orchestrator），这是它最值得抄的设计。
