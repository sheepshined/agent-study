## 2. 目录结构导览

### 2.1 `anon-kode/`（核心源码，重点）

```
src/
  entrypoints/cli.tsx    # TUI 入口（ink/React 终端 UI）
  entrypoints/mcp.ts     # MCP server 模式入口（kode mcp serve）
  query.ts               # ★ Agent 主循环（模型↔工具往返、并发/串行调度）
  Tool.ts                # Tool 接口基座（name/inputSchema/prompt）
  tools.ts               # 工具注册表（getAllTools/getTools/getReadOnlyTools）
  tools/                 # 16 个工具目录：Bash/FileRead/FileEdit/FileWrite/

                         #   Notebook*/StickerRequest
  permissions.ts         # ★ 权限判定（SAFE_COMMANDS、前缀匹配、allowedTools）
  context.ts             # 环境上下文收集（KODING.md 发现、目录结构、代码风格）
  messages.ts            # 消息结构（UserMessage/AssistantMessage/ProgressMessage）
  commands/              # 20+ 个 slash 命令（/compact /clear /model /mcp /review …）
  commands.ts            # slash 命令注册表
  services/claude.ts     # 模型调用（querySonnet/queryHaiku）

  services/mcpClient.ts  # MCP 客户端（把外部 MCP server 挂成工具）
  hooks/                 # React hooks（useCanUseTool、useSlashCommandTypeahead…）
  screens/ components/   # ink 终端界面

```

## 3. 推荐阅读路线

**第 1 阶段：先建立一个 coding agent 的完整骨架（anon-kode 源码，3 个文件）**

1. `anon-kode/src/query.ts` —— 全部核心就在这 519 行：主循环 `query()`、并发/串行工具执行、权限检查入口。读懂它，你就懂了 90% 的 agent。
2. `anon-kode/src/tools.ts` + `src/Tool.ts` —— 工具如何定义（zod schema）与注册。
3. `anon-kode/src/tools/BashTool/BashTool.tsx` —— 最有代表性的单个工具实现：zod 输入、用 Haiku 小模型生成命令描述、`PersistentShell` 执行。

**第 2 阶段：周边机制（anon-kode）**

4. `src/permissions.ts` —— SAFE_COMMANDS 白名单、命令前缀授权、allowedTools 键格式。
5. `src/context.ts` + `src/constants/prompts.ts` —— 系统提示词如何拼装环境上下文（KODING.md/目录结构/代码风格）。
6. `src/commands/compact.ts` + `src/commands.ts` —— 上下文压缩命令与 slash 命令体系。
7. `src/services/mcpClient.ts`、`src/entrypoints/mcp.ts` —— MCP 双角色（既是客户端也是服务端）。
8. `src/tools/AgentTool/AgentTool.tsx` —— 子代理：隔离消息列表里递归调用同一个 `query()`（第 84 行）。

**第 3 阶段：对照正式版 Claude Code 的取证材料**

9. `claude-code-reverse/README.zh_CN.md` —— 先懂方法（动态逆向）再看结果。
10. `claude-code-reverse/results/prompts/`、`results/tools/` —— 正式版的真实提示词与工具定义。
11. `claude-code-reverse/logs/compact.log`、`logs/sub-agent.log` —— 压缩与子代理场景的真实 API 交互。

**第 4 阶段：系统化补课（analysis_claude_code）**

12. 按顺序过 `s01_agent_loop` → `s08_context_compact`（每课先读 `README.zh.md` 再读 `code.py`），对照第 1、2 阶段的源码印象。
13. 选读进阶章节 `s09_memory` ~ `s17_goal_loop`（任务系统、后台任务、团队协作、工作流运行时等）。

**第 5 阶段：官方生态**

14. `claude-code-official/README.md` + `plugins/README.md` —— 了解插件、hooks、settings 的官方玩法。

## 4. 本地运行（anon-kode）

依赖 Node.js ≥ 18 与 pnpm。`package.json` 的 scripts（`anon-kode/package.json`）：

```sh
cd anon-kode
pnpm i
pnpm run dev      # 开发模式运行 TUI（tsx ./src/entrypoints/cli.tsx --verbose）
pnpm run build    # bun 打包为 cli.mjs
```

- 启动后走 onboarding 配置模型；`/model` 切换模型，`/config` 手动填任意 OpenAI 兼容端点（`services/openai.ts` 适配）。
- 可作为 MCP server 被 Claude Desktop 等调用：`kode mcp serve`（见 `README.md` 与 `src/entrypoints/mcp.ts`）。
- 调试日志：`NODE_ENV=development pnpm run dev --verbose --debug`。
- 注意：该快照仅供学习，勿用于生产；`BashTool` 等仍会真实执行命令。

analysis_claude_code 各课可独立运行：每课目录下有 `code.py` 与 `requirements.txt`（Python 环境，需自备模型 API key，见根目录 `.env.example`）。

## 5. 术语表

| 术语 | 含义 |
|---|---|
| **tool_use** | Anthropic API 的工具调用协议：模型返回 `type:'tool_use'` 内容块，客户端执行后以 `tool_result` 消息回填（`query.ts` 第 174 行起） |
| **Harness** | "挽具"：模型之外的一切工程——工具、知识、观察、执行接口、权限（analysis 课程的核心概念） |
| **KODING.md / CLAUDE.md** | 项目记忆文件；anon-kode 时代叫 KODING.md，正式版为 CLAUDE.md（`context.ts` 的 `getClaudeFiles()` 扫描） |
| **allowedTools** | 项目/全局配置里的工具授权表，键形如 `Bash(git status)`（`permissions.ts` 的 `getPermissionKey`） |
| **SAFE_COMMANDS** | 免确认命令白名单：`git status/diff/log/branch、pwd、tree、date、which`（`permissions.ts` 第 19 行） |
| **slash command** | `/compact`、`/model` 等斜杠命令，注册于 `src/commands.ts` |
| **subagent（AgentTool）** | 用独立消息列表运行同一 `query()` 循环的子任务机制（`tools/AgentTool/AgentTool.tsx`） |
| **ThinkTool** | 让模型"思考"但不产生副作用的空工具，用于复杂任务前的推理整理 |
| **MCP** | Model Context Protocol；anon-kode 既能挂外部 MCP server 当工具，也能把自己暴露为 MCP server |
| **compaction** | 上下文压缩：历史过长时把旧对话摘要化（正式版自动触发，anon-kode 为 `/compact` 命令） |
| **ink** | 用 React 写终端 UI 的库，anon-kode/Claude Code 的 TUI 基座 |
| **动态逆向** | claude-code-reverse 的方法：patch 掉 SDK 的 `beta.messages.create`，记录真实请求/响应来理解行为 |
