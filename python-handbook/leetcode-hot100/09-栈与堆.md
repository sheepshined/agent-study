## 20. 有效的括号

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/valid-parentheses/) ｜ 标签：栈 · 字符串

### ① 题意速览
字符串只含 `()[]{}`，判断是否有效：左括号必须用**同类型**右括号闭合、闭合顺序与嵌套正确、每个右括号都有对应的左括号。
- 示例：`()[]{}` → `true`；`([)]` → `false`；`([])` → `true`；`(` → `false`
- 关键约束：长度可为奇偶（奇数必无效，可提前否决）；输入只有这六种字符。

### ② 思路讲解
**从暴力出发**：反复把相邻配对 `()`、`[]`、`{}` 替换成空串，直到无法替换再看是否为空。正确，但一轮替换 O(n)、最坏 O(n²)。

**观察"最近未闭合"**：有效的串里，每个右括号闭合的一定是**离它最近且尚未闭合**的左括号——"最后出现的最先被闭合"，这正是后进先出的栈（Stack）天性。左括号进栈等待；右括号来了核对栈顶，配对则弹栈，不配对直接判负。

**用映射表实现配对**：建 `右括号 → 期望的左括号` 字典，右括号来时查表与栈顶比对——代码短、免写三个 if，方向统一为"右查左"最顺。

**三类失败情形（与代码一一对应）**：
1. 右括号来了但**栈空**——右括号多了（如 `")"`）；
2. 栈顶与期望不符——**交叉/类型错配**（如 `([)]`）；
3. 扫完后**栈非空**——左括号多了（如 `"((("`）。

奇数长度提前判 false：三类失败的必要条件，省一次扫描。

**不变量**：任何时刻，栈里恰好是"已出现但尚未闭合"的左括号，自底向顶与原文顺序一致；栈顶永远是最近的未闭合者。

**套路迁移**："最近配对 / 嵌套"家族的原型：394 字符串解码（嵌套展开）、71 简化路径、32 最长有效括号（栈存下标）；DFS 的函数调用栈、编辑器的撤销栈，本质同源。

### ③ 注释代码
```python
class Solution:
    def isValid(self, s: str) -> bool:
        if len(s) % 2:  # 奇数长度必有落单括号，提前否决
            return False
        pair = {')': '(', ']': '[', '}': '{'}  # 右括号 -> 期望的左括号
        stk = []
        for ch in s:
            if ch not in pair:      # 左括号：进栈等待闭合
                stk.append(ch)
            else:
                # 不变量：栈里恰是"已出现但未闭合"的左括号，栈顶是最近的那个
                if not stk or stk[-1] != pair[ch]:
                    return False    # 失败①栈空（多右）；失败②不匹配（错配）
                stk.pop()           # 配对成功，闭合最近的左括号
        return not stk              # 失败③扫完栈非空（多左）
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(n)**：最坏全是左括号。
- **易错点**：
  1. 弹栈前忘判栈空（用例 `"]"`）→ IndexError；
  2. 结尾忘 `not stk`（用例 `"((("`）→ 误判有效；
  3. 映射键方向写反（左查右）：遇左括号查表落空，逻辑拧巴——统一"右括号查期望左括号"；
  4. 弹栈判断用 `or` 短路：先 `not stk` 再比对栈顶，顺序不能反。
- **面试追问**：
  1. 串里**混入其他字符**怎么办？→ 判 `ch in '([{'` 决定进栈、`ch in pair` 决定配对，其余字符跳过；
  2. 求**最长有效括号子串**（LC 32）？→ 栈存下标、底垫 -1 做基准，配对成功用"当前下标 − 新栈顶"更新答案。

## 155. 最小栈

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/min-stack/) ｜ 标签：栈 · 设计

### ① 题意速览
设计一个栈，支持 `push`/`pop`/`top`，并能在 O(1) 时间内取**当前栈内最小值** `getMin`。
- 示例：`push(-2), push(0), push(-3)` 后 `getMin()` → `-3`；`pop()` 后 `top()` → `0`、`getMin()` → `-2`
- 关键约束：四个操作都要 O(1)；设计题，实现 `MinStack` 类而非 `class Solution`。

### ② 思路讲解
**朴素方案的死穴**：栈 + 一个"当前最小值"变量。push 时更新很容易，但 **pop 弹掉的可能正是最小值**——上一个最小值是多少？无从得知，O(1) 恢复做不到。

**观察**：每个元素入栈的那一刻，"栈内最小值"是确定的。把它**跟着元素一起记住**，pop 时一起带走，恢复就自动发生——这就是"每个前缀各自记账"。

**辅助栈**：主栈正常存元素；辅助栈与主栈**同步**压入"压入该元素后栈内的最小值"（= min(新元素, 辅助栈顶)，空栈时就是新元素本身）。两栈高度永远相同：`getMin` 看辅助栈顶即可，`pop` 时两栈同弹、最小值自动回滚。

**不变量**：`min_stk[i] = min(stk[0..i])`——辅助栈每个位置记录主栈对应前缀的最小值；因此任意时刻栈内最小值 = 辅助栈顶。

**追问（省空间变体，面试常问）**：辅助栈只压"打破纪录"的元素（`val <= 辅助栈顶` 才压），pop 时两栈顶相等才同弹——空间从 O(n) 降到"最小值变化次数"；更极致的是**单栈存差值**：压 `val - cur_min`，差值为负说明刚刷新最小值，pop 出负数可还原旧最小值。面试能讲出权衡（同步版简单稳、差值版省空间）即可。

**套路迁移**："每个前缀维护一个信息、随元素同步进退"的思想，与 01 文件的前缀和一脉相承；同家族：最大栈、含 getMin 的队列（LC 155 变体、LC 232 用栈实现队列的反向题）。

### ③ 注释代码
```python
class MinStack:
    def __init__(self):
        self.stk = []      # 主栈：正常存元素
        self.min_stk = []  # 辅助栈：min_stk[i] = min(stk[0..i])

    def push(self, val: int) -> None:
        self.stk.append(val)
        # 新最小值 = min(新元素, 之前的最小值)；空栈时就是 val 本身
        cur = val if not self.min_stk else min(val, self.min_stk[-1])
        self.min_stk.append(cur)

    def pop(self) -> None:
        self.stk.pop()
        self.min_stk.pop()  # 两栈同步弹出，最小值自动"回滚"到上一个

    def top(self) -> int:
        return self.stk[-1]

    def getMin(self) -> int:
        # 不变量：辅助栈顶 = 主栈全体元素的最小值
        return self.min_stk[-1]
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间**：四个操作全 O(1)；**空间 O(n)**：辅助栈与主栈等高。
- **易错点**：
  1. 用"全局最小值变量"代替同步栈——pop 掉当前最小后无法回滚，本题核心陷阱；
  2. "只在更小时压"的省空间版：入栈条件必须 `val <= 辅助栈顶`（取等），弹栈条件"两栈顶相等才同弹"——漏了取等，重复最小值时错；
  3. `push` 里 min 的判断要先处理空栈，否则对空栈顶取值越界。
- **面试追问**：
  1. **单栈存差值**怎么写？→ 压 `val - cur_min`，为负则更新 `cur_min = val`；pop 出负数则 `cur_min -= 差值` 还原旧最小值——每操作 O(1)、空间与最小值变化次数相关；
  2. 还要支持 `getMax`？→ 再配一个 max_stk，同套路双栈记账。

## 394. 字符串解码

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/decode-string/) ｜ 标签：栈 · 递归 · 字符串

### ① 题意速览
编码串中 `k[...]` 表示方括号内的内容重复 k 次，且可嵌套，解码还原成原串。
- 示例：`3[a]2[bc]` → `"aaabcbc"`；`3[a2[c]]` → `"accaccacc"`；`2[abc]3[cd]ef` → `"abcabccdcdcdef"`
- 关键约束：k 为正整数（可多位）；输入保证合法（括号配对）；嵌套可任意深。

### ② 思路讲解
**从朴素出发**：递归解析——遇到 `k[` 就递归解码括号内子串再重复。可行，但"多位数字 + 配对位置"的边界繁琐，嵌套极深还有递归栈风险。

**栈的视角**：嵌套结构 = "最内层先完成"。遇到 `]` 时需要知道：本层重复次数 k、本层已累积内容、以及**外层进行到一半的字符串**——后进先出，栈应声而出。

**双栈方案，一遍扫描**：数字栈 num_stk、字符串栈 str_stk，外加"当前层"的两个工作变量 cur_num、cur_str——
- 遇**数字**：`cur_num = cur_num * 10 + int(ch)` 累积多位数；
- 遇 **`[`**：把 cur_num、cur_str 压栈（保存外层现场），重置两者，进入新一层；
- 遇**字母**：`cur_str += ch`（当前层在累积）；
- 遇 **`]`**：弹出 k、prev，`cur_str = prev + cur_str * k`——本层完成，拼回外层尾部。

**为什么嵌套天然成立**：每层 `[` 保存的现场是"外层截至此处"的全部状态（次数 + 前缀），`]` 恢复现场并续接——递归需要保存的一切都被显式压进栈里，**栈就是显式化的递归**；`]` 总是与最近的 `[` 配对，深度嵌套时栈深恰为嵌套深度，信息按"由内向外"的顺序逐层恢复，天然正确。

**不变量**：任何时刻 cur_str 是"最内层未闭合部分"的累积结果；栈里自底向顶依次是各外层现场（重复次数 + 已累积前缀）。

**套路迁移**："递归 ↔ 栈互化"原型：71 简化路径、726 原子数量、224 基本计算器。凡是"配对符号中间嵌内容"的解析题，都可套这个双栈骨架。

### ③ 注释代码
```python
class Solution:
    def decodeString(self, s: str) -> str:
        num_stk, str_stk = [], []   # 重复次数栈 / 外层字符串现场栈
        cur_num, cur_str = 0, ""    # 当前层的重复次数与已累积内容
        for ch in s:
            if ch.isdigit():
                cur_num = cur_num * 10 + int(ch)  # 多位数：如 "12"
            elif ch == '[':
                # 不变量：压栈保存外层现场，随后进入新一层
                num_stk.append(cur_num)
                str_stk.append(cur_str)
                cur_num, cur_str = 0, ""          # 现场重置
            elif ch == ']':
                k = num_stk.pop()                 # 本层重复次数（最近的 [ 配对）
                prev = str_stk.pop()              # 外层已累积前缀
                cur_str = prev + cur_str * k      # 本层展开，拼回外层尾部
            else:
                cur_str += ch                     # 普通字母累积到当前层
        return cur_str
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(输出长度)**：解码结果可能远长于输入（如 `2[2[2[a]]]` 每层翻倍，指数于嵌套深度），遍历与拼接的代价以输出为主项；**空间 O(输出长度 + 嵌套深度)**。
- **易错点**：
  1. 多位数只取一位（`"12[a]"` 解成 2 次）——必须 `cur_num * 10 + int(ch)` 累积；
  2. 遇 `[` 忘重置 cur_num/cur_str：内层带上外层的次数与前缀；
  3. `]` 拼接方向写反（`cur_str * k + prev`）：外层前缀必须在前面；
  4. 题目保证输入合法（配对、k 为正），无需防御非法输入——面试口述时点明这个假设。
- **面试追问**：
  1. **递归版**怎么写？→ 全局下标 i 扫描，遇 `[` 递归解析到配对的 `]` 返回子串——与栈版同构，说清"栈 = 显式递归"即是加分；
  2. 嵌套十万层会怎样？→ 递归版有爆栈风险，显式栈只受内存限制——这正是"递归化栈"的工程意义。

## 739. 每日温度

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/daily-temperatures/) ｜ 标签：栈 · 数组 · 单调栈

### ① 题意速览
每天的温度列表，对每一天求"还要**等几天**才有更高温度"；等不到则记 0。
- 示例：`[73,74,75,71,69,72,76,73]` → `[1,1,4,2,1,1,0,0]`
- 关键约束：n 可达 10⁵——O(n²) 的逐日向右扫描会超时。

### ② 思路讲解
**从暴力出发**：每天向右扫到第一个更高温度，O(n²)。慢在大量重复比较：被扫过的日子其实早该有答案。

**单调栈（Monotonic Stack）**：维护一个**下标栈，栈内温度自底向顶严格递减**。新一天 i 到来：
- 只要栈顶温度 < temperatures[i]，说明 i 就是栈顶那天"等来的第一个更热天"，**弹栈结算**：`ans[栈顶下标] = i - 栈顶下标`；
- 循环弹完后 i 自己进栈（它也还在等更热的天）。

**为什么正确且 O(n)**：栈的递减性保证弹出的都是"比 i 冷且还没被认领"的日子，而 i 是它们右侧第一个更高温——距离自然最近；每个下标恰好**进栈一次、出栈一次**，总操作 ≤ 2n，均摊 O(n)。这把"我向右找"反转成"被更热天认领"，是单调栈的核心视角转换。

**不变量**：栈内下标对应的温度严格递减；所有已弹出的下标答案已确定，栈里的都在"等一个更热的天"。

**套路迁移**：单调栈入门题，记住九字口诀"**存下标、比栈顶、弹出结算**"。同族：496 下一个更大元素 I、503 循环数组下一个更大、901 股票价格跨度、84/42（横向结算版单调栈）。

### ③ 注释代码
```python
class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        n = len(temperatures)
        ans = [0] * n            # 初值 0：栈里剩下的"永远等不到"天然覆盖
        stk = []                 # 存下标：栈内温度自底向顶严格递减
        for i, t in enumerate(temperatures):
            # 不变量：栈里是"还没等到更热天"的下标，温度递减
            while stk and temperatures[stk[-1]] < t:
                j = stk.pop()
                ans[j] = i - j   # i 是 j 右侧第一个更热天，弹出即结算
            stk.append(i)        # 自己进栈，继续等更热的天
        return ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个下标进出栈各一次；**空间 O(n)**：栈最坏存满递减序列。
- **易错点**：
  1. 栈里存**下标**不是温度——结算要算下标差；
  2. 弹栈条件写成 `<=`：等温不算"更高"，只有严格更高才弹出；
  3. 用 `if` 代替 `while`：一天高温可能同时结算一串更冷的日子；
  4. ans 初值用 -1：栈里剩余的日子答案是 0，不是 -1。
- **面试追问**：
  1. 在线**股票价格跨度**（LC 901）？→ 同款递减栈但存 (价格, 跨度) 压缩弹出的连续段，跨度累加；
  2. **循环数组**找下一个更大元素（LC 503）？→ 遍历 2n−1 遍、下标取模，只让第一圈下标入栈防重复结算。

## 84. 柱状图中最大的矩形

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/largest-rectangle-in-histogram/) ｜ 标签：栈 · 数组 · 单调栈

### ① 题意速览
柱状图各柱宽 1、高 `heights[i]`，选一段连续柱子构成矩形（矩形高 = 该段**最矮**柱的高），求能得到的最大面积。
- 示例：`[2,1,5,6,2,3]` → `10`（下标 2~3 的柱 5、6：min = 5 × 宽 2）
- 关键约束：n 可达 10⁵；高度可为 0；单根柱也构成矩形。

### ② 思路讲解
**从暴力出发**：枚举左右端点再求段内最小值 O(n³)；预处理区间最小值降到 O(n²)——n = 10⁵ 仍然超时。瓶颈：每个区间都在重复求"最矮柱"。

**换视角——以每根柱为高，能撑多宽**：答案矩形的高一定是**某根柱**的高度。对柱 i，以它为高能撑的最大宽度 = 从 i 向左右各伸到"**第一根比它矮的柱**"为止（不含）。于是答案 = max(h[i] × 宽[i])，问题变成对每根柱求"左右第一根更矮柱"——两个方向都是 739 题同款信号，单调栈的主场。

**单遍写法（递增栈 + 哨兵）**：维护**下标栈，栈内高度严格递增**。遇到比栈顶矮的柱 i 时，栈顶柱的右边界就是 i（第一根更矮者出现），左边界是弹出后的新栈顶（它左侧更近的更矮者），于是立即结算：

> 以弹出柱为高的最大矩形 = h[弹出柱] × (i − 新栈顶 − 1)

两个边界都是更矮的柱，"−1"正是剔掉这两根**不含**的边界柱后的净宽。为什么弹出时结算即终局：一根柱的最大矩形被左右第一根更矮柱唯一夹定，此刻两侧信息恰好凑齐；不漏（哨兵保证最后全部弹出结算）、不重（每根柱只弹一次）。

**哨兵（Sentinel，首尾垫的虚拟柱）**：首尾各垫一根高 0 的柱。尾哨兵逼着所有真柱在扫描结束时全部弹出结算，省掉"扫完再清栈"的收尾代码；首哨兵垫底保证栈永不弹空，宽度公式对"一路伸到最左"的柱也自洽（此时新栈顶是哨兵 0，宽 = i − 1，恰是前缀全更高的净宽）。

**不变量**：栈内高度严格递增；栈中任何一根柱，其左右更近的更矮柱都尚未出现（否则早被弹出结算了）。

**与 42 接雨水对照（同族单调栈，结算方向相反）**：42 维护**递减栈**、按"横向水层"结算（栈顶是坑底，左右是两堵墙，高 = min(两墙) − 坑底、宽 = 右墙 − 左墙 − 1）；84 维护**递增栈**、按"以柱为高的矩形"结算。单调栈的通用心法：**想清楚哪个元素在什么时刻凑齐完整信息、凑齐后结算什么**。

**套路迁移**：85 最大矩形（二维版：逐行累计"向上连续 1 的高度"，每行跑一遍本题）；907 子数组最小值之和（贡献法 + 单调栈）；凡"第一个比它小/大的位置"类问题皆此族。

### ③ 注释代码
```python
class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        # 首尾各垫一根高 0 的哨兵柱：任何真柱右侧终会遇到"更矮者"，
        # 扫描结束时全部真柱都会被触发弹出结算，无需额外收尾
        h = [0] + heights + [0]
        stk = [0]  # 存下标：栈内高度严格递增，首哨兵垫底保证栈永不弹空
        best = 0
        for i in range(1, len(h)):
            # 不变量：栈内下标对应高度严格递增
            while h[i] < h[stk[-1]]:     # i 是栈顶柱右侧第一根更矮柱
                height = h[stk.pop()]    # 弹出柱：此刻左右边界凑齐，立即结算
                width = i - stk[-1] - 1  # 左边界=新栈顶（不含），右边界=i（不含）
                best = max(best, height * width)
            stk.append(i)
        return best
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每根柱进出栈各一次；**空间 O(n)**：栈最坏存满递增柱。
- **易错点**：
  1. 宽度公式 `i - 新栈顶 - 1`：两个减 1 语义不同——右边界 i 不含、左边界新栈顶不含；先 pop 再读新栈顶，顺序反了宽度就错；
  2. 忘加尾哨兵：扫描结束栈里还压着一串递增柱没结算，答案偏小；
  3. 等高柱用严格 `<` 不弹出**并不漏算**——前一根等高柱稍后会以更宽的矩形补上；改成 `<=` 弹出也对，但两套写法别混用；
  4. 高度为 0 的柱照常入栈即可，哨兵逻辑天然覆盖。
- **面试追问**：
  1. **二维** 0/1 矩阵的最大矩形（LC 85）？→ 逐行累计"向上连续 1 的高度"当作 heights，每行跑一遍本题，O(m·n)；
  2. 与 42 接雨水同族在哪、异在哪？→ 同是单调栈，42 用递减栈结算横向水层、84 用递增栈结算"以柱为高的矩形"——结算方向相反。

## 215. 数组中的第K个最大元素

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/kth-largest-element-in-an-array/) ｜ 标签：数组 · 分治 · 快速选择 · 排序 · 堆

### ① 题意速览
无序数组里找**第 k 大**的元素（k 从 1 计），进阶要求不排序就做到 O(n)。
- 示例：`[3,2,1,5,6,4]`，`k = 2` → `5`
- 关键约束：1 <= k <= n；排序 O(n log n) 不是本题考点，要会平均 O(n) 的解法。

### ② 思路讲解
**从朴素出发**：排序后取倒数第 k 个，O(n log n)——为了一个名次把所有名次都排好了，浪费。**堆**：大小 k 的小顶堆流式维护前 k 大，O(n log k)——数据流场景最佳，但静态全量数组还有更快的。

**快速选择（Quickselect）**：快排的分区（partition）思想 + **只递归含答案的一边**。随机选枢轴，partition 后枢轴落到它的最终位置 p（左侧全 ≤ 它、右侧全 ≥ 它）：
- p == n−k（升序摆放后第 k 大的下标）：答案就是它；
- p < n−k：答案在右段，**只**处理右段；否则只处理左段。

**为什么平均 O(n)**：随机枢轴下，期望每轮把规模近似折半，n + n/2 + n/4 + … ≤ 2n。对比快排"两边都递归"是 O(n log n)，只走一边省掉一个 log 因子。最坏 O(n²)（枢轴总选最差），随机化让它概率意义上期望 O(n)，工程上足够稳。

**小顶堆 O(n log k) 何时更优**：数据是**流式**的（n 未知或全量装不下内存，只能维护 k 个）、或 k 极小（log k ≪ log n）；静态全量、k 中等偏大时快速选择占优。两条路线都要会，面试按场景选。

**不变量**：第 k 大元素（若在当前范围内）始终位于区间 `[l, r]` 内；partition 保证枢轴左侧 ≤ 枢轴 ≤ 右侧，所以每轮排除的一侧绝不含答案。

**套路迁移**："partition 后只递归一边"= 二分思想在不均匀分割上的推广；同族：求第 k 小（换个下标）、按频次快速选择（347 题备选）、面试手写 partition 是硬功夫。

### ③ 注释代码
```python
import random

class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        target = len(nums) - k  # 升序摆放后第 k 大的下标（k-1 是第 k 小，别混）

        def partition(l: int, r: int) -> int:
            """随机枢轴划分：返回枢轴最终下标，左侧 <= 枢轴 <= 右侧"""
            p = random.randint(l, r)             # 随机化：防有序/全等数据打成 O(n^2)
            nums[p], nums[r] = nums[r], nums[p]  # 枢轴换到末尾
            pivot = nums[r]
            i = l                                # i：下一个 "<= pivot" 元素应落的坑
            for j in range(l, r):
                if nums[j] <= pivot:
                    nums[i], nums[j] = nums[j], nums[i]
                    i += 1
            nums[i], nums[r] = nums[r], nums[i]  # 枢轴归位
            return i

        l, r = 0, len(nums) - 1
        while True:
            p = partition(l, r)
            if p == target:
                return nums[p]
            # 不变量：第 k 大必在含 target 的那一侧，只处理一边
            if p < target:
                l = p + 1
            else:
                r = p - 1
```
> 数据流 / 内存受限场景的堆版：`import heapq`（Python heapq 是小顶堆），元素流式进堆，超过 k 个就弹堆顶，堆顶即第 k 大，O(n log k)。

### ④ 复杂度 · 易错点 · 面试追问
- **时间平均 O(n)**（随机化后期望；最坏 O(n²)）；**空间 O(1)**：迭代版原地交换。
- **易错点**：
  1. 第 k 大的升序下标是 `n - k`，写成 `k - 1` 求的是第 k 小；
  2. 忘随机化：有序 / 全相同数据把 partition 打成一边倒，LeetCode 有针对性用例卡固定枢轴；
  3. partition 里 `j` 只扫到 `r - 1`（枢轴在 r），最后 `nums[i]` 与 `nums[r]` 交换归位——漏一步就错位；
  4. 大量重复元素时二路划分失衡，可换三路划分（< = > 各一段）。
- **面试追问**：
  1. **数据流**场景怎么办？→ 大小 k 的小顶堆 O(n log k)，内存只需 O(k)，堆顶即当前第 k 大；
  2. 为什么平均 O(n)？→ 期望每轮规模折半，n(1 + 1/2 + 1/4 + …) ≤ 2n；快排两边都递归才是 O(n log n)。

## 347. 前 K 个高频元素

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/top-k-frequent-elements/) ｜ 标签：哈希表 · 桶排序 · 计数 · 堆

### ① 题意速览
数组里找出出现次数**前 k 高**的元素，返回集合（顺序任意）。要求优于 O(n log n)，进阶要求 O(n)。
- 示例：`[1,1,1,2,2,3]`，`k = 2` → `[1,2]`；`[1]`，`k = 1` → `[1]`
- 关键约束：k 保证有解；元素个数 n 有限，频次天然 ≤ n。

### ② 思路讲解
**从朴素出发**：哈希计数 + 按频次全排序取前 k，O(n log n)。瓶颈：给**所有**不同元素排了序，其实只要前 k 个。

**堆**：大小 k 的小顶堆按频次维护，O(n log k)——k 小时已经很优，还能流式处理。

**桶排序（Bucket Sort）压到 O(n)**：频次是整数且取值只有 0 ~ n——**以"出现次数"为桶下标**分桶：`buckets[c]` = 出现次数恰为 c 的元素列表。从高频桶向低频桶**倒序收集**，凑满 k 个即停。排序被"值域做下标"直接消掉：计数一遍 O(n)、建桶一遍 O(n)、收集一遍 O(n)。

**不变量**：桶 c 内元素的出现次数都恰为 c；倒序扫桶时先收到的必然频次更高，凑满 k 个时收集到的一定是频次最高的那批。

**对比小顶堆 O(n log k)**：堆版更通用（频次范围不受限、可流式、k 可远小于不同元素数）；桶排序吃的是"频次为不超过 n 的整数"这个性质，换来线性时间。面试两个都能写，讲清适用条件最加分。

**追问海量数据（计数内存受限）**：词汇表太大、计数表装不下 → 哈希**分片**（相同元素路由到同一片）各片局部 Top K 再归并；或 Count-Min Sketch（近似频次概要结构）以可控误差换内存。

**套路迁移**："要排序的 key 值域有限且为整数 → 值域做桶下标"：41 缺失的第一个正数（值放到值对应的下标）、1051 高度检查器（计数排序）。凡是"排序 key 天然有界"，先想桶。

### ③ 注释代码
```python
class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        cnt = {}                     # 元素 -> 出现次数
        for x in nums:
            cnt[x] = cnt.get(x, 0) + 1
        n = len(nums)
        # 桶下标 = 出现次数（0..n）：频次是 <= n 的整数，值域做下标免排序
        buckets = [[] for _ in range(n + 1)]
        for x, c in cnt.items():
            buckets[c].append(x)
        # 不变量：桶 c 内元素频次恰为 c；倒序扫先收到的频次必更高
        res = []
        for c in range(n, 0, -1):    # 从高频向低频收集
            for x in buckets[c]:
                res.append(x)
                if len(res) == k:    # 凑满即停，不碰低频桶
                    return res
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：计数、建桶、收集各一遍；**空间 O(n)**：计数表 + 桶。
- **易错点**：
  1. 桶数组开 `n + 1`：频次最大是 n（所有元素相同），开 n 会 IndexError；
  2. 堆版把 `(元素, 频次)` 放元组：字典序先比元素——必须 `(频次, 元素)` 才按频次比；
  3. 收集满 k 个要立刻 return，继续收会把低频元素混进答案；
  4. 答案顺序任意，判题不比顺序——别为排序多花无谓的 O(k log k)。
- **面试追问**：
  1. 堆版一句话？→ `heapq.nlargest(k, cnt, key=cnt.get)`，或手写大小 k 的小顶堆（`import heapq`，Python heapq 是小顶堆，堆顶是当前第 k 高频次），O(n log k)；
  2. **海量数据**计数内存受限？→ 哈希分片 + 各片局部 Top K 再归并；或 Count-Min Sketch 以误差换内存。

## 295. 数据流的中位数

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/find-median-from-data-stream/) ｜ 标签：设计 · 数据流 · 堆

### ① 题意速览
设计类：`addNum` 持续灌入数据，`findMedian` 随时返回当前所有数的中位数（偶数个取中间两数平均）。
- 示例：`addNum(1), addNum(2)` 后 `findMedian()` → `1.5`；再 `addNum(3)` 后 → `2.0`
- 关键约束：进阶要求 O(log n) 插入 + O(1) 查询；数据流式、n 事先未知（最多 5×10⁴ 次调用）。

### ② 思路讲解
**从朴素出发**：每来一个数就插入有序数组（二分找位 O(log n)），但挪动元素 O(n)，整体 O(n²)；或查询前重排一次，更糟。瓶颈：中位数只依赖"中间"，我们却维护了全序。

**中位数的结构**：中位数把全体数分成**较小的左半**与**较大的右半**，两半大小差 ≤ 1。查询只需要"左半最大 + 右半最小"——动态集合随时取最值，堆的主场。

**对顶堆（Two Heaps）**：
- **大顶堆 small**：存较小的一半，堆顶 = 左半最大；
- **小顶堆 large**：存较大的一半，堆顶 = 右半最小；
- 约定 `len(small) - len(large)` ∈ {0, 1}（small 可多一个）。中位数：small 多一个 → small 堆顶；等大 → 两堆顶平均。

**插入的平衡步骤（先加一边、再搬一个，两步走）**：
1. 新数先进 small，随即把 small 的堆顶（左半最大）搬给 large——搬过去的必然 ≥ small 里剩下的所有数，"small 全部 ≤ large 全部"的序不会破；
2. 搬完若 large 比 small 多，再把 large 的堆顶（右半最小）搬回 small。

为什么必须"过一道堆顶"而不是直接比较大小选边：直接选边要处理"跟左半比、跟右半比、跟堆顶相等"多种情况，容易漏平衡；统一走"先入 small → 让最大给 large → 反超再搬回"一条路径，逻辑唯一、不变量自动成立。

**不变量**：① small 的每个元素 ≤ large 的每个元素；② 0 ≤ len(small) − len(large) ≤ 1。中位数由两堆顶唯一决定：插入 O(log n)（常数次堆操作）、查询 O(1)。Python 用 heapq：**Python heapq 是小顶堆，大顶堆用负号模拟**——压 −x、读时取反，全程别漏。

**套路迁移**：对顶堆家族：滑动窗口中位数（LC 480，加延迟删除）、任意分位数的多桶推广；"双堆配对"思想还见于会议室问题（LC 253，分别排序起止时间）。

### ③ 注释代码
```python
import heapq  # Python heapq 是小顶堆，大顶堆用负号模拟（压 -x，读时取反还原）

class MedianFinder:
    def __init__(self):
        self.small = []  # 大顶堆（负号模拟）：存较小的一半，堆顶 = 左半最大
        self.large = []  # 小顶堆：存较大的一半，堆顶 = 右半最小

    def addNum(self, num: int) -> None:
        # 平衡第一步：先给 small，再把 small 的最大者让给 large——
        # 让过去的必然 >= small 里剩下的所有数，"small 全 <= large" 不会破
        heapq.heappush(self.small, -num)
        heapq.heappush(self.large, -heapq.heappop(self.small))
        # 平衡第二步：约定 small 可多一个；若 large 反超，搬一个回来
        if len(self.large) > len(self.small):
            heapq.heappush(self.small, -heapq.heappop(self.large))

    def findMedian(self) -> float:
        # 不变量：small 全部 <= large 全部，且 0 <= len(small)-len(large) <= 1
        if len(self.small) > len(self.large):
            return float(-self.small[0])            # 左半多一个：堆顶即中位数
        return (-self.small[0] + self.large[0]) / 2  # 等大：两堆顶取平均
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间**：`addNum` O(log n)（至多三次堆操作）；`findMedian` O(1)；**空间 O(n)**：两堆合计存全部数。
- **易错点**：
  1. 大顶堆负号要贯穿全程（压、弹、读都要取反），漏一处立刻错；
  2. 平均用 `/ 2` 浮点除——`// 2` 会把 1.5 变成 1；
  3. 平衡只走"先入 small → 让最大给 large → 反超搬回"一条路径，自创"比较选边"写法容易漏平衡；
  4. 单元素时走 `len(small) > len(large)` 分支返回 `float(-small[0])`，别忘了 float 化。
- **面试追问**：
  1. **滑动窗口中位数**（LC 480）？→ 对顶堆 + 延迟删除（Lazy Deletion，出窗元素只打删除标记，堆顶失效先弹出、查中位前统一清理）；
  2. 要**任意分位数**？→ 对顶堆推广成多桶（如每 1% 一桶）近似，或用有序集合 / 跳表按名次取。
