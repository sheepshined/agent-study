## 136. 只出现一次的数字

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/single-number/) ｜ 标签：位运算 · 数组

### ① 题意速览
数组里除一个数出现**一次**外，其余每个数都出现**两次**，找出那个单只的数。
- 示例：`[4,1,2,1,2]` → `4`
- 关键约束：进阶要求 O(n) 时间、O(1) 额外空间（把哈希和排序都排除了）。

### ② 思路讲解
**从朴素出发**：哈希计数，出现一次的就是答案——O(n) 时间 O(n) 空间；排序后两两比对相邻元素——O(n log n) 时间。都对，但没到进阶要求。

**最优解：异或（XOR，按位异或）**。三条性质：
1. `a ^ a = 0`（自反：同数相消）；
2. `a ^ 0 = a`（恒等：0 是"什么都不留"的底）；
3. 交换律 + 结合律（异或结果与运算顺序无关）。

把全体数**一锅异或**：由性质 3，等价于把相同的数两两先配对消成 0（性质 1），剩下唯一的单只与 0 异或（性质 2）原样留底。三行代码、一遍流式处理，空间 O(1)。

**不变量**：处理完前 i 个数后，`acc` = `nums[0..i−1]` 中"出现奇数次的数"的异或和——本题里它始终就是那只单只（其余数都出现偶数次，被性质 1 消掉）。

复杂度对比：哈希 O(n)/O(n)；排序 O(n log n)/O(1)；异或 **O(n)/O(1)**，且写法最短。

**套路迁移**：异或消重家族：**两个**单只（LC 260）先全体异或得 `x^y`，取其 lowbit（最低位的 1）把数组分成两组、各自组内异或；其余出现**三次**（LC 137）异或不消，改按位计数模 3；丢失的数字（LC 268）= 数组与补全的下标一起异或，同款消重。

### ③ 注释代码
```python
class Solution:
    def singleNumber(self, nums: List[int]) -> int:
        acc = 0
        for x in nums:
            # 不变量：acc = nums[0..i-1] 中出现奇数次元素的异或和
            acc ^= x  # 成对者自相抵消（a^a=0），单只最终留底（a^0=a）
        return acc
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**：一个变量。
- **易错点**：
  1. `acc` 必须初始化为 0（恒等元），初始化成 1 之类会把所有结果带偏；
  2. 这招依赖"其余**恰好出现两次**"——出现三次时异或三遍等于没消（LC 137 要换按位统计）；
  3. 负数不用特判：Python 的按位异或对负数按补码语义成立，直接 `^` 即可。
- **面试追问**：
  1. 有**两个**单只（LC 260）？→ 全体异或得 `x^y`（必非 0），取其 lowbit 把数组按该位 0/1 分两组，x、y 必分居两组，组内各自异或即得；
  2. 其余出现三次（LC 137）？→ 逐位统计 1 的个数、模 3 取余，余 1 的位拼出答案。

## 169. 多数元素

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/majority-element/) ｜ 标签：数组 · 哈希表 · 分治 · 计数 · 排序

### ① 题意速览
找出数组中出现次数**超过 ⌊n/2⌋** 的元素（题目保证存在）。
- 示例：`[2,2,1,1,1,2,2]` → `2`
- 关键约束：多数元素一定存在；进阶要求 O(n) 时间、O(1) 空间。

### ② 思路讲解
**从朴素出发**：哈希计数取最大——O(n) 时间 O(n) 空间；排序后取中位 `nums[n//2]`——多数元素占一半以上，排序后中位必落在它的区间里，O(n log n) 时间 O(1) 空间（不计排序栈）。两者都达不到"一遍 + 常数空间"。

**最优解：摩尔投票（Boyer-Moore Voting，摩尔投票法）**。维护一个候选者 `candidate` 和净票数 `count`：遇到同票 +1，遇到异票 −1，`count` 归零就换当前元素当候选。物理图像是**配对抵消**：每来一个不同元素，就和当时的候选"同归于尽"一对。

**为什么配对抵消后多数必剩**：多数元素的个数 > 其余所有元素个数之和。看 `count` 的每个归零时刻——**不变量**：刚被切出的那段前缀恰好能拆成若干"两两不同"的配对，每对里多数元素至多占一个；因此被抵消的部分里多数元素不超过一半，**多数元素在剩下的后缀里依然是多数**。归纳下去，扫完时在场的候选必是多数元素（若候选不是多数元素，它在配对中早已被耗尽）。这是"以对消换统计"的经典论证。

复杂度对比：哈希 O(n)/O(n)；排序取中位 O(n log n)/O(1)；摩尔投票 **O(n)/O(1)**，一遍流式、元素只需能判等、无需可排序。

**套路迁移**：配对抵消家族：出现超过 **n/3** 次的元素（LC 229）候选至多 2 个，维护两套（候选，计数）后验证；推广到 n/k 至多 k−1 个候选。同"对消"思想的还有有效括号（栈消对）。

### ③ 注释代码
```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate = 0  # 当前候选
        count = 0      # 候选的净票数
        for x in nums:
            if count == 0:
                candidate = x  # 没有在场的候选，x 上场
                count = 1
            elif x == candidate:
                count += 1     # 同票
            else:
                count -= 1     # 异票：候选与 x 同归于尽一对
        return candidate  # 不变量保证：归零切段里多数至多一半 -> 存活者必是多数
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描；**空间 O(1)**：两个变量。
- **易错点**：
  1. 摩尔投票的前提是"多数元素**存在**"——没有这个保证时，扫完必须再数一遍候选做验证（LC 229 就要这么收尾）；
  2. `count == 0` 要立即换候选（包括最开头），别让旧候选带着"负票"苟活；
  3. `count` 是"净票数"不是"候选出现次数"，两者只在末段一致，中途语义别混。
- **面试追问**：
  1. 超过 **n/3**（LC 229）？→ 至多 2 个答案，维护两个候选、两套计数（两候选同时在场时异票才抵消），末尾各数一遍验证；
  2. 为什么排序取中位也对？→ 多数元素占据排序后长度 > n/2 的连续区间，下标 n//2 必在其中。

## 75. 颜色分类

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/sort-colors/) ｜ 标签：数组 · 双指针 · 排序

### ① 题意速览
数组元素只有 0、1、2（红白蓝），把它们**原地**排序，使相同元素相邻、按 0<1<2 排列。这就是荷兰国旗问题（Dutch National Flag，荷兰国旗问题）。
- 示例：`[2,0,2,1,1,0]` → `[0,0,1,1,2,2]`
- 关键约束：不许调库排序；进阶：一遍扫描 + O(1) 空间。

### ② 思路讲解
**从朴素出发**：计数排序——数出 0/1/2 的个数再分三段回填。O(n) 但要扫两遍，且面试常被追问"一遍"的写法。

**单遍三指针**：p0 指向**下一个 0 的坑**（放进去后右移），p2 指向**下一个 2 的坑**（放进去后左移），i 负责扫描：
- `nums[i] == 0`：与 p0 交换，p0++，**i++**；
- `nums[i] == 2`：与 p2 交换，p2−−，**i 不动**；
- `nums[i] == 1`：i++。

**为什么遇 2 换回的数不能跳过**：p2 换回来的元素**从未被看过**，它可能是 0、1 或 2，必须停在 i 处重审；若贸然 i++，一个换回来的 0 会永远漏在中间。而遇 0 时换回来的**必是 1 或它自己**——**不变量**保证 `[p0, i)` 全是 1，p0 只能换出 1（或 p0 == i 时的自换 0），所以 i 可以放心前进。两条规则的不对称正来自"p0 在已看区、p2 在未看区"。

**不变量**：任意时刻——`[0, p0)` 全 0；`(p2, n−1]` 全 2；`[p0, i)` 全 1；`[i, p2]` 未处理。循环条件 `i <= p2`：p2 位置本身还未处理，p2 收缩到 i 左侧时未处理区清空即结束。

复杂度对比：计数排序 O(n) 两遍；三指针 **O(n) 一遍 + O(1) 空间**，且每个元素至多被交换一次。

**套路迁移**：三分区思想 = 快速排序的**三路划分**（3-way partition）：把"等于 pivot"单独收进中段，数组重复元素极多时从 O(n log n) 逼近 O(n)。同族：283 移动零（两分区版）。

### ③ 注释代码
```python
class Solution:
    def sortColors(self, nums: List[int]) -> None:
        """原地排序，函数无返回值"""
        p0, i, p2 = 0, 0, len(nums) - 1
        # 不变量：[0,p0) 全 0；(p2,n-1] 全 2；[p0,i) 全 1；[i,p2] 未处理
        while i <= p2:
            if nums[i] == 0:
                nums[p0], nums[i] = nums[i], nums[p0]
                p0 += 1
                i += 1  # 换回的必是 1 或自身（[p0,i) 全 1），可安全前进
            elif nums[i] == 2:
                nums[p2], nums[i] = nums[p2], nums[i]
                p2 -= 1  # 换回的数没看过，i 原地重审
            else:
                i += 1   # 1 留在中段
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：一遍扫描，每个元素至多交换一次；**空间 O(1)**。
- **易错点**：
  1. 遇 2 时 **i 不前进**（换回的没看过），遇 0 时 i 前进（换回的必是 1）——两条规则别记反；
  2. 循环条件是 `i <= p2` 不是 `i < p2`——p2 处的元素还未处理，写成 `<` 会漏判（如 `[1,2,0]` 漏掉换回来的 0）；
  3. 计数排序回填的三段边界 `[0,c0)`、`[c0,c0+c1)`、`[c0+c1,n)` 要算对。
- **面试追问**：
  1. 推广到 **k** 种颜色？→ 计数排序 O(n) 两遍最省心；或一趟趟分区做 k−1 轮，O(kn)；
  2. 和快排什么关系？→ 就是三路划分：本题的"中段"固定是 1，快排里换成任取的 pivot，重复元素多时效率大增。

## 31. 下一个排列

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/next-permutation/) ｜ 标签：数组 · 双指针

### ① 题意速览
把数组重排成字典序（Lexicographic Order，字典序）下的**下一个**排列；若已是最大排列，重排成最小（整体升序）。要求原地、常数空间。
- 示例：`[1,2,3]` → `[1,3,2]`；`[3,2,1]` → `[1,2,3]`；`[1,1,5]` → `[1,5,1]`
- 关键约束：必须恰好是"紧邻的下一个"，不能跳过中间任何排列。

### ② 思路讲解
**为什么暴力不可行**：生成全排列、排序、找当前——O(n!)，只能用来理解"下一个"的定义。

**字典序的结构**：把排列从右往左看，**降序后缀是"已经到头"的部分**——后缀内部怎么换都只会变小。所以下一个排列一定发生在"最右边的升序对"处，四步走：
1. **找枢轴 i**：从右往左找第一个 `nums[i] < nums[i+1]`。i 右侧是降序后缀，i 是**最靠右的还能增大的位置**——在越靠右的位置增大，字典序增幅越小。
2. **找 j**：后缀降序 ⇒ 从右往左第一个 `> nums[i]` 的 j，就是后缀中"大于 nums[i] 的数里最小的"。
3. **交换** `nums[i]` 与 `nums[j]`：i 位换成"够用的最小更大值"，前缀增幅最小。
4. **反转 i+1..末尾**：交换后后缀**仍是降序**（换入 j 位的 `nums[i]` 满足 `nums[i] < 原 nums[j]` 且 `nums[i] >= nums[j+1]`，降序链没断），反转即得后缀的最小排列。

**为什么反转后缀就得到最小**：i 位之前完全不动；i 位换入的是可行的最小增大值；后缀交换后仍降序，是"这些元素能组成的最大排列"，反转成升序即最小排列。三者合起来，任何更大的排列要么在比 i 更左处增大（增幅必然更大），要么 i 位放了更大的数——都跳过了至少一个排列，所以结果**紧邻**。**边界**：整串降序 ⇒ 找不到 i（i = −1）⇒ 已是最大排列，反转全串变最小。

**不变量**：步骤 1 结束时 `[i+1, n)` 严格降序且是该后缀的最大排列；步骤 4 结束时它是最小排列。三趟线性扫描，**O(n) 时间 O(1) 空间**。

**套路迁移**：上一个排列 = 镜像四步（找降序对、找最小的小于者、交换、反转）；"字典序第 k 个排列"（LC 60）用阶乘进制直接定位。凡"字典序推进"类题，先问：**降序后缀在哪里？**

### ③ 注释代码
```python
class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        """原地修改，函数无返回值"""
        n = len(nums)
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1  # 步骤1：找最右升序对；相等不算升序。i<0 => 整串降序，已是最大
        if i >= 0:
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1  # 步骤2：后缀降序 -> 从右第一个 > nums[i] 的就是大于者中最小的
            nums[i], nums[j] = nums[j], nums[i]  # 步骤3：交换，i 位增幅最小
        nums[i + 1:] = reversed(nums[i + 1:])  # 步骤4：后缀仍降序，反转成最小排列
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：找 i、找 j、反转各一趟；**空间 O(1)**。
- **易错点**：
  1. 步骤 1 必须用 `>=`：**相等不算升序对**——如 `[1,2,2]` 正确答案是 `[2,2,1]`，写成 `>` 会在相等的 2 处误判出升序对，输出原数组；
  2. 步骤 2 用 `<=` 跳过：相等也不能换——换入相等的值后 i 位没变大，得到的不是"下一个"；
  3. 整串降序时 `i = -1`，`nums[i+1:]` 恰好是全串，反转逻辑要能自然覆盖该边界，别单独 return 原数组。
- **面试追问**：
  1. **上一个**排列怎么求？→ 镜像四步：从右找第一个 `nums[i] > nums[i+1]`，找第一个 `< nums[i]` 的 j，交换、反转后缀；整串升序则反转全串；
  2. 步骤 2 能二分吗？→ 后缀无重复时可二分 O(log n)，但有重复时边界易错；线性扫 O(n) 不影响总复杂度（后面反正要反转）。

## 287. 寻找重复数

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/find-the-duplicate-number/) ｜ 标签：位运算 · 数组 · 双指针 · 二分查找

### ① 题意速览
n+1 个数，取值都在 `[1, n]` 里，**至少有一个数重复**（可能重复多次），找出这个重复数。进阶：不修改数组、O(1) 空间。
- 示例：`[1,3,4,2,2]` → `2`；`[3,1,3,4,2]` → `3`
- 关键约束：数组只读（进阶）；只有一个重复数，但出现次数不限。

### ② 思路讲解
**朴素三连的短板**：排序 O(n log n) 但改数组；哈希 O(n) 但 O(n) 空间；求和/异或只在"恰好重复一次"时成立——本题重复数可能出现**多次**（如 `[2,2,2,2,2]`），差值法直接失效。

**解法一（主解）：Floyd 判圈（Floyd's Cycle Detection，龟兔赛跑）**。把**下标 i 看作节点、`nums[i]` 看作 i 的 next 指针**，从 0 出发沿 `i → nums[i]` 走：每个节点恰有一条出边，值域 [1,n] 只有 n 个节点却被 n+1 条出边指向，鸽巢原理（Pigeonhole Principle）保证**至少两个下标指向同一节点 → 链路必有环**；又因值域从 1 起、**没有任何指针指向 0**，起点 0 必在环外的尾巴上。于是"被多个下标指向的节点" = 入环口 = **重复数**。快慢指针在环内相遇后，把 slow 放回起点、两指针同速前进，**再次相遇处即入环口**：设起点到入环口 a 步、环周长 c、相遇点距入环口 b，则 a+b 是 c 的倍数，故从起点走 a 步与从相遇点走 c−b 步同时到达入环口。O(n) 时间、O(1) 空间、不修改数组——三条进阶全满足。

**解法二（对比）：二分值域**。二分对象不是下标而是**答案的取值范围 [1, n]**：统计 `cnt = #{x <= mid}`。由"只有一个重复数"可证 `cnt(t) > t ⇔ 重复数 ≤ t`（若重复数 ≤ t，超过 t 的值至多 n−t 个、各出现一次，故 cnt(t) ≥ n+1−(n−t) = t+1；反之每个 ≤ t 的值至多出现一次，cnt(t) ≤ t）。于是 `cnt > mid` 时重复数在 `[lo, mid]`，否则在 `[mid+1, hi]`。O(n log n) 时间、O(1) 空间，同样只读——比判圈好想，但慢一个 log。

**不变量**：判圈版——快指针每轮比慢指针多走一步，环内每步追近 1，必相遇；第二次扫描时两指针**同时距入环口 a 步**，相遇即入环口。二分版——`cnt(mid) > mid ⇔ 重复数 ≤ mid`。

**套路迁移**："数组当链表"家族：LC 142 环形链表 II 是判圈原型（本题是其数组伪装版）；LC 442 找所有重复、LC 448 找消失的数字用"原地正负号标记"（允许改数组时的廉价替代）。

### ③ 注释代码
**解法一（主解）：Floyd 判圈**
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        # 下标 i 为节点，nums[i] 为 i 的 next 指针；值域 [1,n] 保证 0 在环外
        slow = fast = 0
        while True:
            slow = nums[slow]        # 龟：一步
            fast = nums[nums[fast]]  # 兔：两步
            if slow == fast:         # 环内必相遇（每轮追近一步），先走后判
                break
        slow = 0                     # 龟回起点，同速再走
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]        # 再次相遇 = 入环口 = 重复数
        return slow
```

**解法二（对比）：二分值域**（单独提交时同样用 `class Solution` 类名）
```python
class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        lo, hi = 1, len(nums) - 1  # 值域 [1, n]，n = len(nums) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            cnt = sum(x <= mid for x in nums)  # 不变量：cnt(t) > t <=> 重复数 <= t
            if cnt > mid:  # [1..mid] 的名额被超员占用 -> 重复数在 [lo, mid]
                hi = mid
            else:
                lo = mid + 1
        return lo
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间**：判圈 **O(n)**（快指针最多绕环常数圈）；二分 O(n log n)。**空间**：两者均 **O(1)** 且不修改数组。
- **易错点**：
  1. 判圈版第一次循环必须**先走后判**（`while True` 内先移动再比较）——起点就是 0，先判会立刻"相遇"退出；
  2. 判圈依赖"0 不会被指向"（值域从 1 起）——若数组允许出现 0，起点可能落进环里，此法失效；
  3. 二分版是**值域二分**：比较的是 `cnt` 与 `mid`，不是元素与 mid；范围是 `[1, n]` 不是 `[0, n]`；
  4. 重复数可能出现多次，"求和减去 1..n 之和"只在恰好重复一次时成立。
- **面试追问**：
  1. 为什么起点 0 一定在环外？→ 所有值都在 [1,n]，没有出边指向 0，0 只能是"尾巴"的头部；
  2. 允许修改数组时有什么更快的？→ 原地交换/正负号标记 O(n)：把 `nums[i]` 归位，落点已被占即重复（LC 442 同款），代价是破坏"只读"约束。
