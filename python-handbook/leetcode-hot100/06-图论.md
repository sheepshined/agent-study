## 200. 岛屿数量

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/number-of-islands/) ｜ 标签：深度优先搜索 · 广度优先搜索 · 并查集

### ① 题意速览
`m × n` 的二进制网格里，`'1'` 是陆地、`'0'` 是水，数一数有多少座岛屿。岛屿由**上下左右**相邻的陆地组成（斜向不算连通）。
- 示例：`[["1","1","0"],["1","0","0"],["0","0","1"]]` → `2`（左上角一座、右下角一座）
- 关键约束：网格四周视为被水包围；格子值是字符 `'1'/'0'` 不是数字。

### ② 思路讲解
**矩阵就是隐式图**：把每个格子看成一个节点，相邻的陆地格子之间有边——"数岛屿"就是数这个图的**连通分量**（Connected Component，连通分量：互相可达的最大节点集团）。

**从暴力出发**：对每对相邻格子维护"是否同岛"……那是并查集的路子（可做，但为连通分量建一套并查集结构太重）。更轻的视角：**找到一座岛后，把它整个访问一遍并标记**，这样每座岛只会被"发现"一次。

**主流程**：从头扫每个格子，遇到 `'1'` 就是撞上了一座**还没见过**的岛——计数 +1，随即从它出发做 DFS（Depth-First Search，深度优先搜索）或 BFS（Breadth-First Search，广度优先搜索），把这座岛能到达的所有陆地格子标记成已访问。

**为什么可以"淹岛"而不是开 visited 数组**：本题的格子值不再被使用，直接把访问过的 `'1'` 置成 `'0'`（俗称"沉岛"），省掉一份 O(mn) 的标记空间。不变量（Invariant，循环/递归每一步都保持为真的性质）：**每座岛恰好被计数一次、且计数后必被完整淹没**——于是扫描推进到哪里都不会重复数、也不会漏数。

**复杂度**：每个格子至多被 DFS 触达常数次（入岛一次、四方向试探各一次），整体 O(mn)。

**套路迁移**：这是"隐式图 + 洪水填充（Flood Fill，从一点出发染整片连通区）"的原型题。同家族：岛屿的最大面积（LC 695，淹没时顺便数格子）、岛屿数量不修改原网格时用 visited 数组、最大人工岛（LC 827，先量岛再架桥）、矩阵连通类问题（被围绕的区域 LC 130、 Pacific/Atlantic 水流 LC 417）全部共用本题骨架。

### ③ 注释代码
```python
class Solution:
    def numIslands(self, grid: List[List[str]]) -> int:
        m, n = len(grid), len(grid[0])

        def dfs(i: int, j: int) -> None:
            # 递归出口：越界，或踩到水/已淹没的格子
            if i < 0 or i >= m or j < 0 or j >= n or grid[i][j] != '1':
                return
            grid[i][j] = '0'   # 淹掉：兼任"已访问"标记，省掉 visited 集合
            dfs(i + 1, j)      # 四方向扩散，只处理上下左右（斜向不连通）
            dfs(i - 1, j)
            dfs(i, j + 1)
            dfs(i, j - 1)

        count = 0
        for i in range(m):
            for j in range(n):
                if grid[i][j] == '1':
                    count += 1   # 撞上一座新岛：它是这座岛第一个被扫到的格子
                    dfs(i, j)    # 把整座岛淹成 '0'，之后扫描不会再撞见它
        return count
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(mn)**：每个格子至多进出 DFS 常数次；**空间 O(mn)**：最坏全图是陆地时递归深度达 mn（DFS 栈）。
- **易错点**：
  1. 先判 `grid[i][j] != '1'` 再递归，别在递归后才判——判晚一格会重复入岛或越界；
  2. 格子值是**字符串** `'1'`，写 `grid[i][j] == 1` 恒为假，计数得 0；
  3. 面试若不允许修改输入，改用 visited 二维数组，DFS 前置判断 `visited[i][j]`；
  4. 超大全陆地图递归会爆栈，可换 BFS 队列或显式栈。
- **面试追问**：
  1. 求**最大岛屿面积**（LC 695）？→ 同款淹没 DFS 改成 `return 1 + 四方向之和`，外层取 max，多一座"面积版"只需加几行；
  2. 用 BFS 写一版？→ 队列起点是撞岛的那个格子，出队时淹格子、把四方向 `'1'` 入队；BFS 空间最坏 O(min(m,n))（队列宽度受短边限制），比 DFS 的 O(mn) 递归栈更稳。

## 994. 腐烂的橘子

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/rotting-oranges/) ｜ 标签：广度优先搜索 · 数组 · 矩阵

### ① 题意速览
网格里三种值：`0` 空、`1` 新鲜橘子、`2` 烂橘子。每分钟，烂橘子把**上下左右**相邻的新鲜橘子传染变烂。求所有橘子都烂掉的最少分钟数；永远烂不完则返回 `-1`。
- 示例：`[[2,1,1],[1,1,0],[0,1,1]]` → `4`；`[[2,1,1],[0,1,1],[1,0,1]]` → `-1`（左下角那颗隔空够不着）
- 关键约束：可能没有橘子（此时返回 0）；传染只走四方向。

### ② 思路讲解
**从暴力出发**：每一分钟做一轮"全体模拟"——把当前所有烂橘子的邻居标烂，重复直到没有变化。正确但每轮要重扫全图，O(mn·分钟数)；而且"分钟数"与"循环轮数"要小心对应。

**正解是多源 BFS**：单源 BFS 求最短路时，起点只有一个；本题的"起点"是**所有烂橘子**——它们在**同一时刻**开始传染，所以全部同时入队当作**第 0 层**。扩散层数就是分钟数：第 1 层是第 1 分钟被感染的橘子，第 2 层是第 2 分钟……这正是多源 BFS（Multi-source BFS：把所有"事件源"一起放进第一层，其余与普通 BFS 完全一致）。

**为什么 BFS 保证"最先到达即最短时间"**：BFS 按层推进，同一层的格子离源点"步数"相同，一个格子第一次被感染时，走过的层数不可能更少——它是真实的最短时间。这和迷宫最短路是同一条性质。

**对账（Accounting，事后核对总数）技巧**：先扫一遍统计新鲜橘子数 `fresh`；BFS 中每感染一颗就 `fresh -= 1`；结束时 `fresh == 0` 说明全烂了，答案就是扩散的层数；否则存在被水隔开的"孤岛橘子"，返回 `-1`。有了这个计数器，就不用在结束时再全图检查一遍。不变量：任意时刻 `fresh` 恰好等于网格里剩余新鲜橘子的个数；进入下一分钟前，队列里恰好是"本分钟会被感染"的全部格子。

**复杂度**：每个橘子至多入队出队一次，O(mn)——比逐轮模拟省掉了重复扫描。

**套路迁移**："多源 BFS = 多个起点一起进第一层"家族：01 矩阵（LC 542，从每个 0 出发求最近 1，把所有 0 当源）、地图分析（LC 1162，从陆地推海洋）、由斜杠划分区域之外的"同时扩散"类题。口诀：**多源最短时间题，先把源点全入队，层数就是时间值**。

### ③ 注释代码
```python
from collections import deque

class Solution:
    def orangesRotting(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        queue = deque()   # 烂橘子坐标 (i, j)
        fresh = 0         # 新鲜橘子计数，用于结束时对账
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 2:
                    queue.append((i, j))   # 多源：所有烂橘子都是第 0 层
                elif grid[i][j] == 1:
                    fresh += 1

        minutes = 0
        # 分层 BFS：while 每转一圈 = 过了一分钟
        while queue and fresh > 0:          # fresh==0 提前收工，minutes 不多算
            minutes += 1
            for _ in range(len(queue)):     # 先记下本层节点数，逐个处理
                i, j = queue.popleft()
                for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    ni, nj = i + di, j + dj
                    if 0 <= ni < m and 0 <= nj < n and grid[ni][nj] == 1:
                        grid[ni][nj] = 2    # 感染的同一瞬标记，防止重复入队
                        fresh -= 1
                        queue.append((ni, nj))  # 下一层的传染源
        return minutes if fresh == 0 else -1    # 对账：还剩新鲜的就传播不到
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(mn)**：每个格子至多入队一次；**空间 O(mn)**：队列最坏存满图橘子。
- **易错点**：
  1. 空输入或**一个新鲜橘子都没有**时应返回 0——`while` 条件里的 `fresh > 0` 就是为此兜底，漏了会多算 1 分钟；
  2. 分层必须**先取 `len(queue)` 再出队**：边出队边入队会改变队列长度，把下一层混进本层，分钟数算多；
  3. 感染时**立刻置 2**：若等出队时才改，同一颗橘子会被两个方向的烂橘子各入队一次；
  4. 返回 `-1` 的唯一依据是 `fresh > 0`，别用"队列空了"判断——队列空时无法区分"烂完了"和"够不着"。
- **面试追问**：
  1. 不分层行不行？→ 可以：每个入队节点带上 `time` 字段，出队时用 `time+1` 感染邻居，最后答案取所有 `time` 的最大值；分层写法少存一个字段，两种都要会；
  2. 若一格一秒只有**一半概率**腐烂（进阶开放题）？→ 期望时间问题，转为概率 DP/BFS 混合模型，先讲清 BFS 求的是确定性最短时间，概率版要重新建模。

## 207. 课程表

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/course-schedule/) ｜ 标签：深度优先搜索 · 广度优先搜索 · 图 · 拓扑排序

### ① 题意速览
`numCourses` 门课程，编号 `0 ~ numCourses-1`。`prerequisites[i] = [a, b]` 表示修 a 之前必须先修 b。判断能否修完**所有**课程。
- 示例：`numCourses = 2`，`prerequisites = [[1,0]]` → `true`（先 0 后 1）；加上 `[0,1]` → `false`（互相等，死锁）
- 关键约束：依赖可能成环；`prerequisites` 可能为空。

### ② 思路讲解
**翻译成图**：课程是节点，"修 a 前必须修 b"就是一条有向边 `b → a`。"能否修完所有课" = 有向图里有没有**环**（Cycle）——有环的部分互相等待，永远修不了。这就是**拓扑排序**（Topological Sort，把有向无环图的节点排成一条线，保证每条边都从左指向右）的经典判环应用。

**从直觉到 Kahn 算法**：想修课，总要从不依赖任何课的课开始。给每个节点记一个**入度**（Indegree：指向它的边的条数，即"还差几门前置"），入度为 0 的课立刻可修。修完一门（出队），它指向的所有课的前置各满足一门，入度 −1；某门课入度减到 0，就加入"可修"队列。这个"入度表 + 队列"的流程就是 **Kahn 算法**。

**不变量**：任意时刻，队列里的课程都是"当前已无未满足前置"的课；出队的顺序是一张合法的修课时间表。若图无环，每门课的入度迟早减到 0、必然出队；**若出队数 < 课程数，剩下的课入度永远减不到 0——它们困在一个环里**，这就是 Kahn 的判环依据。

**为什么不用 DFS**：DFS 也能判环（**三色标记法**：白=未访问、灰=在当前递归栈里、黑=已完成；递归中撞到"灰"就是有环）。两版都要会：Kahn 免递归、还能顺便输出修课顺序；DFS 判环在"只需判有无环"时更直接。

**复杂度**：建图 O(V+E)，每节点入队出队一次、每边被松弛一次，整体 O(V+E)——顶点数 V、边数 E。

**套路迁移**："依赖调度"家族：课程表 II（LC 210，把判断改成输出一条拓扑序，Kahn 的出队序列直接就是答案）、外星文字典（LC 269，从单词顺序推断字符间依赖再拓扑排序）、并行任务最少轮次（LC 1136，按"层"出队，层数即答案）。口诀：**看到"先修/先做 A 才能做 B"，先建图、再拓扑**。

### ③ 注释代码
```python
from collections import deque

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        graph = [[] for _ in range(numCourses)]  # 邻接表：b -> [b 修完后才能修的课]
        indegree = [0] * numCourses              # 入度：每门课还差几门前置
        for a, b in prerequisites:
            graph[b].append(a)
            indegree[a] += 1

        # 所有"零前置"的课先入队，立刻可修
        queue = deque(i for i in range(numCourses) if indegree[i] == 0)
        taken = 0                       # 出队（已修）课程数
        while queue:
            b = queue.popleft()
            taken += 1
            for a in graph[b]:
                indegree[a] -= 1        # b 修完，a 的一门前置被满足
                if indegree[a] == 0:    # 前置全部凑齐，a 变为可修
                    queue.append(a)
        # 出队数 < 课程数 <=> 有课的前置永远凑不齐 <=> 存在环
        return taken == numCourses
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(V+E)**：每点每边各处理一次；**空间 O(V+E)**：邻接表 + 入度表 + 队列。
- **易错点**：
  1. 边的方向别建反：`[a, b]` 是 `b → a`（先修 b），建反了入度统计全错；
  2. 依赖对可能有**重复边**，Kahn 天然不受影响（重复边多扣一次入度又多补一次？不会——每条重复边都会让 a 的入度 +1 且在 b 出队时 −1，两次各算各的，恰好抵消）；但换成 DFS 判环时重复边无害、别误判；
  3. 邻接表用 `[[] for _ in range(n)]` 初始化，写成 `[[]] * n` 会 n 个槽共享同一个列表（append 互相污染）；
  4. `prerequisites` 为空时要返回 `true`（入度全 0，全队入队）。
- **面试追问**：
  1. 用 **DFS 三色标记**判环？→ 每点三态：0 未访问、1 递归中（灰）、2 已完成；递归进入邻居时若邻居是灰，说明撞回当前路径，有环。注意回溯前要把节点标成 2（黑）；
  2. 输出**任意一条**合法修课顺序（LC 210）？→ 记录 Kahn 的出队序列即可，它本身就是拓扑序；无环时长度恰为 n。

## 208. 实现 Trie (前缀树)

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/implement-trie-prefix-tree/) ｜ 标签：设计 · 字典树 · 哈希表 · 字符串

### ① 题意速览
设计一个 **Trie（前缀树/字典树）** 类，支持三个方法：`insert(word)` 插入单词、`search(word)` 判断**完整单词**是否存在、`startsWith(prefix)` 判断**前缀**是否存在（此前缀后面接什么都行）。假设输入只含小写字母。
- 示例：依次执行 `insert("apple")`、`search("apple") → true`、`search("app") → false`、`startsWith("app") → true`、`insert("app")`、`search("app") → true`
- 关键约束：`search` 与 `startsWith` 的区别只在"是否要求走到词尾"。

### ② 思路讲解
**从朴素出发**：`search`/`startsWith` 拿一个集合/哈希表存所有词——`search` 是 O(1)，但 `startsWith(prefix)` 得把集合里所有词扫一遍逐个判断 `w.startswith(prefix)`，O(总字符数)。瓶颈：哈希表存的是**整词**，前缀信息被整词"打散"在各个 key 里，公共前缀没有复用。

**Trie 的核心想法**：把所有词按**公共前缀**合并到同一条路径上。每个节点是一个"字符分岔口"：
- `children`：本节点的子节点表——26 槽数组（`[None]*26`，按 `ord(ch)-97` 索引，查找快、省下哈希开销）或字典（键任意、写法简单，本题用字典）；
- `isEnd`：布尔标记，表示"从根走到这里拼出的串是一个**完整单词**的结尾"，而不只是某个更长单词的中间前缀。

有了 `isEnd`，"前缀存在"与"单词存在"只差一步：`startsWith` = 能沿着前缀走到底；`search` = 走到底之后**还要** `isEnd` 为真（`"app"` 路径存在但没打词尾标记，所以 `search("app")` 为 false）。

**不变量**：任意时刻，从根到节点 p 的路径上字符依次拼接 = p 所代表的前缀；节点 p 的 `isEnd` 为真 ⇔ 该前缀已被某次 `insert` 作为完整单词插入。插入/查询都从根出发逐字符下行，长度 L 的串只走 L 步。

**复杂度**：三个方法都是 O(L)（L 为串长），与库里存了多少词无关——这是 Trie 对哈希表的本质优势：**查询成本取决于"要查的串"，不取决于"库的规模"**。

**套路迁移**：Trie 家族：单词搜索 II（LC 212，Trie + 网格回溯同时搜一堆词）、添加与搜索单词（LC 211，支持通配符 `.`，在 children 分叉处逐支尝试）、最大的异或对（LC 421，二进制位版 Trie）。凡是"大量串共享前缀 + 高频前缀/整词查询"，先想 Trie。

### ③ 注释代码
```python
class TrieNode:
    def __init__(self) -> None:
        self.children = {}   # 子节点表：字符 -> 下一层节点（26 槽数组也行）
        self.isEnd = False   # 从根到此的路径是否构成一个完整单词

class Trie:
    def __init__(self) -> None:
        self.root = TrieNode()   # 哨兵根节点：空串，不存任何字符

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            if ch not in node.children:   # 路径缺一段，就地建节点
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.isEnd = True   # 词尾打标记；insert 是唯一打标记的地方

    def _find(self, s: str):    # 沿 s 走到底，返回终点节点；路断了返回 None
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None:    # 中途无路，说明此前缀从未被插入过
                return None
        return node

    def search(self, word: str) -> bool:
        node = self._find(word)
        return node is not None and node.isEnd   # 必须落在"词尾"上才算单词

    def startsWith(self, prefix: str) -> bool:
        return self._find(prefix) is not None    # 路径走通即前缀存在
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间**：insert/search/startsWith 均为 O(L)（L 为串长）；**空间 O(总字符数 × 字母集)**：最坏（无公共前缀）退化成"每词一条链"。
- **易错点**：
  1. `search` 忘查 `isEnd`：只走到 `"app"` 路径就返回 true，把 `"apple"` 误认成单词 `"app"`；
  2. `_find` 中途用 `children[ch]` 直接下标会 `KeyError`，用 `.get()` 先探路；
  3. 多个方法共享"走到底"逻辑时，别在 `_find` 里顺手判断 `isEnd`——`startsWith` 不需要它；
  4. 根节点代表空串，`startsWith("")` 应返回 true（`_find("")` 返回 root，非 None，天然正确）。
- **面试追问**：
  1. 输出**所有以某前缀开头**的词？→ 用 `_find` 走到前缀终点，再从那里 DFS 收集：每遇 `isEnd` 就把"前缀 + 已走路径"收进结果（递归时携带拼接串或回溯拼串均可）；
  2. 26 槽数组 vs 字典怎么选？→ 字母集小且固定用数组（省哈希、定位快），字符集大或稀疏用字典（省内存）；两者复杂度同阶，面试讲清取舍即可。
