**这个专题练什么**：二叉树是"递归思维"的主场，动笔前先过**递归三要素**——**函数定义**（这个函数对子树算什么、返回什么信息）、**基线条件**（base case，何时停，通常是 `root is None`）、**递归调用**（如何把问题缩小交给左右子树）。两条遍历骨架要练到闭眼能写：**DFS（Depth-First Search，深度优先搜索）递归**——前序/中序/后序只是"访问根的时机"不同，且都能把递归的隐式调用栈换成显式栈改写成迭代版；**BFS（Breadth-First Search，广度优先搜索）队列层序**——`collections.deque` 出队入队，按 `len(queue)` 整层处理。最后一个核心意识是**信息流向**："自顶向下"把祖先知道的事实（上下界、层号、累积和）当**参数**传下去；"自底向上"让子树算好的结果（深度、贡献、命中情况）当**返回值**传上来；两股流不够用时，再加一条**全局变量**通道沿途记账（543/124 题的"双通道"分工）。刷完这 15 题，拿到新树题应当能条件反射地问自己：**这个函数向子树要什么、向父亲回传什么、全局另记什么？**

## 94. 二叉树的中序遍历

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/binary-tree-inorder-traversal/) ｜ 标签：栈 · 树 · 深度优先搜索 · 二叉树

### ① 题意速览
给定二叉树根节点，按**中序**（左 → 根 → 右）顺序返回所有节点值。
- 示例：`[1,null,2,3]` → `[1,3,2]`
- 关键约束：递归实现平凡，进阶要求**迭代**实现；树可能为空（返回空列表）。

### ② 思路讲解
**从递归出发**：中序的递归定义就是"左子树的中序 + 自己 + 右子树的中序"，三行写完。它是遍历骨架的起点，但面试官显然不满足于此——追问必然是"递归的本质是什么？能用显式数据结构模拟吗？"

**递归在干什么**：递归调用的隐式行为是调用栈（Call Stack）——每进入一个子问题就压栈，返回就弹栈。递归版中序里，栈里压着的是"还没访问完、等左子树回来再处理的祖先"。

**迭代版 = 把调用栈换成显式的栈**。中序要求"左子树全部处理完才轮到自己"，于是三步循环：
1. **一路压左**：从当前节点沿左孩子一路压栈，直到没有左孩子——栈顶就是"下一个要访问的节点"（它没有更左的等待者）；
2. **弹出访问**：栈顶出栈写入结果——轮到它了；
3. **转向右子树**：指针移到弹出节点的右孩子，重复前两步——右孩子为空时，下一轮弹出的就是"等它返回的祖先"，与递归的返回行为完全同构。

**不变量（Invariant，循环每一步都保持为真的性质）**：任何时刻，栈从底到顶恰好构成"从根到当前指针路径上、自己还没被访问且右子树未处理的祖先链"，栈顶永远是中序序列的下一个节点——弹出顺序因此严格等于中序。

**Morris 遍历（Morris Traversal，莫里斯遍历）追问版**：能否 O(1) 空间？可以——利用树里的"空闲指针"。对每个节点，找它左子树的**最右节点**（中序意义下它的前驱（Predecessor）），把前驱悬空的右指针临时指向自己（线索），然后下潜左子树；之后走到自己时顺着线索回来访问，再**还原**线索。代价：每条边至多走两次，时间 O(n)、空间 O(1)，但中途修改了树结构（需还原），面试讲清原理即可。

**套路迁移**：这是"递归 ↔ 显式栈"互相翻译的原型题，三个遍历的迭代版只差"访问时机"：前序在压栈时访问、中序在弹出时访问、后序要靠"上次访问节点"或逆序技巧。同家族：验证 BST（98 题，迭代中序）、第 K 小（230 题，迭代中序提前停）。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def inorderTraversal(self, root: Optional[TreeNode]) -> List[int]:
        # 递归一行版（面试先给，本质是把问题交给左右子树）：
        # return (self.inorderTraversal(root.left) + [root.val]
        #         + self.inorderTraversal(root.right)) if root else []
        res, stack = [], []
        cur = root
        while cur or stack:
            # 一路压左：把"自己 + 整条左祖先链"压栈，直到没有左孩子
            while cur:
                stack.append(cur)
                cur = cur.left
            # 不变量：栈顶是中序序列的下一个节点（它没有更左的等待者）
            cur = stack.pop()
            res.append(cur.val)   # 访问：它的左子树已全部处理完
            cur = cur.right       # 转向右子树；为空则下轮弹出"等它返回的祖先"
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点压栈、弹栈各一次；**空间 O(h)**（h 为树高，递归版是递归栈、迭代版是显式栈），链状树最坏 O(n)。
- **易错点**：
  1. 外层条件漏写 `stack`：右子树为空时要回头弹祖先，必须是 `cur or stack`；
  2. "一路压左"写进外层循环体外，只压了一次左链就退出；
  3. 空树应返回 `[]`，不是报错。
- **面试追问**：
  1. 前序/后序迭代版怎么改？→ 前序：压栈时访问、先压右再压左；后序：按"根右左"遍历后整体反转，或记录 prev 判断右子树是否已访问；
  2. Morris 为什么能 O(1)？→ 中序前驱（左子树最右节点）在中序序列里紧邻自己，把它悬空的 right 当"回路"临时用，访问完还原，省掉整条祖先链的栈。

## 104. 二叉树的最大深度

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/maximum-depth-of-binary-tree/) ｜ 标签：树 · 深度优先搜索 · 广度优先搜索 · 二叉树

### ① 题意速览
求二叉树的最大深度：从根到最远叶子节点最长路径上的**节点数**。
- 示例：`[3,9,20,null,null,15,7]` → `3`（3 → 20 → 15）
- 关键约束：空树深度为 0；叶子节点指没有孩子的节点。

### ② 思路讲解
**递归三要素逐条对号（本题是二叉树递归的"Hello World"）**：
- **函数定义**：`depth(root)` = 以 root 为根的子树的最大深度；
- **基线条件**：`root is None` 时深度为 0；
- **递归调用**：整棵树深度 = max(左子树深度, 右子树深度) + 1（自己这一层）。

**信息流向：自底向上**。深度在子树里先算好、再一层层回传——父节点不需要任何额外信息，只做"取大 + 1"。这是最纯粹的"返回值就是答案的一部分"的递归形态。

**对比 BFS 数层数（自顶向下视角）**：从根出发一层一层往下走，走完的层数就是深度。队列层序遍历，每处理完一整层深度 +1，队列空时层数即答案。两种视角殊途同归：DFS 统计"最深的一条链"，BFS 统计"总共有几层"。

**不变量**：递归版每一步，`depth(x)` 返回时恰好等于 x 子树内最深链的节点数——对每个节点成立则对根成立。BFS 版是"每轮循环开始时，队列里恰好是下一整层的节点"。

**套路迁移**："自底向上返回子树信息 + 用返回值拼出答案"是树题第一模板：直径（543 题）在求深度的同时多记一条全局路径、平衡二叉树（LC 110）在求深度的同时多判一次高度差。先吃透本题，后面所有"返回值 + 全局变量"双通道的题都是它的加料版。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
from collections import deque

class Solution:
    def maxDepth(self, root: Optional[TreeNode]) -> int:
        # 递归版（自底向上）：三要素齐活，一行核心
        if root is None:          # 基线条件：空树深度 0
            return 0
        # 递归调用：信任子调用返回"子树最大深度"（函数定义），取大 + 自己这层
        return max(self.maxDepth(root.left), self.maxDepth(root.right)) + 1

    def maxDepthBFS(self, root: Optional[TreeNode]) -> int:
        # BFS 版（自顶向下数层数），提交时二选一
        if root is None:
            return 0
        depth, queue = 0, deque([root])
        while queue:
            # 不变量：每轮开始时 queue 恰好装着"下一整层"的节点
            for _ in range(len(queue)):
                node = queue.popleft()
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
            depth += 1            # 走完一整层，层数 +1
        return depth
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点访问一次；**空间**：递归版 O(h)（递归栈，链状最坏 O(n)）；BFS 版 O(w)（w 为最大层宽，满树最坏 O(n)）。
- **易错点**：
  1. 深度数的是**节点数**不是边数：单节点树答案 1、空树 0；
  2. BFS 版 `for _ in range(len(queue))` 忘了先固定层数，边遍历边入队会跨层；
  3. 写成 `if root.left is None and root.right is None: return 1` 之类的"叶判断"分支画蛇添足，`root is None` 一个基线就够。
- **面试追问**：
  1. 求**最小深度**（LC 111）？→ 不能照抄取 min：单链树（根 + 一个孩子）最小深度是 2 不是 1，必须特判"只有单侧孩子"的节点；
  2. 树极深（十万层）时递归版有什么风险？→ Python 默认递归深度上限约 1000，会 RecursionError，改用 BFS 版或显式栈迭代。

## 226. 翻转二叉树

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/invert-binary-tree/) ｜ 标签：树 · 深度优先搜索 · 广度优先搜索 · 二叉树

### ① 题意速览
把每个节点的左右子树互换（整棵树镜像翻转），返回翻转后的根。
- 示例：`[4,2,7,1,3,6,9]` → `[4,7,2,9,6,3,1]`
- 关键约束：是"整棵镜像"，不是只翻一层的左右；空树返回 None。

### ② 思路讲解
**为什么这题著名**：Homebrew 作者 Max Howell 的面试轶事让它出了名——"Google：90% 的工程师用你写的软件，但你不会在白板上翻转二叉树"。它简单，但简单题最能暴露"是否真的理解递归"。

**递归三要素**：函数定义 `invert(root)` 返回"翻转后这棵树"的根；基线条件是空树翻转仍是空树（返回 None）；递归调用是先翻转左右子树、再交换 root 的左右指针。

**关键认知：翻转的是指针，不是值**。树的结构由 left/right 指针决定，交换 `root.left` 与 `root.right` 这两个引用，整个子树就随引用整体搬家——不需要逐个交换节点值，也不需要新建节点。子树内部又被递归各自翻好，合起来就是整棵镜像。

**易混的顺序问题**：先翻转再交换、还是先交换再翻转？都对，但引用要接对。最不易错的写法：先用临时变量接住"翻转后的左右子树根"，再一次性赋给 `root.left/right`；若先交换再递归，递归对象也跟着换了位置，逻辑自洽同样正确——初学者翻车多半出在两种写法混着写。

**不变量**：`invert(x)` 返回后，x 的左右指针所指两棵子树互为镜像，且 x 子树整体 = 原 x 子树的镜像——由归纳法，节点自身交换 + 两棵已镜像的子树，整棵即镜像。

**套路迁移**："对每个节点做统一的结构性操作"家族：对称二叉树（101 题，把"交换"换成"左右对照"）、合并二叉树（LC 617，两棵树同位置相加）。凡是"操作不改返回值语义"的题，返回原根还是新根要自己定清楚并写进注释。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def invertTree(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        # 基线条件：空树翻转仍是空树
        if root is None:
            return None
        # 递归调用：信任 invertTree 对子树返回"已翻转子树的根"（函数定义）
        left = self.invertTree(root.left)
        right = self.invertTree(root.right)
        # 交换指针：整个子树随引用换位，不动任何节点的值
        root.left, root.right = right, left
        # 不变量：此刻 root 子树 = 原 root 子树的镜像
        return root
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点访问一次；**空间 O(h)**：递归栈，链状最坏 O(n)、平衡时 O(log n)。
- **易错点**：
  1. "先交换再递归"版里递归对象写反——交换后 `root.left` 指的已是原右子树，写法要与顺序配套；
  2. 误以为要交换节点值：值不动，动的是指针；
  3. 基线条件漏 `None` 判断，直接访问 `root.left` 抛 AttributeError。
- **面试追问**：
  1. 能用**迭代**做吗？→ 能：BFS 或栈式 DFS 遍历到每个节点时交换其左右指针，处理顺序不重要，每节点处理一次即可；
  2. 翻转两次等于什么？→ 恒等操作，可用来做对拍测试：`invert(invert(t))` 的序列应与原树一致。

## 101. 对称二叉树

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/symmetric-tree/) ｜ 标签：树 · 深度优先搜索 · 广度优先搜索 · 二叉树

### ① 题意速览
判断一棵二叉树是否轴对称：它的左子树与右子树互为镜像。
- 示例：`[1,2,2,3,4,4,3]` → `true`；`[1,2,2,null,3,null,3]` → `false`（形状不镜像）
- 关键约束：对称要同时满足"值相等"和"位置镜像"（外对外、内对内）。

### ② 思路讲解
**从直觉出发**：比较"根的左子树"和"根的右子树"是否互为镜像。但单参数递归不够用——镜像比较永远是**两个节点**同时参与：p、q 处于镜像位置，当且仅当值相等，且"p 的左"对上"q 的右"、"p 的右"对上"q 的左"。

**关键设计：双参数递归**。把函数定义从"判断一棵树"升级为"判断两个节点是否互为镜像"——
- **函数定义**：`compare(p, q)` = 以 p、q 为根的两棵子树是否互为镜像；
- **基线条件**：两个都空 → 镜像成立；一空一非空 → 不成立；都非空但值不等 → 不成立；
- **递归调用**：`compare(p.left, q.right)`（外侧）与 `compare(p.right, q.left)`（内侧）。

入口是 `compare(root.left, root.right)`。

**为什么不是 `compare(p.left, q.left)`**：镜像即照镜子——p 的左手边要和 q 的**右手边**面对面。左对左是"复制"不是"镜像"。

**不变量**：`compare(p, q)` 返回 true 时，p、q 两棵子树沿轴互为镜像；递归逐层下探，所有"镜像位"节点对被恰好检查一次，无遗漏无重复。

**再进一步（面试加分）**：对称也可用序列理解——左子树按"根左右"遍历、右子树按"根右左"遍历，两序列相等即对称；但**只看一个序列（如中序）不行**：全等值树的不同形状可以有相同中序，必须带 null 占位或双序列对照。

**套路迁移**：双参数递归是"单参数不够用"时的标准升级：本题传"一对镜像节点"，验证 BST（98 题）传"上下界一对参数"，层序类题传"层号"。当问题的状态超过一个对象，就把它做成参数传下去。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def isSymmetric(self, root: Optional[TreeNode]) -> bool:
        if root is None:          # 空树也算对称
            return True
        return self.compare(root.left, root.right)

    def compare(self, p: Optional[TreeNode], q: Optional[TreeNode]) -> bool:
        # 基线条件①：两边都空 -> 镜像成立（必须先于②判断）
        if p is None and q is None:
            return True
        # 基线条件②：一空一非空 -> 形状不对称
        if p is None or q is None:
            return False
        # 基线条件③：值不等 -> 不对称
        if p.val != q.val:
            return False
        # 递归调用：镜像位配对——p 的左对 q 的右（外侧），p 的右对 q 的左（内侧）
        # 不变量：compare(p, q) 为真 <=> 两棵子树沿轴互为镜像
        return self.compare(p.left, q.right) and self.compare(p.right, q.left)
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点至多参与一次比较；**空间 O(h)**：递归栈，链状最坏 O(n)。
- **易错点**：
  1. 写成 `compare(p.left, q.left)`——那是"复制"判据，不是镜像；
  2. 基线条件顺序错：先访问 `p.val` 再判空会空指针崩溃，"都空"必须最先判；
  3. 只比当前对、忘了两侧都要递归（漏一侧则形状错误漏判）。
- **面试追问**：
  1. 用**迭代**写？→ 队列成对入队：初始 `(left, right)`，每次弹出一对比较，再把 `(p.left, q.right)`、`(p.right, q.left)` 成对入队——把递归栈换成队列，逻辑一字不差；
  2. 什么时候用 DFS、什么时候用 BFS？→ 本题两者等价；若只需判"是否对称"且树很深，DFS 递归栈 O(h) 更省；迭代成对比较则天然是 BFS 风格。

## 543. 二叉树的直径

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/diameter-of-binary-tree/) ｜ 标签：树 · 深度优先搜索 · 二叉树

### ① 题意速览
二叉树中任意两节点间最长路径的**边数**称为直径，路径不一定经过根，求直径。
- 示例：`[1,2,3,4,5]` → `3`（路径 4-2-1-3 或 5-2-1-3，3 条边）
- 关键约束：路径可以不过根；单节点树直径为 0。

### ② 思路讲解
**从错误直觉出发**：直径 = 根的左深 + 右深？只对"恰好过根的路径"成立。路径可以盘在任意子树内部——比如左子树又深又宽时，最长路径可能完全不碰根。

**正确拆解：给路径找最高点**。任何路径都有一个"最高点"（路径上深度最小的节点）：从它左子树下来、经过它、再下到右子树。于是**枚举每个节点当最高点**，"过它的最大路径边数 = 左子树深度 + 右子树深度"，全局取最大。

**实现的关键分工（本题灵魂）**：递归函数只有一个返回值，但这里同时要两样东西——
- **返回给父亲的是"深度"**：父亲算"左深 + 右深"需要孩子的深度；
- **全局记录的是"过自己的路径"**：路径信息没法用返回值往上带（一拐弯就断），所以用全局变量 `self.ans` 在递归途中顺手更新。

这就是**"返回值一条信息流、全局变量另一条信息流"的双通道**：深度自底向上回传，直径在沿途每个节点结算一次。

**不变量**：`depth(x)` 返回时，x 子树的最深链已算出，且 `self.ans ≥` x 子树内所有"过某节点"路径的最大值——每颗子树的信息被父亲用一次、被全局记一次，两不遗漏。

**为什么不用"枚举两个端点"**：那是 O(n²)；按"最高点"拆解后每节点只结算一次，一遍后序遍历完成。"给路径找最高点/拐点"是把路径问题化归为子树信息问题的通用转换器。

**套路迁移**：本骨架（后序返回深度 + 全局更新路径最值）是二叉树递归的黄金模板：124 最大路径和（15 题）一模一样，只是"边数"换成"点权和"且多了负值截断；平衡二叉树（LC 110）、二叉树的坡度（LC 563）同款。分工口诀：**要给父亲的，用 return；只给自己记账的，用全局。**

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        self.ans = 0  # 全局通道：记录"以某节点为最高点"的最大路径边数

        def depth(node: Optional[TreeNode]) -> int:
            # 基线条件：空树深度 0
            if node is None:
                return 0
            # 递归调用：先拿左右子树深度（自底向上）
            left = depth(node.left)
            right = depth(node.right)
            # 结算：以 node 为最高点的路径边数 = 左深 + 右深
            self.ans = max(self.ans, left + right)
            # 返回通道：只把"单侧最深链"交给父亲，拐弯信息不回传
            # 不变量：返回值 = node 子树的最深链节点数
            return max(left, right) + 1

        depth(root)
        return self.ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点结算一次；**空间 O(h)**：递归栈，最坏 O(n)。
- **易错点**：
  1. 返回值写成 `left + right + 1`——向父亲回传的必须是"单侧最深链"，拐弯信息只进全局不回传；
  2. 直径数的是**边**不是节点：过最高点的路径是 `左深 + 右深` 条边（若问节点数才是 +1）；
  3. 单节点/空树边界：直径 0，`self.ans` 初始 0 恰好兜住。
- **面试追问**：
  1. 直径必须过根吗？→ 不必，最高点可以在任何子树——这正是要枚举每个节点当最高点的原因；
  2. 要**输出路径本身**？→ 更新 `self.ans` 时记录当时的 node，最后从该节点沿"较深一侧"回溯收集节点。

## 102. 二叉树的层序遍历

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/binary-tree-level-order-traversal/) ｜ 标签：树 · 广度优先搜索 · 二叉树

### ① 题意速览
按层从上到下、每层从左到右遍历二叉树，返回二维数组：每层一个子数组。
- 示例：`[3,9,20,null,null,15,7]` → `[[3],[9,20],[15,7]]`
- 关键约束：输出必须**按层分组**，不是一维扁平序列。

### ② 思路讲解
**从朴素 BFS 出发**：队列逐个出队入队，得到一维序列。但题目要"按层分组"——瓶颈在于：一维遍历里你不知道"哪几个节点属于同一层"。

**关键技巧：按 len(queue) 分层**。BFS 的队列天然带分层性质——某时刻队列里恰好装着"同一整层"的所有节点。于是每轮大循环先记下 `size = len(queue)`，再**恰好出队 size 个**：这 size 个就是完整的一层；出队时把它们的孩子入队，恰好凑成下一整层。队列空即结束。

**不变量（BFS 题的通用句式）**：每轮大循环开始时，队列里恰好是"下一整层"的节点，且 `res` 已收好其上所有层。归纳可证：初始队列只有根（第 0 层）；出队 size 个、孩子入队后，队列恰好是再下一层。这一条保证每层不被切断、不混层。

**为什么用 deque 不用 list**：`list.pop(0)` 要把后面全体前移，是 O(n)；`deque.popleft()` 是 O(1)。层序遍历手写时的固定动作。

**延伸变形（同骨架换壳，先埋个伏笔）**：
- **锯齿形层序（LC 103）**：奇数层正序、偶数层反序——每层收集完按层号决定是否 `level.reverse()`；
- **自底向上（LC 107）**：正常层序后 `res.reverse()`（比每层 `insert(0, ...)` 的 O(n²) 优）；
- **右视图（199 题）**：每层只取最后一个；每层最大值（LC 515）/平均值（LC 637）：每层取 max / 求均值——骨架全同，只换"层内结算函数"。

**套路迁移**："队列 + 按 len(queue) 分层"是所有树/图层序题的总模板。图上的 BFS（最短步数、腐烂橘子 LC 994）区别只在"节点带坐标、邻居是四方向"，分层思想一模一样——先在树上把分层写熟，图 BFS 只是换了邻居函数。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
from collections import deque

class Solution:
    def levelOrder(self, root: Optional[TreeNode]) -> List[List[int]]:
        if root is None:
            return []
        res = []
        queue = deque([root])
        while queue:
            size = len(queue)      # 本轮恰好出队 size 个 = 一整层
            level = []
            for _ in range(size):
                node = queue.popleft()
                level.append(node.val)
                # 孩子入队，凑成下一层（先左后右）
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
            # 不变量：此刻 level 收齐一整层，queue 恰好装着下一整层
            res.append(level)
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点进出队各一次；**空间 O(w)**（最大层宽，满树最坏 O(n)），不计输出。
- **易错点**：
  1. 写成 `for node in queue` 边遍历边入队——队列在变长，会把"下一层"也遍历进去，必须先固定 `size = len(queue)`；
  2. 空树返回 `[]` 而不是 `[[]]`；
  3. 用 `list.pop(0)` 当队列，大数据量退化 O(n²)。
- **面试追问**：
  1. **锯齿形**（LC 103）怎么做？→ 分层后按层号奇偶决定是否 `level.reverse()`，或用双端队列每层交替从左/右取放；
  2. **自底向上**（LC 107）？→ 正常层序后整体 `res.reverse()`，一行搞定；不要逐层 `insert(0, ...)`，那是 O(n²)。

## 108. 将有序数组转换为二叉搜索树

> [难度：简单] ｜ [LeetCode 链接](https://leetcode.cn/problems/convert-sorted-array-to-binary-search-tree/) ｜ 标签：树 · 二叉搜索树 · 数组 · 分治 · 二叉树

### ① 题意速览
把升序数组转成一棵**高度平衡**的 BST（Binary Search Tree，二叉搜索树）：任意节点左右子树高度差 ≤ 1，答案不唯一，返回任一合法解。
- 示例：`[-10,-3,0,5,9]` → `[0,-3,9,-10,null,5]`（也可以是其他平衡形态）
- 关键约束：必须高度平衡；数组严格升序、无重复。

### ② 思路讲解
**从朴素想法出发**：BST 要求"左 < 根 < 右"，任选一个数当根，左半递归建左子树、右半递归建右子树——都能建成**合法** BST。但随便选根，歪了就不平衡：总拿首元素当根，建出来是一条向右的链。

**取中点：平衡是白送的**。让**中点当根**——左半段递归建左子树、右半段递归建右子树。为什么必然平衡？归纳论证：左右两半长度至多差 1；两半递归出的子树（归纳假设：也是平衡的）高度至多差 1；加上根之后整体高度差仍 ≤ 1。顺带的两份红利：两半规模每层减半 → 树高 O(log n)；BST 查询/插入的最坏复杂度也被锁在 O(log n)——**取中点等于给整棵树做了一次二分**。

**递归三要素**：函数定义 `build(l, r)` 用 `nums[l..r]` 建平衡 BST 并返回根；基线条件 `l > r`（区间空）返回 None；递归调用 `mid = (l + r) // 2`，根取 `nums[mid]`，左右分别 `build(l, mid-1)`、`build(mid+1, r)`。

**不变量**：`build(l, r)` 返回的树，节点值恰为 `nums[l..r]` 且平衡有序；每层递归区间严格减半，递归树深度 O(log n)。

**与二分查找的亲缘**：递归结构和二分查找完全同构——"取中点、分两半"既是 BST 合法性的来源（左半全 < 中 < 右半全），也是平衡性的来源（两半等量）。分治（Divide and Conquer，分而治之）的味道：大问题 = 中点 + 两个规模减半的同构子问题。

**套路迁移**："有序序列建平衡 BST"家族：有序链表转 BST（LC 109，链表不能 O(1) 取中点，要快慢指针或中序占位法）。本题也是"分治构造"的代表——105 题（前序 + 中序构造）同属"确定根 + 切两半递归"的构造家族。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def sortedArrayToBST(self, nums: List[int]) -> Optional[TreeNode]:
        def build(l: int, r: int) -> Optional[TreeNode]:
            # 基线条件：区间为空，返回空树
            if l > r:
                return None
            # 取中点做根：左半全部 < 根 < 右半，BST 合法性成立
            mid = (l + r) // 2
            node = TreeNode(nums[mid])
            # 不变量：build(l, r) 恰好用 nums[l..r] 建出平衡 BST
            node.left = build(l, mid - 1)    # 左半 mid-l 个
            node.right = build(mid + 1, r)   # 右半 r-mid 个，与左半差 <= 1
            # 归纳：两半平衡且高度差 <= 1 -> 整棵平衡（平衡是白送的）
            return node

        return build(0, len(nums) - 1)
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个元素恰好建一个节点；**空间 O(log n)**：递归栈深度 = 树高（不计输出的树本身）。
- **易错点**：
  1. 区间口径混乱：闭区间 `[l, r]` 配 `mid-1`/`mid+1`，半开区间 `[l, r)` 配 `mid`/`mid+1`——两种口径混用必错；
  2. 基线条件写成 `l >= r`：漏掉单元素区间（`l == r` 时要建节点）；
  3. 其他语言里 `(l + r) // 2` 可能整型溢出，稳妥写法 `l + (r - l) // 2`（面试可提）。
- **面试追问**：
  1. 换成**有序链表**（LC 109）？→ 链表取中点要 O(n)：① 快慢指针找中点，总 O(n log n)；② 按中序顺序给节点分配链表值（"中序占位"），总 O(n)——后者是加分答案；
  2. 为什么任意平衡答案都算对？→ 判题只验"合法 BST 且平衡"，取左中点 `(l+r)//2` 或右中点 `(l+r+1)//2` 建出的都是合法解。

## 98. 验证二叉搜索树

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/validate-binary-search-tree/) ｜ 标签：树 · 深度优先搜索 · 二叉搜索树 · 二叉树

### ① 题意速览
判断给定二叉树是否是合法 BST：每个节点的**整个左子树**严格小于它、**整个右子树**严格大于它。
- 示例：`[5,1,4,null,null,3,6]` → `false`（3 位于 5 的右子树却 3 < 5）
- 关键约束：约束是"子树整体"级别的，不是"父子两点"；节点值可达 32 位整数边界。

### ② 思路讲解
**最常见的错误（点破）**：只比较每个节点和它的两个孩子——`left.val < root.val < right.val`。反例：`[5,1,6,null,null,3,7]`，5<6、3<6、6<7 每对"父-子"都合法，但 3 在 5 的右子树里、3 < 5，非法。**BST 的约束是"子树整体"，父子两两比较覆盖不到"与祖先的关系"**。

**修法一：递归传上下界（主推）**。每个节点被祖先"圈"在一个开区间 (low, high) 里：往左走，上界收窄为父亲的值；往右走，下界抬升为父亲的值——
- **函数定义**：`valid(node, low, high)` = node 子树的值是否全落在开区间 (low, high) 内；
- **基线条件**：空树合法，返回 True；
- **递归调用**：左子树 `valid(node.left, low, node.val)`（上界收到 node.val）、右子树 `valid(node.right, node.val, high)`（下界抬到 node.val）。

根的初始区间是 (−∞, +∞)。"与祖先的关系"被折叠进参数——信息自顶向下流，父子比较的漏洞被堵死。

**不变量**：进入 `valid(node, low, high)` 时，(low, high) 恰好是"node 及其子树全体"可取值的开区间边界（由所有祖先保证）——子树内任何越界值都能在它这里或其祖先处被抓住。

**修法二：中序严格递增**。BST 的中序遍历必然严格递增，反之也成立。用 94 题的迭代中序骨架，维护"上一个访问的值 prev"，每访问一个节点检查 `node.val > prev`。两个坑：必须**严格**大于（相等即非法）；prev 初值用 `None` 标记"还没访问过"（节点值本身可达 int 边界，不能用 0 或最小整数充当哨兵）。

**套路迁移**："把祖先约束折叠成参数下传"是树题通用武器：本题传 (low, high) 区间、二叉树的层序编号（LC 662）传编号区间、路径总和传累积和。信息流方向是自顶向下——祖先知道的事实，用参数告诉子孙。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def isValidBST(self, root: Optional[TreeNode]) -> bool:
        # 修法一：递归传上下界（信息自顶向下）
        def valid(node: Optional[TreeNode], low: float, high: float) -> bool:
            # 基线条件：空树天然合法
            if node is None:
                return True
            # 当前节点必须落在祖先圈定的开区间内（严格不等）
            if not (low < node.val < high):
                return False
            # 递归调用：进左子树收上界、进右子树收下界
            # 不变量：传给子树的 (low, high) 恰好是子树全体可取值的开区间
            return (valid(node.left, low, node.val) and
                    valid(node.right, node.val, high))

        return valid(root, float('-inf'), float('inf'))

    def isValidBSTInorder(self, root: Optional[TreeNode]) -> bool:
        # 修法二：中序严格递增（94 题迭代骨架 + prev 哨兵），提交时二选一
        stack, cur, prev = [], root, None
        while cur or stack:
            while cur:                # 一路压左
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            # 不变量：prev 是中序序列中上一个访问的值，必须严格小于当前值
            if prev is not None and cur.val <= prev:
                return False
            prev = cur.val
            cur = cur.right
        return True
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点判一次；**空间 O(h)**：递归栈/显式栈，链状最坏 O(n)。
- **易错点**：
  1. 只比较父子两点（本题最经典陷阱，反例见思路）；
  2. 区间写成闭区间 `low <= val <= high`——BST 要求严格，相等即非法；
  3. 上下界初值用 `INT_MIN/INT_MAX` 或 0：节点值本身可达 2^31−1，会误杀——用 `float('±inf')` 或 None；
  4. 中序版把 `<=` 写成 `<`，或忘了更新 `prev`。
- **面试追问**：
  1. 为什么中序法只需比较**相邻**两个值？→ 中序序列相邻即"中间没有别的节点"，序列严格递增 ⇔ 整树是 BST——局部判据等价全局性质；
  2. 找出**第一个非法节点**？→ 上下界法在 `return False` 前记录 node；中序法记录第一次违反 prev 的节点，两者都是 O(n)。

## 230. 二叉搜索树中第 K 小的元素

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/) ｜ 标签：树 · 深度优先搜索 · 二叉搜索树 · 二叉树

### ① 题意速览
给定 BST（Binary Search Tree，二叉搜索树）的根和整数 k，返回树中第 k 小的节点值（k 从 1 计）。
- 示例：`[5,3,6,2,4,null,null,1]`，k = 3 → `3`
- 关键约束：1 ≤ k ≤ 节点数；进阶：若树频繁插入/删除且频繁查询第 k 小，怎么办？

### ② 思路讲解
**从朴素出发**：中序遍历拿到有序数组，取第 k−1 个。O(n) 时间 O(n) 空间，但做了两件多余的事——遍历了整棵树、存了所有值。**第 k 小只需要"前 k 个"**，后面的都不必碰。

**核心转化**：BST 的中序遍历天然升序——"第 k 小"就是"中序序列的第 k 个"。于是把中序改成**边遍历边计数，计到 k 立即停**：用 94 题的迭代中序骨架，弹栈访问时 `count += 1`，`count == k` 直接返回该值。最坏仍是 O(n)（k = n 时），但小 k 时**提前终止**，空间也从"存全树的 O(n)"降到"只存祖先链的 O(h)"。

**为什么迭代版比递归版适合提前停**：递归版要在函数之间传"找到了"的信号（哨兵返回值/非局部变量/抛异常），控制流别扭；迭代版一个 while 循环，`count == k` 直接 `return`，干净利落。

**不变量**：弹栈访问第 i 个节点时 count = i，且它的值是全树第 i 小（中序有序性保证）；循环停在 count == k 的第一次访问，其后节点一个都没碰。

**再进一步（进阶追问的答案预告）**：频繁插入/删除 + 频繁查第 k 小，每次 O(n) 太慢——给每个节点挂"子树节点数"字段（顺序统计树，Order Statistic Tree 的思路）：查询时比较左子树 size 决定走左/走右/停，单次 O(h)；插入删除沿途同步更新 size。这是"用额外字段换查询速度"的设计题化。

**套路迁移**："BST 中序 = 有序序列"是 BST 题的第一性质：验证 BST（98 题，中序判递增）、中序后继（LC 285）、把 BST 变累加树（LC 538，逆中序累加）。凡是"第 k 个 / 前 k 个 / 区间 [a, b]"类问题，先想中序 + 提前停 / 剪枝。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def kthSmallest(self, root: Optional[TreeNode], k: int) -> int:
        stack = []
        cur = root
        count = 0
        while cur or stack:
            # 一路压左（中序：先穷尽左子树）
            while cur:
                stack.append(cur)
                cur = cur.left
            node = stack.pop()
            count += 1
            # 访问第 count 个节点；到 k 立即返回，右子树与祖先都不再遍历
            if count == k:
                return node.val
            # 不变量：已访问的 count 个节点构成中序前缀 = 全树最小的 count 个
            cur = node.right
        return -1  # 题目保证 k 合法，形式兜底
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(h + k)**：先下潜 h 找到中序第一个，再访问 k 个，最坏 O(n)；**空间 O(h)**：显式栈只存祖先链。
- **易错点**：
  1. 写成"中序全遍历存数组再取下标"：功能对，但被追问"浪费在哪"就露馅——提前停是本题考点；
  2. count 与判等顺序：先 `count += 1` 再判 `== k`，反了会返回第 k+1 个或漏判；
  3. 递归版忘了用 `nonlocal`（或可变容器）共享计数器，各层各数各的。
- **面试追问**：
  1. **频繁插入删除 + 频繁查第 k 小**（题面进阶）？→ 节点加 size（子树节点数）字段：查询 O(h)，插入/删除沿途 O(h) 更新 size；能讲清"为什么哈希表不够（查询的是排名不是值）"是加分项；
  2. 求**第 k 大**？→ 中序反着走：右-根-左（逆中序），同样计数提前停。

## 199. 二叉树的右视图

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/binary-tree-right-side-view/) ｜ 标签：树 · 深度优先搜索 · 广度优先搜索 · 二叉树

### ① 题意速览
从树的右侧看过去，按从上到下顺序返回能看到的节点值——即每层最靠右的节点。
- 示例：`[1,2,3,null,5,null,4]` → `[1,3,4]`
- 关键约束：不是"右链"——某层只有左孩子时，看到的也是这个左孩子。

### ② 思路讲解
**从直觉出发拆题**："从右边看到什么" = **每层最后被看到的节点**。层序视角下就是"BFS 每层取最后一个元素"——102 题的分层骨架原样搬来，只是每层结算时只留 `level[-1]`。

**BFS 版**：标准分层 BFS，每轮出队 `size` 个，第 size 个（最后一个）写入结果。不变量与 102 题一致：每轮开始时队列恰好装着下一整层。

**DFS 版（追问常客）**：按"**根 → 右 → 左**"的顺序 DFS，每一层**第一个**被访问到的节点就是该层最右节点——同一层里最右的在这条顺序下最先到达。用 `depth` 参数标层，首击判定 `depth == len(res)`（这层还没人来过）就追加答案。**必须先走右**：先走左的话每层第一个到达的是最左节点，得到的是左视图——首击法的铁律是"想要的视图方向先走"。

**两版对比**：BFS 直觉直接；DFS 空间 O(h)，对"一层极宽"的树比 BFS 的 O(w) 划算得多。注意 DFS 首击法不依赖左右子树深度——只依赖"每层第一个到达者"，左子树再深也不会喧宾夺主。

**不变量**：BFS 版每层结算时 level 恰为本层从左到右全部节点；DFS 版 `res[d]` 一旦写入不再变化，且恰为该层最右节点（根右左保证首个到达者即最右）。

**套路迁移**："每层只取特定位置"家族：左视图（根左右首击）、每层最大值（LC 515）、每层平均值（LC 637）——全是 102 题骨架换"层内结算函数"。它还是"视图类"问题的树上原型：答案条数 = 层数，每层贡献恰好一个元素。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
from collections import deque

class Solution:
    def rightSideView(self, root: Optional[TreeNode]) -> List[int]:
        # BFS 版：分层取每层最后一个
        if root is None:
            return []
        res = []
        queue = deque([root])
        while queue:
            size = len(queue)          # 不变量：queue 恰好装着一整层
            for i in range(size):
                node = queue.popleft()
                if i == size - 1:      # 本层最后一个 = 右视图能看到的
                    res.append(node.val)
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)
        return res

    def rightSideViewDFS(self, root: Optional[TreeNode]) -> List[int]:
        # DFS 版：根 -> 右 -> 左，每层第一个到达者即最右节点
        res = []

        def dfs(node: Optional[TreeNode], depth: int) -> None:
            if node is None:
                return
            # 首击判定：depth == len(res) 说明这层还没人来过，我是本层最右
            if depth == len(res):
                res.append(node.val)
            dfs(node.right, depth + 1)   # 必须先右后左，顺序不能反
            dfs(node.left, depth + 1)

        dfs(root, 0)
        return res
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点处理一次；**空间**：BFS O(w)（最大层宽，最坏 O(n)）、DFS O(h)（递归栈，最坏 O(n)）。
- **易错点**：
  1. DFS 版先左后右——得到的是左视图；首击法要求"想要的视图方向先走"；
  2. BFS 版忘了只在 `i == size - 1` 结算，或每层全收集再取尾（结果对但多耗一层存储）；
  3. 首击判定与层号口径不配套：`depth` 从 0 计、`res` 初始为空，`depth == len(res)` 才是"该层第一人"。
- **面试追问**：
  1. **左视图**？→ BFS 每层取第一个，或 DFS 改成"根 → 左 → 右"首击；
  2. 树一层塞十万节点，选哪版？→ DFS：空间 O(h) 远小于 BFS 的 O(w)，这是 DFS 版存在的最大理由。

## 114. 二叉树展开为链表

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/flatten-binary-tree-to-linked-list/) ｜ 标签：栈 · 树 · 深度优先搜索 · 链表 · 二叉树

### ① 题意速览
把二叉树**原地**展开成一个"链表"：所有节点沿 right 指针串联，顺序等于**前序遍历**（根左右），left 全部置 None。不得新建节点。
- 示例：`[1,2,5,3,4,null,6]` → `1→2→3→4→5→6`（全部走 right 指针）
- 关键约束：原地修改；展开后每个节点 left 必须为 None。

### ② 思路讲解
**先想清楚"展开"的语义**：前序序列 1,2,3,4,5,6 要变成 `1.right=2, 2.right=3, ...`——难点在于前序是"根-左-右"，而链表的 next 要接在 **right** 指针上，意味着**左子树整体要插到根和右子树之间**。

**写法一：前驱接管法（推荐）**。对当前节点 curr：
1. 左子树为空 → 直接 `curr = curr.right` 看下一个；
2. 否则找到**左子树的最右节点**——它就是前序意义下"左子树里最后一个被访问的节点"（也是 curr 的中序前驱，94 题 Morris 的老熟人）；
3. 三步接线：**前驱.right = curr.right**（右子树搬到左链末尾）→ **curr.right = curr.left**（左子树整体顶到右边）→ **curr.left = None**（清干净）。然后 `curr = curr.right`（即原来的左孩子）继续。

指针变化只有这三条：前驱的悬空 right 正好当"接线柱"，把左右两段链焊起来。

**写法二：反向后序拼接法（代码更短）**。前序是"根左右"，把访问顺序**倒过来**就是"右-左-根"。全局变量 prev 记录"上一个接好的节点"，递归顺序右 → 左 → 根，每访问一个节点：`node.right = prev; node.left = None; prev = node`。等价于从链表尾部往前逐个接——后处理的接在前面，天然形成前序链。

**为什么两版都不用额外数组**：写法一借"树里现成的悬空指针"搬运子树；写法二利用"right 反正要被重写"——旧值用完即弃，当场变成链。原地题的共同心法：**找到那块"反正要被覆盖"的空间，让它当搬运工。**

**不变量**：写法一处理到 curr 时，curr 的祖先链已全部接好成前序前缀，curr.right 是前序序列的下一个节点；写法二每步结束时 prev 是已接好部分的链头，已接部分恰为原树"反向后序已访问部分"的前序链。

**套路迁移**：前驱节点的第二个用武之地（第一个是 94 题 Morris 遍历）——凡"把 A 接到 B 后面"的重链接题，先问"中序/前序意义下谁紧挨着谁"，**紧邻关系就是接线点**。同家族：恢复二叉搜索树（LC 99，Morris 定位错位对）。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def flatten(self, root: Optional[TreeNode]) -> None:
        """原地展开，函数无返回值。写法一：前驱接管法。"""
        curr = root
        while curr:
            if curr.left:
                # ① 找左子树的最右节点 = 前序意义下左子树最后一个节点
                pred = curr.left
                while pred.right:
                    pred = pred.right
                # ② 右子树接到前驱右边（左链的末尾）
                pred.right = curr.right
                # ③ 左子树整体顶到右边，left 清空
                curr.right = curr.left
                curr.left = None
            # 不变量：curr 左侧无悬挂子树，curr.right 是前序序列的下一个节点
            curr = curr.right

    def flattenRev(self, root: Optional[TreeNode]) -> None:
        """写法二：反向后序（右-左-根）逐个接，prev 从链尾往回长。"""
        self.prev = None

        def dfs(node: Optional[TreeNode]) -> None:
            if node is None:
                return
            dfs(node.right)          # 先右
            dfs(node.left)           # 再左
            # 最后根：把自己插到已接好链的头部
            node.right = self.prev
            node.left = None
            self.prev = node         # 不变量：prev 是已接好前序链的链头

        dfs(root)
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：写法一每条边至多走两次（找前驱一次、主循环一次）；写法二每节点一次；**空间 O(1)**（写法一）；写法二 O(h) 递归栈。
- **易错点**：
  1. 忘了 `curr.left = None`——判题器检查 left 全空，挂着旧左子树直接判错；
  2. 接线顺序错：`curr.right = curr.left` 做在找前驱之前，右子树还没搬走就被顶掉——必须先 `pred.right = curr.right`；
  3. 写法二里 `node.right = self.prev` 必须在更新 prev 之前，顺序颠倒会接出断链。
- **面试追问**：
  1. 写法一为什么是 O(n) 不是 O(n²)？→ 粗看每节点都"找一遍前驱"像平方级，但每条边在所有"找前驱"中至多被扫一次，边数 n−1，合计 O(n)；
  2. 展开成**中序**链怎么做？→ 递归把左子树链在根前面（约定沿 left 串联）或用 Morris 思路重链接，先定"链沿哪个指针走"再动手。

## 105. 从前序与中序遍历序列构造二叉树

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/construct-binary-tree-from-preorder-and-inorder-traversal/) ｜ 标签：树 · 数组 · 哈希表 · 分治 · 二叉树

### ① 题意速览
给出一棵树的**前序**和**中序**遍历结果（节点值互不相同），重建这棵二叉树。
- 示例：`preorder = [3,9,20,15,7]`，`inorder = [9,3,15,20,7]` → `[3,9,20,null,null,15,7]`
- 关键约束：节点值互异（保证根在中序中唯一可定位）；n ≤ 3000（暗示别写 O(n²) 的切片版）。

### ② 思路讲解
**两个序列各自知道什么**：
- **前序**：第一个元素一定是**根**（根左右，根最先出场）；但前序分不清哪段是左子树、哪段是右子树；
- **中序**：根把序列切成两半——根左边全是左子树、右边全是右子树；但中序第一个不一定是根。

**合起来正好互补**：前序定根（拿第一个），中序用这个根**定位切分点**——切分点左边的个数 = 左子树规模。于是递归：`build(preL, preR, inL, inR)`——前序区间第一个是根，去中序区间查根的位置 `idx`，左子树规模 = `idx − inL`，对应前序 `[preL+1, preL+规模]` 与中序 `[inL, idx−1]`；右子树对称。

**朴素版的慢点**：每层递归都在中序区间里**线性找根**（`inorder.index(root)`），或者干脆切片 `inorder[:idx]` 复制数组——O(n²) 起步。优化：**预处理哈希表 `{值: 中序下标}`**，定位切分点 O(1)；区间用下标传参，全程不复制数组。O(n²) → **O(n)**，这一步哈希就是 01 文件"空间换时间"的老套路。

**不变量**：`build(preL, preR, inL, inR)` 恰好用"前序 `[preL..preR]` 与中序 `[inL..inR]` 对应的同一批节点"建出该子树并返回根——两个区间长度恒相等（同一批节点的两种排列），每层递归区间严格缩小，n 个节点各建一次。

**哈希的意义**：空间 O(n) 换"每层定位从 O(n) 到 O(1)"。树题里凡出现"按值查找/定位"，先建"值 → 下标（或节点）"的哈希。

**套路迁移**："两种遍历定一棵树"家族：中序 + 后序（LC 106，根换成后序最后一个，其余推导对称）。反例要记牢：**前序 + 后序无法唯一确定二叉树**——只有一个孩子的节点分不清孩子是左是右，面试常考这个"为什么不行"。

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def buildTree(self, preorder: List[int], inorder: List[int]) -> Optional[TreeNode]:
        # 哈希表：值 -> 中序下标，切分点 O(1) 定位
        pos = {v: i for i, v in enumerate(inorder)}

        def build(preL: int, preR: int, inL: int, inR: int) -> Optional[TreeNode]:
            # 基线条件：区间空，无节点
            if preL > preR:
                return None
            # 前序区间第一个 = 根
            root = TreeNode(preorder[preL])
            idx = pos[preorder[preL]]       # 根在中序中的位置 = 切分点
            left_size = idx - inL           # 左子树节点数
            # 不变量：两个区间长度相等，对应同一批节点
            root.left = build(preL + 1, preL + left_size, inL, idx - 1)
            root.right = build(preL + left_size + 1, preR, idx + 1, inR)
            return root

        return build(0, len(preorder) - 1, 0, len(inorder) - 1)
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：哈希定位 O(1)，每节点建一次；**空间 O(n)**：哈希表，外加 O(h) 递归栈（最坏 O(n)）。
- **易错点**：
  1. 左子树的前序区间写错：是 `[preL+1, preL+left_size]`，不是 `[preL+1, preL+idx]`——中序下标不能直接搬进前序区间；
  2. 切片实现逻辑对但每层复制数组，O(n²)，n = 3000 也会被卡；
  3. 忘了"值互异"是前提：有重复值时哈希定位不唯一，算法前提被破坏（面试应主动指出）。
- **面试追问**：
  1. **中序 + 后序**版本？→ 根是后序最后一个，哈希同款，左右区间推导对称（LC 106）；
  2. 不用哈希还有什么技巧？→ 迭代 + 栈：沿前序一路建左链，中序指针只前进、遇到就对齐弹栈建右链——"消耗式双指针"，O(1) 额外空间（进阶，讲清机制即可）。

## 437. 路径总和 III

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/path-sum-iii/) ｜ 标签：树 · 深度优先搜索 · 二叉树

### ① 题意速览
给定二叉树和整数 targetSum，统计"**向下**的路径"中节点和等于 targetSum 的条数。路径不必从根开始、不必到叶结束，但必须沿父子边连续向下。
- 示例：`[10,5,-3,3,2,null,11,3,-2,null,1]`，target = 8 → `3`（5→3、5→2→1、−3→11）
- 关键约束：节点值可正可负（不能靠"和超了就剪枝"）；路径方向只能父到子。

### ② 思路讲解
**先写暴力（双重递归，O(n²)）**：对每个节点都问一遍"以我为起点向下凑出 targetSum 的路径有几条"（路径总和 I 的写法），外层再遍历每个节点当起点。n 个起点 × 每起点 O(n) = O(n²)。思路直白，面试先写它保底。

**慢在哪**：每个节点被每条祖先链重复访问。换个视角——从"枚举起点"换成"枚举终点"：一条向下路径的和 = 根到当前节点的前缀和 − 某个祖先处的前缀和。这正是 **560 题「和为 K 的子数组」的树上版**！

**树上前缀和 + 哈希（O(n) 主解）**：
- 维护"**从根到当前节点路径**上的前缀和 → 出现次数"的哈希，初始 `{0: 1}`（空路径，让"从根开始"的路径也能被查到）；
- DFS 自顶向下，走到 x 时 `curr += x.val`；以 x 为**终点**、和为 target 的路径条数 = `hash[curr − target]`——查的是"祖先里有多少节点的前缀和恰为 curr − target"；
- 把 curr 计入哈希，递归左右子树；
- **回溯撤销（最易漏的一步）**：离开 x 前执行 `hash[curr] -= 1`。哈希是**全局共享**的：不撤销的话，左子树的前缀和会被右子树"查到"——但两者不是祖先关系，路径不连续，统计就错了。

**不变量**：进入 x 的递归时，哈希里恰好只有"根到 x 的真祖先（含空路径）"的前缀和——撤销动作维护的正是这一条；因此 `hash[curr − target]` 查到的必然是 x 的祖先，路径必然连续向下。

**与 560 的对照**：数组版在一条"前缀和链"上查询；树上版把"数组下标"换成"祖先关系"，用 DFS + 回溯维护"当前链上的前缀和集合"。唯一区别：**数组前缀天然排成一条线，树的前缀要靠撤销来保持"只在当前链上"**。

**套路迁移**：树上前缀和家族：树上路径统计类问题（值和、异或和、计数）都套这个模子。核心句式：**前缀和把"路径和"变成"两个前缀的差"，哈希把"找差值"变成 O(1) 查询，DFS + 回溯保证哈希只含当前链。**

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
from collections import defaultdict

class Solution:
    def pathSum(self, root: Optional[TreeNode], targetSum: int) -> int:
        prefix = defaultdict(int)
        prefix[0] = 1          # 空路径前缀：允许"从根开始"的路径被查到
        self.ans = 0

        def dfs(node: Optional[TreeNode], curr: int) -> None:
            if node is None:
                return
            curr += node.val   # 根到 node 的前缀和
            # 以 node 为终点的合法路径数 = 祖先中前缀和为 curr-target 的个数
            self.ans += prefix[curr - targetSum]
            prefix[curr] += 1          # 当前前缀入哈希，供子孙查询（先查后存！）
            # 不变量：此刻 prefix 只含"node 及其真祖先"的前缀和
            dfs(node.left, curr)
            dfs(node.right, curr)
            prefix[curr] -= 1          # 回溯撤销！哈希全局共享，不撤会跨子树误查
            # 撤销后不变量恢复：prefix 回到只含 node 真祖先的状态

        dfs(root, 0)
        return self.ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每节点进出哈希各一次；**空间 O(n)**：哈希 + O(h) 递归栈。
- **易错点**：
  1. **忘了回溯撤销** `prefix[curr] -= 1`：跨子树误配、答案偏大——本题第一坑；
  2. 漏了 `prefix[0] = 1`：从根出发的路径全部漏计；
  3. 先存后查：target 为 0 时"自己减自己"被算成一条空路径——必须**先查后存**；
  4. 误允许"拐弯"路径：前缀差只覆盖"直下"路径，拐弯要换 124 题的拐点枚举。
- **面试追问**：
  1. 哈希为什么记"出现次数"而不是"是否存在"？→ 不同祖先的前缀和可能相等，多条路径都能以当前节点为终点，要逐条计数；
  2. 双重递归版和前缀和版怎么取舍？→ 双重递归 O(n²) 零状态、好写好讲，面试先给出再优化；前缀和版是正解——关系同 560 与暴力子数组和。

## 236. 二叉树的最近公共祖先

> [难度：中等] ｜ [LeetCode 链接](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/) ｜ 标签：树 · 深度优先搜索 · 二叉树

### ① 题意速览
给定二叉树和树中两个节点 p、q，找它们的最近公共祖先（LCA，Lowest Common Ancestor）：同时是 p 和 q 祖先的节点中深度最大者（节点可以是自己的祖先）。
- 示例：`[3,5,1,6,2,0,8,null,null,7,4]`，p=5、q=1 → `3`；p=5、q=4 → `5`
- 关键约束：所有节点值互异；p、q 都在树中；第二个示例说明"祖先含自身"。

### ② 思路讲解
**从定义到递归**：LCA 是"从下往上第一个分叉点"——p 和 q 分居它两侧，或其中一个就是它。倒过来想：自底向上收集信息，最合适的是**后序遍历**（先左右、后根）。

**递归三要素（返回值定义是本题最妙的设计）**：
- **函数定义**：`lca(root, p, q)` 返回"root 子树中 p/q 的命中情况"——子树同时含 p 和 q 时返回它们的 LCA；只含其中一个时返回那个节点；都没有返回 None。**LCA 和"命中节点"共用"节点"作返回值，一个返回值三种语义**；
- **基线条件**：root 为空 → None；root 就是 p 或 q → 返回 root（命中即返回，不再往下找）；
- **递归调用**：left、right 分别递归左右子树，然后合并——两边都非空：p、q 分居两侧，**当前 root 就是 LCA**，返回 root；只有一边非空：命中结果原样上传（LCA 在命中一侧，或在更上面等另一侧命中）；两边都空：None。

**"p 或 q 本身是祖先"为什么天然成立**：若 p 是 q 的祖先，DFS 走到 p 时基线条件直接返回 p，p 子树内对 q 的搜索被短路——p 以"单侧命中"的身份一路上传，语义完全自洽，不需要任何特判。第二个示例正是这种情况。

**不变量**：每次递归返回时，返回值准确表达"该子树内 p/q 的存在情况"（三态：None / 单命中 / 已定 LCA）；合并时该语义继续成立，故根处返回值就是全局 LCA。

**为什么不用"分别找路径再比对"**：先记下根到 p、根到 q 的两条路径，再找最后分叉——也对，但要两次遍历加路径存储。后序一体化版本一次遍历、零额外结构。面试可以先讲路径法（直观）再给后序法（漂亮），展示思考层次。

**套路迁移**："后序 + 三态返回值"家族：BST 版 LCA（LC 235，利用大小关系直接判方向，退化为一次搜索）、二叉树中的最大路径和（15 题，返回值兼做"单侧贡献"）。设计心法：**让返回值承载"子树对父亲的全部有效信息"，语义可以复合，但每种取值的含义要写清楚。**

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def lowestCommonAncestor(self, root: 'TreeNode', p: 'TreeNode', q: 'TreeNode') -> 'TreeNode':
        # 基线条件：空 -> 没命中；root 是 p 或 q -> 命中即返回（含"p 是 q 祖先"情形）
        if root is None or root is p or root is q:
            return root
        # 后序：先收集左右子树的命中情况
        left = self.lowestCommonAncestor(root.left, p, q)
        right = self.lowestCommonAncestor(root.right, p, q)
        # 合并：两边都命中 -> p、q 分居两侧，当前节点是 LCA
        if left and right:
            return root
        # 只有一边命中 -> 结果原样上传（可能还不是最终 LCA，交给更上层合并）
        # 不变量：返回值三态——None / 单个命中节点 / 已确定的 LCA
        return left or right
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每个节点访问一次；**空间 O(h)**：递归栈，最坏 O(n)。
- **易错点**：
  1. 基线条件漏 `root is p or root is q`：p 是 q 祖先时会漏判（p 子树里找不到另一个，p 的命中就丢了）；
  2. 比较用 `root.val == p.val` 而不是 `root is p`：值互异时碰巧能过，但语义上该比节点引用（题目给的是节点对象）；
  3. 把 `return left or right` 讲成"找非空"：它的语义是"单侧命中原样上传"，两种说法混着讲会露馅。
- **面试追问**：
  1. **BST 的 LCA**（LC 235）？→ 利用"p、q 都小于根走左、都大于走右、分居两侧即答案"，一条路径 O(h)，不需要后序；
  2. p、q **可能不在树中**怎么办？→ 先 O(n) 验证两者存在，或把返回值升级为 (节点, 命中掩码) 二元组——命中满两个才认定 LCA，返回值语义要扩展。

## 124. 二叉树中的最大路径和

> [难度：困难] ｜ [LeetCode 链接](https://leetcode.cn/problems/binary-tree-maximum-path-sum/) ｜ 标签：树 · 深度优先搜索 · 动态规划 · 二叉树

### ① 题意速览
路径 = 树中任意节点序列，相邻节点有边相连、每个节点至多出现一次；路径**至少含一个节点**、不必过根，求节点值之和的最大值。节点值可负。
- 示例：`[-10,9,20,null,null,15,7]` → `42`（15→20→7）；`[-3]` → `-3`
- 关键约束：至少一个节点（全负树答案是最大单节点，不能返回 0）；路径"拐弯"（同时取左右两臂）至多一次。

### ② 思路讲解
**路径的形状**：任何合法路径都有一个**最高点**（拐点）——在拐点处"从左子树上来、经过自己、向右子树下去"，左右两臂各至多一条链。与 543 直径完全同构：**枚举每个节点当最高点，"过我的最大路径和 = 左臂最优 + 我 + 右臂最优"**，全局取最大。

**返回什么给父亲（与 543 的差别所在）**：父亲要的不是"过我拐弯的路径"，而是"**以我为端点、向下延伸一条链**的最大贡献"——父亲若把我拉进它的路径，路径到我为止、至多再选我的左臂或右臂之一继续（两臂都选就拐两次弯了）。所以：
- **返回值通道（自底向上）**：`gain(node) = node.val + max(0, gain(左), gain(右))`——**负贡献截断为 0**（宁可不要这条臂，路径到我就结束）；
- **全局通道**：`self.ans = max(self.ans, 左贡献 + 右贡献 + node.val)`——"过我的完整路径"在拐点结算。

**负值截断为什么必须**：节点值可负，更长的链不一定更优。`max(0, ...)` 把"要不要这条臂"的决策下沉到每个节点；截断后哪怕左右臂全负，"过我"的路径退化为单节点 `node.val`，恰好兜住"全负树"的边界。

**不变量**：`gain(x)` 返回时，"x 为一端向下的最大贡献"已定，且 `self.ans ≥` x 子树内所有路径的最大和——每个节点当一次拐点，所有可能的最高点被穷举。

**与 543 的骨架对照（总复习）**：同是"后序 + 双通道"。差异仅在——543 返回 `max(左, 右) + 1`（深度），124 返回 `val + max(0, 左, 右)`（截断贡献）；543 全局记 `left + right`（边数），124 全局记 `left + right + val`（点和）。**一个模板，两次全剥**——本专题"返回值/全局分工"意识在此收口。

**套路迁移**："拐点枚举 + 贡献回传"家族：最长同值路径（LC 687，贡献变成"同色链长"）、树上几乎所有"路径最值" DP。通用句式：**向父亲只报"单侧最优延伸"，"双侧拼起来的完整答案"进全局。**

### ③ 注释代码
LeetCode 已提供 TreeNode 节点定义。
```python
class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        self.ans = float('-inf')   # 全负树也要有正确初值：至少包含一个节点

        def gain(node: Optional[TreeNode]) -> int:
            # 基线条件：空子树贡献 0
            if node is None:
                return 0
            # 左右臂的最大贡献；负值截断为 0（宁缺毋滥，路径可到我就结束）
            left = max(gain(node.left), 0)
            right = max(gain(node.right), 0)
            # 全局通道：以 node 为最高点（拐弯）的完整路径和
            self.ans = max(self.ans, left + right + node.val)
            # 返回通道：只交"单侧延伸"给父亲，拐弯信息不回传
            # 不变量：gain 返回"以 node 为一端向下的最大贡献"（已截断）
            return node.val + max(left, right)

        gain(root)
        return self.ans
```

### ④ 复杂度 · 易错点 · 面试追问
- **时间 O(n)**：每节点结算一次；**空间 O(h)**：递归栈，最坏 O(n)。
- **易错点**：
  1. 返回值忘了 `max(0, ...)` 截断：负臂被顺手带给父亲，污染父亲的最优路径；
  2. 全局更新时左右没截断，或 `self.ans` 初值用 0——单节点/全负树立即翻车，初值应 `float('-inf')`；
  3. 把"过根"当全局最优：路径最高点可在任意子树（543 的教训在这里同样适用）。
- **面试追问**：
  1. 要求**输出路径本身**？→ 更新 ans 时记录拐点与两臂的"贡献来源"，最后沿贡献回溯收集节点；
  2. 节点值全为正时能简化吗？→ 截断永不触发，代码退化为 543 骨架的"点和"版——本质复杂度全来自负值，能讲清"哪一行是给负值准备的"是加分项。

| 递归三要素 | — | 函数定义（算什么/返回什么）、基线条件（何时停）、递归调用（如何缩小问题），树题动笔前的三连问 |
| DFS / BFS | Depth-First / Breadth-First Search | 深度优先（递归或显式栈，前/中/后序）与广度优先（队列，按层），二叉树的两条遍历骨架 |
| 自顶向下 / 自底向上 | Top-Down / Bottom-Up | 信息流方向：祖先信息作参数下传（上下界、层号、累积和）vs 子树结果作返回值上传（深度、贡献、命中） |
| 双通道 | — | 返回值传"父亲需要的信息"、全局变量记"沿途结算的答案"，543/124 一类路径题的核心分工 |
| 前驱 | Predecessor | 中序意义下紧邻自己之前的节点 = 左子树的最右节点；Morris 遍历与 114 题接线的支点 |
| 树上前缀和 | Prefix Sum on Tree | 根到当前节点的路径和；任意向下路径和 = 两个前缀和之差，配哈希与回溯撤销（437 题） |
| 回溯撤销 | Backtracking / Undo | DFS 离开节点时撤销其对全局共享结构的修改，维持"哈希只含当前链"的不变量 |
| 中序有序性 | Inorder = Sorted | BST 的中序遍历严格递增，是"第 k 小、验证、范围查询"类问题的第一性质 |
